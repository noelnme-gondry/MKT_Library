# 보고서 이용권 결제 운영

5,900원 · 결제일부터 달력 기준 1개월 · 자동 갱신 없음. 기존 유효 이용권은 중복 구매를 막는다. 월말은 다음 달 마지막 날짜로 맞춘다.

## 서버 설정

Railway 앱 서비스의 서버 환경변수에 다음을 설정한다. 소스·문서·채팅에 키 값이나 DB 연결문자열을 붙이지 않는다.

| 변수 | 의미 |
|---|---|
| `TOSS_CLIENT_KEY` | 토스 주문서형/결제창형 연동 클라이언트 키 (`test_gck_` / `live_gck_`) |
| `TOSS_SECRET_KEY` | 같은 상점·환경의 시크릿 키 (`test_gsk_` / `live_gsk_`) |
| `PAYMENTS_DATABASE_URL` | 결제 주문만 보관하는 PostgreSQL 연결문자열 |
| `PAYMENTS_LIVE_ENABLED` | 실결제 활성화 시에만 `true`. 테스트 완료 전에는 설정하지 않는다. |

테스트 키와 라이브 키를 섞지 않는다. API 개별 연동 키(`ck`/`sk`)와 신규 주문서 연동 키는 다른 제품이므로 SDK만 임의로 바꾸지 않는다. 토스 개발자센터에서 주문서형/결제창형 키를 확인한다.

먼저 해당 DB에 `scripts/payments-schema.sql`을 적용한다. DB 사용자에게 이 테이블의 조회·삽입·갱신 권한을 부여한다. DB 연결은 서버에만 제공한다. `/api/payments/config`에는 사용 가능 여부와 공개 클라이언트 키만 반환된다. 설정 미완료 시 결제 UI는 구매 문의를 안내한다.

## 결제와 복원

1. 서버가 주문번호·5,900원·상품 버전·복원 코드 해시·멱등 키를 저장한다.
2. 사용자 클릭 후에만 토스 SDK를 불러온다. 카드 입력은 토스 화면에서 처리한다.
3. 리턴 경로는 `/api/payments/return`이다. 결제키·주문번호는 HttpOnly 임시 쿠키로 옮기고, 추적 스크립트가 있는 구독 페이지에 도달하기 전에 URL에서 제거한다.
4. 서버는 주문 소유 쿠키·금액·토스 응답을 확인한 뒤 승인 결과와 만료일을 저장한다. 동일 주문의 재시도에는 같은 멱등 키를 사용한다. 승인 결과가 불명확하면 재결제하지 않고 승인 확인을 재시도한다.
5. 활성화 후 복원 코드를 파일로 보관할 수 있다. 다른 기기의 구독 페이지에서 이 코드로 이용권을 복원한다. 프로젝트 파일은 별도 백업/가져오기로 이동한다.
6. 이용권 검증 장애 시 마지막 유효 캐시는 최대 72시간이며 원래 만료일을 넘지 않는다. 검증 성공 시 취소·만료가 확인되면 권한을 회수한다. 이것은 브라우저 내 기능 제한이며 DRM을 보장하지 않는다.

CSV·분석 결과·프로젝트명·파일명·로고는 주문·승인·복원 요청에 포함하지 않는다. 결제 복원 코드를 GA나 고객지원 공개 로그에 남기지 않는다.

## 환불과 취소

공개 정책은 `/subscription#refund-policy` 및 `/en/subscription#refund-policy`가 안내한다. 환불 접수 후 운영자가 토스 상점관리자에서 해당 주문의 전액/부분 취소를 처리한다. 앱에 비밀키를 입력하는 관리자 화면은 만들지 않는다.

토스 결제 상태 변경 웹훅 주소는 `https://growthoptplaybook.com/api/payments/webhook`이다. 웹훅 본문을 신뢰하지 않고 토스 API로 해당 결제를 조회해 취소를 반영한다. 웹훅이 누락돼도 다음 이용권 확인에서 토스 상태를 다시 조회한다. 부분 취소도 공개 환불정책에 따라 유료 이용을 종료한다. 이미 저장한 프로젝트 읽기와 백업은 막지 않는다.

결제·공급 기록은 법정 5년 보관 대상이다. DB 백업·법정 보관기간 이후 파기 운영은 실결제 개시 전에 설정해야 한다. 승인되지 않은 주문과 실제 거래 기록을 구분하며, 승인 결과가 불명확한 주문을 임의 삭제하지 않는다. [전자상거래법 시행령 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1018638379)

## 배포 후 필수 실측

- 실제 상점의 테스트 결제 → 승인 → 새로고침 → Word/Excel 다운로드 → 다른 브라우저에서 코드 복원.
- 토스 테스트 취소 → 웹훅 또는 접근 재검증 → 다운로드 제한, 프로젝트 백업 유지.
- 중간 네트워크 끊김 → 동일 주문 승인 재시도; 이중 결제 없음.
- 라이브 상점 활성화, 사업자 표시 정보·연락처·통신판매업 신고 적용 여부 확인.
- 테스트 이벤트 `state=test`를 매출로 집계하지 않는다. `payment_access_activated`는 클라이언트 활성화 이벤트로, 회계 매출의 정본은 토스/주문 DB다.

현재 자동 검증은 모의 토스 응답과 DB 테스트 대역을 사용한다. 실제 토스·PostgreSQL·웹훅·라이브 결제는 환경 설정 후 별도 실측해야 한다.

공식 연동 근거: [SDK 초기화](https://docs.tosspayments.com/sdk/v2/js/environment), [금액 검증과 승인 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow).
