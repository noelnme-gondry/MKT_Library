# 유입·첫 사용·재사용 개선 반영 기록

기준: `cfed87310ab0606ee97099c33e7680dc2d794009` / PR #868 이후. 결제는 사용자 요청에 따라 테스트·제한 상태를 유지한다. 이 문서의 “반영”은 코드 변경이며 배포·실제 성과 달성과 구분한다.

## 먼저 정정할 항목

앞선 여정 감사의 S2는 잘못된 현황 진단이었다. `next.config.mjs`의 `diagnosisPillar`가 이미 `ad-performance-drop`, `cpa-reduction`, `ctr-improvement`, `creative-fatigue`를 `ad-performance-diagnosis`로 영구 리다이렉트한다. 현재 원고도 KO/EN 진단 글 하나다. 옛 URL·그림 경로를 별도 현행 글로 읽으면 안 된다. 추가 글 통합·삭제·리다이렉트는 하지 않는다. 검색 성과는 GSC로 별도 확인해야 한다.

## 기술적으로 지켜야 할 경계

- 미리보기는 Word/Excel과 같은 결과 payload의 요약이다. 전체 차트·전체 원본·수식 파일을 미리보기에서 생성하지 않는다. 실제 다운로드는 유효 구매 권한을 다시 검사한다.
- 미리보기는 React 텍스트로 렌더하며 원본·캠페인·결론을 서버, 스토리지, 분석 이벤트에 보내지 않는다. 이벤트에는 도구·언어·화면 범주만 남긴다.
- 주간 계산 완료는 결정 검토 완료가 아니다. 주간 결정과 보고서 저장은 독립 행동이므로 서로의 단계 전환율을 만들지 않는다. 누락된 수집은 0명의 사용자로 추정하지 않는다.
- 알림 동의는 기본 미선택이다. 계정 전체 검토·만료 알림 활성화와 해당 메모 알림 저장이 함께 성공해야 한다. 잘못된 동의 문자열·검토일 없는 등록은 거절한다. 무료 캘린더에는 기존 계약대로 캠페인명·메모 내용을 넣지 않는다.
- 신규 페이지·도구·수학 엔진·결제 환경변수는 만들거나 바꾸지 않았다. 기존 사용자 변경·미추적 작업을 보존한다.

## 입력 자동화의 다음 구현 조건

연결이 필요 없다는 결론이 아니다. 먼저 주사용 소스와 반복 과제를 확정해야 한다. 현재 사용자에게 Meta CSV / Sheets / GA4·Google Ads 중 주사용 소스를 질문했으며 답변은 미확인이다. 이번 준비 안내는 Meta와 비공개 Sheets 업로드를 모두 다룬다.

1. 실제 소스의 최초·다음 주 export 파일 두 개로 날짜·통화·전환 정의·컬럼 변화를 확인한다. 민감 원본은 브라우저에서만 사용한다.
2. Sheets가 반복 소스라면 별도 사용자 동작으로 최소 읽기 권한을 요청하는 브라우저 직접 연결을 설계한다. 기존 로그인(openid/email)에 권한을 몰래 추가하지 않는다. Google OAuth 공개 클라이언트·허용 origin·동의 화면 설정이 필요하다. 액세스 토큰은 메모리에만 두고 만료 시 사용자 재승인을 받는다.
3. 닫힌 브라우저의 자동 갱신·서버 감시·광고 원본 동기화는 위 방식으로 해결되지 않는다. 그 요구가 실증되면 F-03/F-04 및 개인정보처리방침부터 별도로 결정한다.
4. 팀 공유는 현재 무료 백업과 선택 메모 공유를 먼저 검증한다. 역할 권한·동시 편집이 실제 필요하면 별도 계정 모델로 설계한다. 백업 파일 교환을 팀 기능 구현이라고 부르지 않는다.

공식 참고: [Google 브라우저 토큰 모델](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [플랫폼별 일별 캠페인 내보내기](https://support.google.com/analytics/answer/16748649), [Google Sheets 내보내기](https://support.google.com/docs/answer/9330963).

## 검증 기록

최종 실행 결과는 PR의 Test plan과 아래에 기록한다. 테스트 전 상태를 통과로 기입하지 않는다.

- 초기 회귀 재현: 퍼널 테스트가 주간·구매 집계 부재로 실패.
- 중간 전수 검사: 이번 변경의 JSX 구문 오류와 결과 카드 머리 버튼 수 증가를 발견하고 수정. 기존 결함으로 돌리지 않음.
- 미리보기 메뉴→대화상자→닫기 포커스 복귀 실패를 재현하고 명시적인 복귀 대상 지원으로 수정.
- `npm run test:all`: 3,698 통과, 2 제외. 이어서 마지막 저장 안내 분기 변경의 화면 테스트 5개도 통과.
- `npm run lint`, `npm run build`: 통과. 빌드로 KO/EN 정적 페이지 생성 확인.
- 신규 진입·보고서 미리보기 + 기존 유료 작업 흐름 E2E: 35개 통과. 320px 모바일, 1440px 데스크톱, 영문 라이트 모드. 글의 양 테마 대비·가로 넘침, 실습/입력 링크, 요약 일치, 파일 차단, 포커스 복귀 포함.
- 브라우저 검사에서 미리보기의 잘못된 `<dl>` 구조 및 영문 수식 스크롤 영역의 키보드 접근을 발견·수정했다. 테마 전환 중간색을 잘못 측정한 테스트는 저장 테마로 다시 로드한 뒤 측정하도록 고쳤다. 대비 기준을 낮추지 않았다.
- 마지막 터치 점검에서 미리보기 닫기·템플릿 버튼·입력 도움말 링크의 44px 기준을 보강했다. 실제 버튼 크기를 단언하는 브라우저 검사 8개 재실행 통과 (2026-09-14).
- 첫 전체 CI에서 템플릿 도달성 테스트 4개가 새 업무별 링크와 기존 목록 링크를 중복 선택해 실패했다. 전체 목록 카드로 검사 범위를 명확히 했으며, 결제 테스트의 예시 실행도 업로더 초기화 완료를 기다리도록 맞췄다. 관련 모바일·태블릿·데스크톱·영문 테스트 16개와 해당 파일 ESLint 통과. 전체 CI는 수정 커밋 기준으로 다시 실행한다.

실사용 전환율·검색 순위·실메일 수신·실거래·경쟁사 로그인 이후 경험은 이번 코드 검증 범위가 아니다. “경쟁사 대비 모든 격차 제거” 또는 “리텐션 상승”으로 보고하지 않는다.
