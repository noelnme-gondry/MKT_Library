# 결과 자율화 — 총괄 계획 (Roadmap)

> 작성 2026-09-30 · PR #941 기준. 설계 상세는 `docs/result-autonomy-spec.md`, 화면·대외 계약은 `docs/product-ssot.md` §5.5a.
> 이 문서는 "무엇을 왜, 어떤 순서로" 하는지의 한 장짜리 지도다. 진행하면서 §4 표의 상태 칸을 고친다.

---

## 1. 왜 하는가

AI 대화형 분석은 무엇이든 한 번에 결과를 내고 원하는 방향으로 고칠 수 있다. 우리 도구는 **정해진 포맷에 유저가 데이터를 맞춰 넣는 구조**라서 그 지점에서 약했다. 목표는 세 가지다.

1. **분석 시작의 자율성**: 우리 포맷에 데이터를 맞추는 대신, 유저 데이터에 우리가 맞춘다.
2. **결과 출력의 고도화**: 결과 안에서 나눠 보기·범위·보기 방식을 바로 바꾼다.
3. **결과 출력의 자율화**: 결과와 다운로드를 원하는 형태로 받는다. 이것이 Pro를 쓸 이유가 된다.

**차별점은 지킨다.** AI처럼 유연하지만, 같은 입력이면 매번 같은 답이 나오고(결정론), 검증된 통계 엔진을 쓰며, 원본 데이터는 기기 밖으로 나가지 않는다.

## 2. 대전제 (전 도구 공통 원칙)

| # | 원칙 | 한 줄 |
|---|---|---|
| P1 | 계산은 고정, 보여주는 방식은 자유 | 통계 엔진·골든 테스트는 건드리지 않는다. 앞(데이터 맞추기)과 뒤(결과 구성·다운로드)만 연다 |
| P2 | 필수 필드 대신 "있는 만큼 된다" | 컬럼 조합별로 되는 것만 계산하고, 안 되는 것은 필요한 컬럼을 알려 준다 |
| P3 | 모든 조정은 레시피로 저장 | 고른 단어 목록(칩)만 저장하고 상태는 매번 거기서 만든다. 다음 기간 CSV에 그대로 다시 적용된다 |
| P4 | 결과는 공통 틀, 내용은 도구별 | 블록 종류(결론·수치·그림·표·한계·행동)와 조작만 공통이고 무엇을 담는지는 도구가 정한다 |
| P5 | 자유에도 정직성 가드 | 숨기기·범위·이름은 자유. 엔진 숫자 수정·판정 뒤집기는 불가. 결론의 근거 블록은 숨길 수 없다 |
| P6 | 무료 = 그 자리에서 조정, Pro = 저장·반복·형식 | 레시피 계정 저장·다운로드 설정 파일은 Pro 범위(`product-ssot.md` F-01 안) |
| P7 | 공용 부품 하나 + 도구별 선언 | 입력창·사전·저장·다운로드 설정은 한 벌. 도구는 단어·블록·어댑터만 선언한다 |

**사용자 확정 결정 (2026-09-30)**
- LLM·외부 API를 쓰지 않는다. 대신 **단어 사전 + 드롭다운 자동완성 입력창**을 쓴다(`채` → 채널별·채널+캠페인별).
- 파일럿 도구는 **5-21 성과 변동 원인(PVM)**.
- 다운로드 한계 문구는 기본 포함이고 뺄 수 있다. 빼면 "작성자가 분석 한계 N건을 제외했습니다" 한 줄이 남는다.
- 국가·OS 등 임의 축은 반드시 지원하고, 헤더 표기가 제각각인 것도 인식한다.
- 대소문자·공백만 다른 값은 자동으로 합치고, 합친 사실을 알린다.
- "채널별"이 우리 필드인지 CSV 컬럼인지는 매핑으로 정한다. 매핑과 축 지정이 한 번에 된다.
- 입력창은 **필터 막대 안**에 두고, 필터와 같은 조건은 한 곳(필터)이 가진다.
- 레시피 계정 동기화는 **이름 붙여 저장** 방식.
- 다운로드 설정은 **PNG 제목·기간·출처 / 보고서에 넣을 블록 / 파일 이름 규칙** 세 가지.

**5-21·5-22 화면 정리 (2026-09-30, 사용자 예시 승인 후)**

- 예시에서는 선택지 축소·직접 조작·근접 배치·강조 위계만 가져온다. 기존 분석 내용, 핵심 그림, 계층 분해표, 포화도 지도와 응답곡선은 유지한다. 표 열 편집은 추가하지 않는다.
- 5-21의 분석·비교 날짜 자체에서 각각 기간을 편집한다. 적용/취소, 날짜 순서 검증, 직전 같은 길이 선택, 기간 겹침·길이 차이 안내를 제공한다. 수동 날짜와 기간 명령 중 마지막 선택을 적용하며 다른 조건은 보존한다.
- 5-22는 분석 기간만 같은 방식으로 편집한다. 양쪽의 대상 필터는 아이콘 버튼으로 여는 선택 패널에서 선택하고, 공용 상태·선택 칩은 그대로 사용한다. 날짜를 칩·읽기 전용 문장·별도 기간 버튼에 중복 노출하지 않는다.
- 불필요한 ‘한눈에 보기’ 제목을 걷고, 저장 조건을 저장 버튼 바로 아래에 묶는다. 수치·항등식·추정 로직 변경 없음. KO/EN 동등 반영.
- 검증: 원본 행 직접 합산과 화면 단가 대조, 독립 기간 변경/취소/잘못된 입력/명령 재선택, 요약→상세 기간 승계. 브라우저에서 320/768/1440의 날짜 조작·포커스·가로 넘침과 기존 PNG 흐름 검사.

**결과 구획 보강 (2026-09-30, 사용자 화면 피드백)**

- 분석 대상의 문서형 삼각형 토글을 선택 패널로 교체. 플랫폼·국가·채널·소스를 그룹별 버튼으로 선택하며 즉시 결과에 반영한다. 대상 초기화는 날짜를 보존한다.
- 기여도는 채널별 카드 안에 이름·총 기여·비중/효율 막대를 정렬하고 공통 축척을 유지한다. 범례의 색과 막대를 연결하고 상승/하락 방향을 구분한다.
- 다음 기간 비교는 분석 → 판단 저장 → 재검토의 안내 순서와 행동 영역으로 구분. 예시 미저장·로그인/Pro 조건은 행동 옆에 유지한다.
- 추가 변동 근거의 중복 요약은 후속 피드백으로 제거하고 인과 한계는 핵심 그림 옆에 유지한다. 수학·표·기존 수치는 유지한다. KO/EN과 모바일 대응을 포함한다.

단계별 비율은 동일 사용자 코호트를 추적한 퍼널 전환율이 아니다. 식별 불가 중간 단계는 합쳐 표시하고 한계를 밝힌다. 모든 도구의 하단을 일괄 전환하지 않고 5-21에서 먼저 검증한다.

검증: 전체 548파일·4,826테스트 통과(1파일·4테스트 건너뜀), lint·production build 통과. KO/EN 기능 회귀 54개 통과 후 최종 정렬 수정에 관련된 27개(디자인 15·기능 12)를 다시 통과했다. 디자인 검사 범위는 대시보드·PVM KO/EN·포화도·구성 변화 분석, 320/768/1440px. 실제 화면은 PVM KO 라이트 320/980/1440px와 EN 다크 1440px에서 단계·수치·버튼·하단을 확인했다. 참고 창의 axe·Escape·포커스 복귀, CPI 3단계↔CPA 4단계도 검사했다. 화면에서 발견한 다음 행동의 말줄임과 하단 제목 크기를 추가 수정했다. 운영 계정·실구매·다른 기기 복원은 미확인이다.

**다음 순서:** 5-22 검토 후 §4.2의 **5-3 → 5-2**. 확장 순서는 사용자 “쫙 진행해” 지시에 따라 확정했다. B/C 운영 확인(실제 계정 저장·다른 기기 복원·운영 DB 마이그레이션)은 로컬 구현 검증과 구분해 미확인으로 유지한다. 5-3 이후 도구, 묶음 보고서, 팀 공유는 아직 미구현이다.

**5-22 목적 중심 디자인 재검토 시작 (2026-09-30, 현재 화면 공유)**

목적은 ‘어느 채널에 추가 예산을 검토할지, 그 근거가 충분한지 판단하고 예산 배분으로 연결’이다. 5-21의 카드 모양이나 단계별 전환 분해를 그대로 복제하지 않는다. `design.md` §2에 목적 → 질문 → 근거 → 행동 → 배치 이유의 설계 기준을 추가했다.

현재 1440px 예시 결과를 캡처해 확인한 범위: 분석 설정·날짜·대상 패널, 결론과 공용 저장/공유 안내, 평균·한계효율 비교, 하단 진입부. 날짜 직접 편집·공용 검토 안내는 이미 반영됐지만 아래는 추가 정리 대상이다. 이번 문서/캡처 작업에서 앱 UI를 수정한 것은 아니다.

| 현재 상태 / 영향 | 다음 구성 방향 | 보존할 근거 |
|---|---|---|
| 결과 앞에 핵심 요약·해석 문단·데이터 준비가 길게 놓임 | 결론과 핵심 판단을 먼저 읽히게 하고 데이터 교체·한계 설명은 관련 조작/그림에 배치 | 예시 여부, 데이터 출처, 관측 범위·적합 한계 |
| 평균 효율 지도와 한계효율의 행동 라벨을 혼동할 수 있음 | 관측 효율에 따른 검토 우선순위와 추가 지출의 모델 추정을 구분해 연결 | 실제 평균/한계 값·포화지수·관측 수·적합도·응답곡선 |
| 기간 민감도 설명이 긴 문단이며 헤더가 큰 고정 영역을 차지함 | 실행 목적·조건·결과를 구분하고 결과를 읽을 공간과 정보 우선순위 검토 | 기간 검증 동작, 비교 불가 사유, 분석 설정 접근 |
| 하단에 프로젝트·같은 CSV 추천·다음 단계·전체 여정·FAQ가 반복 | 예산 배분으로 이어지는 주 행동과 선택적 방법/자료를 구분 | 연결 계약·데이터 승계·참고 자료 접근 |

5-3 착수 시 지킬 기존 계약: 예산/목표 수치 입력, 관측 범위 상한, 신뢰도 낮은 채널 유지, 국가 단일 강제, 채널별 모형 검증. 현재 `unitField`·objective·국가/채널/OS 범위는 전용 상태를 쓰므로 공용 필터를 바로 얹으면 이중 상태가 된다. 상태 소유자를 먼저 레시피로 이관하고 배분 합계·목표 경계·저장 복원 테스트를 통과시킨 뒤 5-2로 넘어간다.

### 4.3 도구 하나를 붙일 때의 체크리스트

B·C는 공용이라 도구마다 새로 만들지 않는다. 도구가 하는 일은 아래 선언뿐이다.

- [ ] **단어**: `lib/vocabulary/tools/<도구>Words.js` — 도구에만 있는 조합·지표·보기. 공용 단어로 되는 건 만들지 않는다
- [ ] **사전 등록**: `lib/recipe/toolVocabulary.js`에 한 줄 → 마이페이지 "내 분석 설정"과 계정 저장(B)이 자동으로 이 도구를 지원
- [ ] **도구 선언(spec)**: 허용 지표·기간 종류·축 단수·블록 목록(`locked`: 결론의 근거)·내보내기 형식
- [ ] **어댑터**: `lib/recipe/<도구>Recipe.js` — 레시피 → 엔진 입력·보기. **엔진 수학은 변경 금지**
- [ ] **"있는 만큼 된다"**: 필수 필드를 완화할 수 있는지 확인하고, 안 되는 조합은 사유 문구
- [ ] **입력창 배치**: 필터 막대가 있으면 `commandSlot`, 없으면 결과 위. 필터 축과 겹치는 단어는 `onSelectStep`으로 필터에 쓴다
- [ ] **다운로드 설정(C)**: `ResultActionCard`에 `exportOptions` 전달. 카드 밖 그림은 `figureExportSettings` + `AnalysisExportProvider`로 감싸야 PNG에 닿는다. 도구 자체 CSV·PNG 항목은 `onSelect(exportContext)`로 받는다
- [ ] **정직성**: 보기 설정은 표에만(합계 검증은 가리기 전 행), 판정 보류·항등식 같은 근거는 숨김 불가
- [ ] **테스트**: 어댑터 골든 + 도구 스모크(축 교체 시 항등식·결과 불변 조건) + design-rules e2e(320/980/1440)
- [ ] **문서**: `docs/product-ssot.md` 도구 계약, `ARCHITECTURE.md` 경로
