# 프로젝트·구독 관심 검증 운영안

2026-09-09. 현재는 월 5,900원 구독 **관심 확인** 단계다. 결제·예약·자동 갱신은 없고 입금 안내도 없다. 은행·계좌·예금주·결제 확인 연락처는 미정이다. 실제 판매를 켜기 전에 세금 표시와 약관·환불·키 발급 운영을 별도로 확정한다.

## 측정 계약

| 목적 | 이벤트 | 필수 조건 | 해석 |
|---|---|---|---|
| 분석 결과 도달 | analysis_ready (GA 파생) | 원본 analysis_completed, result_state=ready, source!=demo, 원본 파라미터 복사 | 실제 데이터 결과 도달 |
| 결정 저장 | weekly_decision_committed (GA 파생) | 원본 weekly_decision_saved, source!=demo, 원본 파라미터 복사 | 다음 검토할 결정 저장 |
| 결정 재검토 완료 | decision_review_completed | 저장된 결정의 dataOrigin=real | 데모와 출처 미확인 구 기록은 주요 이벤트 제외 |
| 구독 설명 노출 | subscription_viewed | source=subscription_page | 일반 안내 조회 |
| 무료 한도 시도 | subscription_gate_viewed | source=project_limit | 추가 프로젝트를 만들려는 수요. 다른 source는 브랜딩/일괄 보고서 관심으로 분리 |
| 가격 제시 후 관심 | subscription_interest_clicked | state=monthly_5900 | 월 5,900원 문구를 보고 누른 관심. 결제 전환·예약·매출이 아님 |
| 보고서 보관 | weekly_report_saved | 저장 성공, source!=demo | 프로젝트에서 다시 읽을 보고서 저장 |

프로젝트명·파일명·헤더 값·원본 행·키·로고·실제 KPI 값은 전달하지 않는다. 브라우저 차단이나 분석 수집 설정에 따라 이벤트가 수신되지 않을 수 있으므로 화면의 관심 표시는 서버 접수 확인이 아니다. 같은 사용자의 반복 클릭과 고유 사용자 수를 구분한다. GA 속성 542428327에서 subscription_interest_clicked와 project_limit_reached를 주요 이벤트로 등록했다(2026-09-09). 둘 다 기본 금액 없음·세션당 한 번이다. project_limit_reached는 event_name=subscription_gate_viewed AND source=project_limit, 원본 파라미터 복사 조건이다. 배포 후 실제 수신은 별도 확인 대상이다.

## 저장/복원 계약

- 원본은 브라우저 IndexedDB에만 보관한다. 서버 업로드/동기화 없음. 프로젝트 소속은 사용자가 선택한다.
- 파일명과 기간은 고객 식별자가 아니다. 같은 프로젝트에서 기간이 바뀐 CSV를 올리며 컬럼·통화·기간 관계를 확인한다. 데이터 종류별 최신 파일이 교체되고 최대 16개 기간 집계가 남는다.
- 파일 25 MiB, 프로젝트 원본 합계 100 MiB, 브라우저 원본 합계 250 MiB, 프로젝트 기록 JSON 10 MiB, 백업 150 MiB, 로고 1 MiB/4096px. 유료도 같은 공간 한도다. 이는 앱 안전 한도이며 성능·처리 행 수나 브라우저의 공간 보장이 아니다.
- `/subscription`은 Blob 바이트 합계, 기록 JSON 크기, StorageManager의 사이트 사용량/할당량 추정치를 구별한다. 브라우저 추정값은 다른 사이트의 데이터가 아니라 이 출처의 다른 저장 데이터·캐시를 포함할 수 있다.
- 완전 백업에는 원본·매핑·필터·사용자 지표/차트 설정·운영 메모·주간 프로젝트 설정·집계·결정·저장한 보고서·브랜딩이 들어간다. 기존 '설정 파일' 내보내기는 도구 보기·사용자 지표 설정용 별도 형식이다. 라이선스는 백업하지 않는다.
- 가져오기는 형식/크기 확인, 원본 파싱, 기존 프로젝트 교체 확인 후 원자적으로 저장한다. 현재 무료 한도에서도 기존 프로젝트 복원·열기·내보내기는 허용한다. 다른 기기의 브라우저에 동일 백업을 가져오면 수동 이전할 수 있다.
- 저장소 전체 삭제는 모든 프로젝트의 원본·집계·결정·보고서·로고를 포함한다. 저장 실패는 분석 실패로 위장하지 않으며 세션 분석을 유지한다.

## 검증 범위

Vitest: 키 유효/만료/회수/오프라인 유예·다른 키 캐시 오용, 파일명 변경과 기간/컬럼/통화 관계, 구 프로젝트 변환, 결정 CSV 필드 왕복, 잘못된 백업 거절, CP949 원본 한글 복원.
Playwright: 실제 IndexedDB 구 단일 프로젝트 이전 → 백업 다운로드 → 무료 한도 → 관심 표시 → 삭제 → 백업 복원 → 재접속. KO 320/768/1440 및 EN 라이트, axe 포함. 기존 여러 프로젝트를 무료 상태로 각각 여는 경로도 검사한다.
미실측: iOS/Android 실기기, Lighthouse, 운영 Supabase 연결, 실제 지불 의향/결제 전환율. 테스트 결과와 실제 저장 크기 측정은 최종 검증 뒤 아래에 기록한다.

## 로컬 검증 결과
- Vitest: 409개 파일, 3,351개 테스트 통과. 기존 사용자 미추적 테스트도 포함한 로컬 결과이며 PR CI 수는 다를 수 있다.
- 전체 Playwright: 111개 통과, 용량 측정의 모바일/태블릿 중복 실행 2개 의도적 제외. 마지막 설정·운영 메모 보존 보강 후 프로젝트/주간 리뷰 16개 추가 통과(동일한 측정 제외 2개). KO 320/768/1440 및 EN 라이트·axe 포함.
- 10,000행·7열 합성 CSV를 실제 업로드하고 IndexedDB의 파일 바이트와 행 수를 확인했다. 원본 **490,053 bytes (약 0.47 MiB)**, 프로젝트 기록 JSON **2,241 bytes**, 해당 새 Chromium 테스트 프로필의 사이트 사용량 추정 **516,345 bytes (약 0.49 MiB)**. 이때 보고된 할당량 8,590,450,937 bytes는 그 환경의 추정치이며 제품 한도나 다른 기기에서의 보장이 아니다.
- 이름 변경·주간 재업로드, 기존 프로젝트 분리, 잘못된 원본을 포함한 백업의 복원 거절 시 기존 데이터 보존, 삭제 후 백업 복원/재접속, 무료 한도 관심 이벤트를 확인했다.
- 원격 브라우저 검사에서 초기화 전 DB 접근과 복원 중 프로젝트 전환의 시간차가 드러났다. 초기 파일·설정·메모 복원이 끝나야 프로젝트 준비 상태를 열도록 수정하고, 테스트도 SSR 제목 대신 실제 생성 버튼 활성화를 기다린다. 새 서버를 띄운 CI 모드에서 프로젝트 검사 8개 통과(용량 중복 측정 2개 제외).
- 전체 CI 모드 로컬 재실행은 110개 즉시 통과·1개 재시도 통과였다. 재진입 직후 삭제 버튼이 먼저 활성화되는 원인을 수정해 가져오기·내보내기·삭제에도 준비 상태를 적용했다. 수정 후 프로젝트 흐름을 각 기기에서 3회씩 반복해 24개 모두 통과(용량 중복 측정 6개 제외)했다.
