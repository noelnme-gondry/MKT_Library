| # | 원칙 | 한 줄 |

| P1 | 계산은 고정, 보여주는 방식은 자유 | `*Math.js`·골든 불변. 앞(데이터 맞추기)·뒤(결과 구성·다운로드)만 연다 |

### 1.1 "공통 틀"이 뜻하는 것 (P4 보충)

모든 도구가 같은 내용을 보여 준다는 뜻이 아니다. **블록의 종류와 블록에 대한 조작**만 공통이다.

| 블록 | 공통 조작 | 5-21이 담는 것 | 5-22가 담는 것 |
|---|---|---|---|
| `verdict` 결론 | 표시/숨김 | "CPA 1,200→1,450원, 가장 큰 기여 Meta" | "Google 포화, TikTok 여지" |
| `stat` 수치 | 고르기·순서 | 전체 변화·가장 큰 기여·채널 수 | 채널별 포화지수 |
| `figure` 그림 | 표시/숨김·허용 형태 안에서 바꾸기·PNG | Mix/Rate 기여 막대 | 한계 vs 평균 |
| `table` 표 | 열 고르기·정렬·상위 N·필터 | 채널/캠페인/소재 분해표 | 채널 포화 표 |
| `caveat` 한계 | 표시/숨김(다운로드는 §7) | "구성 분해는 인과 아님" | "관측 범위 밖은 외삽" |
| `action` 행동 | 표시/숨김·결정 기록 연결 | "Meta 캠페인 X 효율 점검" | "Google → TikTok 재배분" |

조작을 한 번 만들면 21개 도구 전부에서 동작한다. 지금 `MetricConfigPanel`·`CustomMetricBuilder`·`CustomChartBuilder`가
5-2 대시보드 밖으로 못 나간 이유가 이 공통 틀의 부재다(`custom-metrics-data-config-spec.md` §7 #3 보류).

## 2. 레시피 3종 (스키마 초안)

전부 순수 JSON. 원본 행·값·파일명은 넣지 않는다(§2.2 — 매핑 동기화와 같은 규칙, `product-ssot.md`의 2026-09-21 Pro 컬럼 매핑 동기화 결정).
단, **값 필터**(`Meta만`)는 유저가 고른 값 문자열이 들어간다 → 값 필터는 계정 동기화에서 빼고 기기에만 둔다(2026-09-30 확정).

```js
DataRecipe = {
  version: 1, toolId: "5-21",
  mapping: { [header]: standardKey },          // 기존 매핑 계약 그대로
  levels: ["channel", "campaign_id"],          // 분해 축 (도구가 허용하는 슬롯에 컬럼 배정)
  metric: "cpa",                                // 도구 허용 목록 안에서
  period: { kind: "lookback", weeks: 1, basis: "calendar" }  // | {kind:"range", a:{..}, b:{..}} | {kind:"monthOverMonth"}
  filters: [{ field: "channel", op: "in", values: ["Meta"] }],
}
ViewRecipe = {
  version: 1, toolId: "5-21",
  blocks: [{ id: "verdict" }, { id: "fig.mixRate" }, { id: "tbl.channel", columns: [...], sort: {...}, topN: 10, only: "worse" }],
  hidden: ["caveat.nonCausal"],                 // 숨김도 명시 기록
  labels: { "tbl.channel": "매체별 원인" },     // 이름 바꾸기(표시만)
  customMetrics: [...]                          // formulaEngine 서술자(기존 스펙 재사용)
}
ExportRecipe = {
  version: 1, format: "xlsx" | "docx" | "csv" | "png",
  blocks: "view" | [...ids],                    // 화면 뷰를 따를지 따로 고를지
  includeCaveats: true, withFormulas: true, branding: true, locale: "ko",
}
```

- **S1 구현 형태(2026-09-30)**: 위 세 객체를 따로 저장하지 않고 **고른 단어의 순서 목록(`steps: [{id, params}]`)만 저장**한다.
  세 레시피 상태는 `foldSteps`가 도구 기본값에서 단계를 접어 매번 파생한다 → 칩 목록과 상태가 두 벌이 될 수 없다.
  같은 `slot` 단어는 교체, `phase`는 적용 순서만 정한다(“OS로 먼저 나누기”는 칩 순서와 무관하게 기본 축 뒤에 적용).
- 레시피는 **도구가 선언한 허용 목록으로 검증**한 뒤 적용한다. 모르는 키·버전은 거절하고 이유를 보여 준다(§7 "모르는 미래 값은 거절").
- 레시피 적용 결과가 기존 화면 상태(`useSavedToolInput` 값들)와 두 벌이 되지 않게, 5-21의 `metricOverride`·`weekBasis`·`lookback`은
  **DataRecipe로 흡수**한다(§7 메타 4).

## 3. 명령 입력창 + 단어 사전

### 3.1 동작

1. 레시피 편집 자리에 입력창 하나. 치는 즉시 아래에 후보 목록(최대 8개)이 뜬다.
2. 후보를 고르면 **칩**으로 입력창에 남고, 해당 레시피 조작이 바로 적용된다(결과가 즉시 바뀜 — §9 즉시 피드백).
3. 칩을 지우면 그 조작이 취소된다. 칩 목록 = 레시피를 사람 말로 적은 것. 저장·공유도 이 칩 목록으로 보인다.
4. 사전에 없는 말은 적용하지 않는다. "해당하는 항목이 없습니다 — 이런 말은 됩니다: …"로 근처 단어를 제안한다.
5. 키보드: ↑↓ 이동, Enter 선택, Backspace로 마지막 칩 삭제, Esc 닫기. `role="combobox"` + `aria-activedescendant` 계약.

### 3.2 한글 매칭 규칙 (결정론)

| 입력 | 매칭 방식 | 예 |
|---|---|---|
| 완성 음절 접두 | 라벨·별칭의 접두 | `채` → 채널별, 채널+캠페인별 |
| 조합 중(IME) | 마지막 음절을 자모 분해해 접두 비교 | `챈`(채+ㄴ 조합 중) → 채널별 |
| 초성만 | 초성 열 비교 | `ㅊㄴ` → 채널별 |
| 영문·약어 | 별칭 | `cpa`·`CPI`·`mom` |
| 데이터 값 | 매핑된 컬럼의 실제 값 | `me` → `Meta만`, `Meta 제외` |

정렬: 정확 접두 > 초성 > 별칭 > 부분 포함, 동률이면 사전 순서(=추천 순). **입력마다 같은 순서**(결정론).

### 3.3 사전 항목 구조

```js
{
  id: "level.channel_campaign",
  kind: "level" | "metric" | "period" | "filter" | "view" | "export",
  label: { ko: "채널+캠페인별", en: "By channel + campaign" },
  aliases: { ko: ["채널 캠페인", "캠페인별"], en: ["by campaign"] },
  tools: ["5-21", "9-3"],            // 이 단어를 받는 도구
  requires: ["channel", { oneOf: ["campaign_id", "campaign_name"] }],   // P2: 없으면 비활성 + 이유
  conflicts: ["level.channel"],      // 같은 슬롯 단어는 교체
  apply: (recipe) => recipe',        // 순수 함수. 레시피만 바꾼다
  hint: { ko: "캠페인 단계까지 분해", en: "Decompose down to campaigns" },
}
```

- **사전이 제품의 핵심 자산**이다. 도구별 사전은 공용 단어(기간·필터·내보내기)와 도구 전용 단어(축·지표·보기)를 합쳐 만든다.
- 비활성 단어도 **숨기지 않고 흐리게 + 필요한 컬럼**을 보여 준다(§12.31 "못 쓰는 도구는 숨기지 말고" 와 같은 원칙).
- 가드: 사전의 모든 `requires` 키는 `STANDARD_FIELDS`에 실재, 모든 `apply` 결과는 레시피 검증 통과, 모든 `tools`는 `publishedToolIds()` 안 —
  사전에서 **파생**하는 테스트로 강제(§7 메타 1).

### 3.4 차원 컬럼 인식 — 표기가 제각각인 축 (필수)

유저는 같은 축을 전혀 다른 이름으로 쓴다(OS를 `플랫폼`·`platform`·`device`로, 국가를 `country`·`geo`·`마켓`으로).
축 단어(`OS별`·`국가별`)는 **인식된 컬럼이 있어야 뜨므로**, 인식이 곧 기능의 입구다.

현재 등록 상태(`utils/csvConstants.js`, 2026-09-30 실측):

| 표준 키 | 지금 별칭 | 빠진 흔한 표기(보강 후보) |
|---|---|---|
| `platform` (:21) | os · platform_name · campaign_platform · campaign_os · mkt_platform · 플랫폼 | device · device_os · os_name · app_platform · operating system · 운영체제 · 기기 · 디바이스 · OS구분 |
| `country` (:96) | country · mkt_country · 국가 · country_code · 마켓 | geo · country_name · nation · market · 나라 · 국가명 · 국가코드 · 지역(모호 — 아래) |

주의: 표준 키 `platform` 자체가 별칭에 없고 헤더명 일치로만 잡힌다 — 대소문자·공백·접미사(`Platform (OS)`) 변형을 매핑 테스트로 확인할 것.

인식은 세 겹으로 한다(엔진 불변, 매핑 계층만):

1. **헤더 별칭 보강**: 위 표를 `STANDARD_FIELDS`와 의미 매퍼(`semantic-mapper/nameFeatures.js`의 `platform`·`country`) **양쪽에** 같은 목록으로(두 벌이면 갈린다 — 한쪽에서 파생하거나 정합 테스트).
2. **값으로 판별**(`valueVocabulary`, §7 "헤더명이 아니라 값으로 매핑"): 헤더가 `구분`·`type`·`dim1`처럼 무의미해도 값이
   `iOS·Android·AOS·ios·aos·iPhone·안드로이드` 대부분이면 OS, `KR·US·JP·Korea·대한민국·한국·미국` 대부분이면 국가로 후보를 올린다.
   숫자 컬럼 제외·짧은 토큰 정확일치 규칙(PR #603 함정)을 그대로 따른다.
3. **그래도 못 잡은 문자열 컬럼은 원래 이름으로 축 단어를 만든다**: `권역`·`앱 버전`처럼 표준 키가 없는 차원도 `권역별`로 뜬다.
   표준 필드를 계속 늘리지 않는다(5-29 `SegmentRoleMapper`와 같은 원칙). 단 카디널리티가 행 수에 가까운 컬럼(ID·자유 텍스트)은 축 후보에서 뺀다.

`지역`·`region`은 국가일 수도 권역일 수도 있어 헤더만으로 가르지 않는다 — 값 판별(2)이 국가 어휘면 국가, 아니면 (3)으로 원래 이름 축.

**대소문자·앞뒤 공백만 다른 값은 자동으로 같은 값으로 합친다**(2026-09-30 사용자 결정, 앞선 "자동 금지" 안을 뒤집음).
대표 표기는 가장 많이 나온 표기(동률이면 먼저 나온 것). 숫자가 바뀌는 처리이므로 합친 묶음을 화면에 알리고(`dimensions[].merged`),
`대소문자 구분하기` 단어로 되돌릴 수 있다. 구현 `lib/vocabulary/dataContext.js` `buildValueCanonicalizer`.

**"채널별"이 우리 필드인지 CSV 컬럼인지는 매핑이 정한다**(2026-09-30 결정, 구현 `buildDataContext`):
- 컬럼이 표준 필드로 매핑돼 있으면 단어는 하나(`채널별`)이고 힌트에 실제 컬럼명(`컬럼: 매체`)을 보인다. 컬럼명으로 쳐도 찾는다.
- 매핑 안 된 문자열 컬럼은 이름 그대로 단어(`권역별`, 힌트 `CSV 컬럼 그대로`). 표준 단어와 이름이 겹치면 `채널 (CSV 컬럼)별`.
- 축 필드가 비어 있고 이름이 그 필드 별칭인 컬럼이 있으면 `채널별 — '매체'를 채널로 지정` 후보. 고르면 **매핑과 축을 한 번에** 적용한다
  (`toSelection` → `{mapping, step}`; 매핑은 기존 매핑 스토어에 쓰고 레시피에는 저장하지 않는다 — 매핑 SSOT 유지).
- 드롭다운 순서: 같은 순위 안에서 축 단어가 먼저(`채` → 채널별 · 채널+캠페인별 · 채널+캠페인+소재별), 부분 일치는 아래(`캠` → 캠페인별이 먼저, 채널+캠페인별은 그 아래).

가드: `lib/platformExports.js` 플랫폼 내보내기 파일 + 표기 변형 픽스처(헤더·값 각각)로 **기존 계약·의미 매퍼 V2·분석 자격 셋 다** 통과를 단언(§7 데모 픽스처 함정).

### 4.2 "있는 만큼 된다" — 컬럼 조합별 계산 가능 항목

엔진 `PVM_MATH`는 분해 축을 **필드 이름으로** 받는다(`pvmMath.js:191` `r[keys.ch]`). 즉 채널 자리에 국가·OS 컬럼을 넣어도
수학은 그대로다 → 축 선택 자유를 **엔진 변경 없이** 열 수 있다(컴포넌트의 `keys` 조립만 바뀜).

| 있는 컬럼 | 되는 것 | 안 되는 것(이유 표시) |
|---|---|---|
| 날짜·비용·결과 + 축 1개 | 1단 Mix/Rate 분해, 스코어카드 | 캠페인·소재 단계(축 컬럼 필요) |
| + 캠페인 | 2단 분해, 캠페인 표 | — |
| + 소재 | 3단 분해, 소재 표, 신규 소재 | — |
| + 소재 URL | 소재 미리보기 링크 | — |
| + 노출 | CPM × 반응률 분해 | — |
| 결과 2종(설치·가입) | CPA/CPI 전환 | 하나만 있으면 그 지표 고정 |
| 날짜 2주 미만 | — | 주간 비교 전부(기간 단어 비활성, "최소 2주 필요") |

현재 필수 필드 `5-21: date · spend|cost · channel · installs|actions`(`csvConstants.js:1307`) 중 **`channel`을 "축 1개 이상"으로 완화**하는 것이 P2의 첫 적용이다.
→ 채널 컬럼이 없고 캠페인만 있는 CSV도 분석이 열린다. 축 조합 가드: 같은 컬럼 중복 배정 금지, 상위가 하위를 포함하는 순서 유지(over-merge 함정 §7 — 복합키는 엔진이 이미 처리).

## 5. 정직성 가드 (P5 구체화)

- 레시피는 **입력 범위와 표시**만 바꾼다. 엔진 출력 숫자를 바꾸는 조작 단어는 사전에 두지 않는다.
- 필터·상위 N으로 **일부만 보이면 결론·수치 옆에 범위를 표시**("Meta만 · 상위 5개"). 칩 목록이 곧 범위 표기다.
- 필터는 두 종류를 구분한다: ① **분석 전 범위**(행을 빼고 다시 분해 → 숫자가 바뀜, 정당) ② **보기 필터**(분해는 전체, 표에서만 숨김). 단어 라벨이 둘을 구분해야 한다(`Meta만 분석` vs `Meta만 보기`) — 섞이면 "합이 안 맞는다"는 의심이 나온다(§12.10 롤업 항등식).
- 항등식 확인·판정 보류 사유는 결과의 **근거**라 숨김 대상에서 뺀다(2026-09-30 확정).
