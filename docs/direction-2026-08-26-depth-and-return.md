## 1. 이 결정이 바꾸는 것 (먼저 알아야 할 두 가지)

### 1.1 지금 공개된 사실 하나가 **거짓이 된다**

`brandFacts.js`와 `docs/product-ssot.md`에 이렇게 적혀 있다.

```
F-04  "새로고침하면 분석 데이터가 사라집니다."
      detail: "분석 결과를 서버나 브라우저 저장소에 남기지 않는 것이 기본 동작입니다."
      en: "Results are not persisted to a server or browser storage by default."
```

**기본값을 ON으로 올리는 순간 이 문장은 사실이 아니다.** 이건 부수적인 문구 손질이 아니라 §2.8(정직성) 위반이 되는 지점이고, 같은 문장이 랜딩·도구 롱폼·`llms.txt`·개인정보처리방침·비교 페이지에 파생돼 있다. 그래서 **저장 기본값 변경과 카피 교체는 같은 PR이어야 한다.** 둘을 나누면 그 사이 배포분이 거짓말을 한다.

순서도 정해져 있다(§2.12) — **`docs/product-ssot.md`를 먼저 고치고 `brandFacts.js`를 그 사본으로 맞춘다.** 반대로 하면 SSOT가 코드를 따라가는 역전이 된다.

### 1.2 재업로드 마찰(B3)이 **완전히 풀린다**

지난 계획에서 B3은 "파일은 매번 다시 골라야 해서 반쪽"이라고 적었다. IndexedDB를 쓰면 그 전제가 사라진다.

```
지금        매주 CSV 다시 고름 → 매핑 확인 → 분석          (마찰 3단계)
IndexedDB   사이트 열면 지난주 데이터 그대로 → 새 주차만 추가  (마찰 1단계)
```

**이게 이번 결정의 진짜 크기다.** 영속 기본값 ON은 "배지를 띄우려고" 켜는 게 아니라 **매주 다시 올리는 일을 없애려고** 켜는 것이다. 재방문의 최대 장애물이 여기였다.

## 2. 저장소 선택 — localStorage vs IndexedDB

지금 `useDataStore`는 `persist` + `partialize` 허용목록으로 **localStorage**를 쓰고, 원본 CSV는 저장하지 않는다.

| | localStorage (현재) | IndexedDB (제안) |
|---|---|---|
| 용량 | 약 5MB | 수백MB~ (기기·브라우저 여유에 따름) |
| 20만 행 CSV | **불가능** | 가능 |
| 저장 형태 | 문자열만 | 구조화 객체·Blob |
| 접근 | 동기 | 비동기 |
| 외부 전송 | 없음 | 없음 |
| 다른 사이트에서 읽기 | 불가(오리진 격리) | 불가(오리진 격리) |
| 서비스 제공자 열람 | **불가** | **불가** |

**Gondry님 판단이 맞다** — IndexedDB는 기기 안에서만 살고 네트워크로 나가지 않으므로, 여기에 원본을 둬도 "제공자가 데이터를 못 본다"는 정체성은 그대로다. §2.2(서버 전송·저장 금지)도 안 깨진다.

**권고: 둘 다 쓰는 2층 구조.**

```
localStorage   설정·플래그·결정 기록 요약   (작고, 동기 읽기가 필요하고, 첫 페인트에 쓰임)
IndexedDB      원본 CSV·매핑·분석 스냅샷    (크고, 비동기로 늦게 와도 되는 것)
```

전부 IndexedDB로 옮기면 비동기라서 첫 렌더 분기가 전부 로딩 상태를 타야 한다. 지금 잘 돌아가는 걸 건드릴 이유가 없다.

### 정직하게 짚어둘 것

원본 CSV가 디스크에 남는다는 건 **새로운 성질**이다. 제공자는 못 보지만, **그 기기를 쓰는 사람은 본다.** 마케팅 운영 데이터는 사내 민감 자료이므로(§1) 다음 통제 장치가 저장 기능과 **같이** 나가야 한다. 나중에 붙이면 안 된다.

- [ ] **한 번에 지우기** — 눈에 띄는 곳에. 묻힌 설정 안이 아니라
- [ ] **자동 만료** — 마지막 사용 후 N일(초안: 30일) 지나면 자동 삭제. 잊고 방치한 데이터가 영원히 남지 않게
- [ ] **저장 중 표시** — 지금 이 기기에 무엇이 남아 있는지 화면이 말한다(파일명·주차·용량)
- [ ] **끄기** — 기본은 ON이되 끄면 즉시 전부 삭제
- [ ] **사생활 보호 모드 대응** — IndexedDB가 없거나 세션 종료 시 사라지는 환경에서 조용히 실패하지 말고 "이 브라우저에서는 저장이 안 돼요"로 정직하게
- [ ] **브라우저 자동 정리 대응** — 용량이 부족하면 브라우저가 임의로 지울 수 있다. 지워졌을 때 "데이터가 있었던 것처럼" 굴지 말 것

그리고 하네스도 같이 고쳐야 한다. `AGENTS.md §7`에 **"localStorage 영속 금지(사용자가 명시적으로 켠 경우만). 새로고침 리셋이 기본."** 이 규칙이 있다. 기본값을 뒤집으면 이 줄이 틀린 규칙이 되고, **틀린 규칙은 없는 규칙보다 해롭다**(§15). 같은 작업에서 갱신한다.

## 3. 새 정체성 카피 (초안)

지금 문장은 정확하지만 어렵다 — "클라이언트 사이드", "서버로 전송하거나 저장하지 않습니다"는 마케터의 말이 아니다. 핵심을 **구조로** 말하면 훨씬 강해진다: *못 보는 게 아니라, 볼 방법 자체가 없다.*

### 한 줄 (히어로·랜딩)

> **KO** — 데이터를 모아두는 서버가 없어요. 그래서 만든 사람도 여러분 파일을 볼 수 없어요.
> **EN** — There's no server collecting your data. Not even we can see your file.

### 상세 (개인정보처리방침·FAQ·롱폼)

> **KO** — 올린 파일은 이 브라우저 안에서 열리고 계산돼요. 저장을 켜두면 **이 기기 안에만** 남고, 인터넷으로 어디에도 보내지 않아요. 언제든 한 번에 지울 수 있어요.
> **EN** — Your file is opened and calculated inside this browser. With saving on, it stays **on this device only** and is never sent anywhere. You can erase it all at any time.

### F-04 교체안

```
기존  "새로고침하면 분석 데이터가 사라집니다."
신규  "분석 데이터는 이 기기에만 저장됩니다. 서버로 보내지 않고, 언제든 지울 수 있습니다."
      en: "Your analysis data is stored on this device only. It is never sent to a server, and you can erase it at any time."
```

**쓰면 안 되는 표현**: "100% 안전", "완벽한 보안", "절대 유출되지 않음". 제품이 보장할 수 있는 범위(전송 안 함·서버에 없음)를 넘는 주장이고, `brandFacts.js`에 이미 그 이유가 주석으로 적혀 있다.

### 고쳐야 할 곳

`brandFacts.js`가 SSOT라 파생은 자동이지만, 파생이 아닌 자리가 남아 있다.

1. `docs/product-ssot.md` F-04 (**먼저**)
2. `src/lib/brandFacts.js`
3. `src/app/(ko)/privacy/page.js` · `(en)/en/privacy/page.js` — 저장 항목·보관 기간·삭제 방법
4. `src/app/llms.txt/route.js` — 파생이지만 문장이 바뀌므로 스냅샷 확인
5. `CsvGuide` / 업로드 화면의 안내 문구
6. 관련 테스트 — **문장을 테스트에 복사하지 말고 SSOT를 조회해 대조할 것**(§12.29)
