# 퍼널 재점검 및 작업 상태

기준: `771f69b3`와 작업 브랜치 `codex/blog-inline-csv-insights`. 배포나 외부 서비스 활성화 완료 보고가 아니다.

## 감사에서 바로잡을 표현

- 자동갱신 없는 5,900원 상품이라고 LTV 상한이 반드시 5,900원인 것은 아니다. 반복 구매를 막는 코드가 없다면 상한·재구매율 0은 성립하지 않는다. 실제 구매자 코호트 계측이 필요하다.
- “이메일·푸시·.ics 모두 0건”은 기준 커밋과 불일치한다. `WeeklyReviewScreen`은 이미 `serializeDecisionReviewIcs`와 `downloadCalendar` 버튼을 사용하고 있었다. 다만 사용자가 직접 캘린더를 받아야 하므로 자동 발송과는 다르다.
- 기존 여러 프로젝트·브랜딩도 유료 범위다. 다운로드만이 유일한 유료 기능이라는 표현은 범위를 좁혀야 한다. 반복 가치와 신원 확보가 약하다는 문제 제기는 별도로 유효하다.
- 지원 비용·환불 증가·가격 이탈 원인은 운영 데이터 없이 확정하지 않는다. 우선 검증할 가설이다.
- 현재 `HomeToolFinder`는 목적을 고르거나 ‘전체 도구 보기’를 누르기 전 상세 도구 목록을 접어 둔다. 모든 도구가 처음부터 펼쳐진다는 지적도 기준 코드와 구분해야 한다.

## 코드 반영

- B안의 선택 메모 저장 API, Google 계정 인증, 최초 성공 저장부터 1회 14일 Pro 체험, 만료 후 읽기/내보내기/삭제 유지. 선택한 메모만 보내고 CSV·스냅샷·매핑은 제외한다.
- 기존 구매 유지 및 명시적 계정 연결. 최초 저장 시각은 DB 트랜잭션에서 기록한다. 로그인 팝업은 분석 페이지를 그대로 둔다.
- 발행 블로그 47편의 KO/EN을 조사하여 37편에 H2 섹션별 경량 뷰를 배치하고, CSV 계산에 맞지 않는 10편에는 제외 사유를 기록했다. 설계/인과 모형이 필요한 글은 기술적 집계임을 명시하며 완전한 모델 판정을 가장하지 않는다.
- 차트 하나, 결과, 상세 분석으로 동일 CSV 전달. 기존 데이터 교체 동의·프로젝트 변경 감지·공유 그룹 매핑·잘못된 숫자 거부를 적용했다.
- 수학 엔진 수정 없음. 기존 사용자 변경 및 미추적 작업 보존.
- 후속 구현: 결제 위젯 자동 준비와 단일 결제 버튼, 실행 전 로컬 임시 보관·복귀 복원·24시간 만료·전체 삭제 연동, 상단 가격, 모바일 경량 진입/PC 링크, 선택형 게이트 보류 사유, 시트 갱신 우선 버튼, 환불정책 위계 조정.
- SMTP 작업 큐·결제 안내·선택 동의 검토/D-7 메일·기존 계정 이메일 로그인, 계정 메모의 로컬 검토 목록 복사, 체험 잔여 버킷 계측을 구현했다. 운영 발송은 설정/실검증 전 비활성이다.

## 아직 하지 않은 것

- 운영 OAuth 연결, DB 마이그레이션 실행, 실계정/실결제 검증, 배포.
- 운영 SMTP·발신 도메인·고지 확정 및 스케줄러 등록, 실제 이메일 수신/반송 검증.
- 자동갱신 또는 상품 가격/ID 전환. 기존 비자동갱신 구매 계약을 유지했다.
- Buttondown 실제 구독 완료의 제품 내 대시보드 연동은 미구현이다. 현재는 제출 시도만 계측하며 실제 완료는 Buttondown에서 확인한다.

운영 활성화 조건과 실제 환경 점검은 `account-archive-rollout.md`에 정리했다.
