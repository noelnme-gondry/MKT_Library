# 주간 리뷰 개선 실행안과 운영 검증

기준: `weekly-review-monetization-readiness-2026-09-09.md`의 후속 제안. 이전 #812의 결함 수정은 완료된 기준선이며, 이 문서는 그 이후의 측정·분석 품질·도구 연결·블로그·수익화 결정을 다룬다.

## 이번 구현

- 주간 화면의 공통 업로더가 `weekly-review`를 계측 식별자로 사용한다. 데이터 계약과 계산 그룹은 기존 대시보드 계약을 그대로 사용한다.
- 실제 블로그 본문에 렌더된 공개 도구 링크의 노출과 같은 탭 클릭을 기록한다. 별도 작성한 CTA 목록을 순회하지 않는다. KR/EN 모두 적용하며 외부 링크·다운로드·새 탭 클릭은 현재 탭의 분석에 귀속하지 않는다.
- 주간 리뷰 진입→업로드→매핑→결론→결정 저장→복사/인쇄를 같은 도구 식별자로 연결한다. 글 귀속은 클릭한 도구·언어가 일치하는 30분 안의 이벤트에 한정한다. 데모 결과·데모 보고서는 실사용 글 전환에 귀속하지 않는다.
- 업로드 시작부터 첫 결론까지 시간은 구간으로만 전송한다. 새로고침으로 시작 시각을 잃은 경우 시간을 추정하지 않는다. 새 파일 업로드가 시작되면 그 시점부터 다시 측정한다.
- 결과를 만들지 못한 주간 비교는 차단 사유를 보내며, 저장 집계의 최초 복원 중 상태는 제외한다. 완료 결과도 `signal / quiet / unknown`을 구별한다. `unknown`을 정상 분석 실적으로 합치지 않는다.
- 복사는 실제 클립보드 쓰기 성공일 때 `state=completed`, 인쇄는 `state=requested`다. 인쇄 요청을 PDF 저장 성공이나 실제 공유로 보고하지 않는다.

파일명·프로젝트명·캠페인명·지표값은 이벤트에 포함하지 않는다. 글 슬러그는 공개 콘텐츠 식별자다. 지표는 브라우저의 분석 전송 허용과 광고 차단 여부에 영향을 받는다.

## 매주 볼 측정표

분석 시 아래 조건으로 **순서 있는 세션 퍼널**을 구성한다. 계정의 보고서가 사용자 단위라면 이를 세션 완료율로 바꿔 표시하지 않는다. 단순 이벤트 건수의 나눗셈은 재시도·여러 파일·설정 변경 때문에 완료율이 될 수 없다. KR/EN과 데모를 분리하고, 같은 날짜 범위에서 분모·분자와 표본 수를 함께 기록한다. 현재 문서에는 실사용 수치가 없다.

| 질문 | 이벤트와 조건 | 해석 및 다음 행동 |
|---|---|---|
| 글에서 도구가 보이는가 | `blog_cta_viewed`, `placement=article_body` | 실제 뷰포트 진입. 글 전체 방문 수와 같은 분모가 아님. 관찰 API가 없는 환경은 노출 미측정 |
| 보인 링크를 누르는가 | 위 노출→`blog_tool_cta_clicked`, 같은 글·도구·언어 | 같은 탭 경로만 비교. 새 탭을 실패로 단정하지 않음 |
| 실제 파일로 끝내는가 | `data_import_start`→`data_import_success`→`mapping_confirmed`→`weekly_review_completed`, `tool_id=weekly-review`, 데모 제외 | 완료는 보고서 생성까지이며 업무상 결론의 정확성이나 유용성을 입증하지 않음 |
| 어디서 멈추는가 | `data_import_failed`, `analysis_blocked`, `weekly_review_blocked` | 파싱/필수 매핑/기간 비교 사유를 구별. 실패 후 성공한 세션은 최종 완료에도 포함 |
| 얼마나 걸리는가 | 완료의 `elapsed_bucket` | 업로드 시작 이후 경과 시간. 읽는 시간 포함, 계산 실행 시간 아님. 값 없는 복원 세션을 0초로 채우지 않음 |
| 판단 가능한 결과인가 | 완료의 `result_state` | `unknown` 비중과 차단 사유를 먼저 개선. `quiet`는 동등성·효과 없음의 입증 아님 |
| 저장한 집계로 이어지는가 | 완료의 `data_continuity=saved_snapshot` | 데이터 연결 사용량이다. 사람 단위 재방문율·장기 유지율이 아님 |
| 보고서를 가져가는가 | 완료→`weekly_review_export`, clipboard/completed와 print/requested 분리 | 복사 이후 실제 팀 사용은 인터뷰로 확인. 데모는 별도 |
| 행동을 남기는가 | 완료→`weekly_decision_saved` | 저장은 실행 사실이나 성과 개선의 증거가 아님 |

`weekly_review_viewed`는 같은 페이지 런타임에서 언어별 한 번, 완료는 기존 입력 키별 한 번이다. 새로고침은 중복 방지 메모리를 초기화한다. 따라서 이벤트 수를 고유 사용자 수로 쓰지 않는다. 클릭 귀속용 sessionStorage는 별도 30분 한도이며 탭 간·기기 간 연결을 약속하지 않는다.

## 분석 품질 검토 순서

1. 실제 데이터 사용 동의를 확인하고 브라우저에서만 업로드한다. 검토 기록에는 익명 사례 번호를 사용하고 원본 파일·캠페인 식별자를 저장소나 이슈에 첨부하지 않는다.
2. 비교 전 기간 길이·누락 날짜·통화·전환 정의·매체 귀속 기간·집계 단위를 확인한다. 서로 다른 정의가 섞였으면 임계값 튜닝 대상에서 제외하고 입력 안내 개선 사례로 남긴다.
3. 결과를 보기 전에 운영 담당자가 사례를 `추가 확인 필요 / 유지하며 관찰 / 판단 불가`로 표시하고 근거를 남긴다. 이것은 전문가 참고 판정이며 인과효과의 정답이 아니다.
4. 현재 5%·z 1.5·30전환 기준에서 화면 상태와 담당자 판정을 대조한다. 변동성 이력 부족·저볼륨·0분모·부분 기간은 별도 묶음으로 본다. 판단 불가를 음성 사례로 넣지 않는다.
5. 알려진 사건만 모으지 말고 변화가 없던 기간도 포함한다. 같은 캠페인의 연속 주가 독립 표본인 것처럼 정확도를 과장하지 않는다. 탐색에 쓴 기간과 최종 확인 기간은 분리한다.
6. 오탐/미탐이라는 표현을 쓸 때는 전문가 참고 판정 대비임을 명시한다. 실제 효과의 오탐률이나 p값으로 해석하지 않는다. 불일치 원인이 입력 정의라면 임계값보다 입력 계약을 고친다.
7. 기준 변경은 사례별 개선·악화와 보류 건수를 비교한 뒤 결정한다. 현재는 실제 사례가 없어 임계값을 변경하지 않았다. 기존 수학 엔진은 그대로 둔다.

검토 기록 열: 익명 사례 번호 / KPI 종류 / 완전·부분 기간 / 이력 충분 여부 / 볼륨 충분 여부 / 전문가 참고 판정 / 화면 상태 / 불일치 설명 / 안내 수정 또는 추가 검증 필요. 금액·원본 행은 기록에 필요하지 않다.

## 추가 도구 연결 판단

| 반복되는 업무 질문 | 기존 도구 후보 | 연결 전 확인할 조건 |
|---|---|---|
| CPA 변화가 어느 캠페인 구성과 관련되는가 | 기존 PVM | 이미 V1에서 사용. 결과 비중의 산술 기여이며 인과 원인으로 바꾸지 않음 |
| 증액 여지가 있는가 | 포화도 진단·예산 배분 | 비용 범위·충분한 관측·목적 KPI 확인. 주간 변화 하나로 최적 예산을 약속하지 않음 |
| 소재 교체가 필요한가 | 소재 분석 | 소재 식별자와 일별 관측이 있는지 확인. 캠페인 주간 집계를 소재 데이터로 간주하지 않음 |
| 어떤 구성에서 변화했는가 | 구성 변화 분석 | 실제 분할 축과 집계 단위 확인. 매핑되지 않은 축을 임의 생성하지 않음 |
| 채널 기여를 알고 싶은가 | MMM·공선성 점검 | 장기 주간 패널·식별 가능성·불확실성 확인. 2주 업로드에서 MMM으로 자동 이동시키지 않음 |

도입 순서는 인터뷰에서 반복된 질문과 실제 입력 충족 여부로 정한다. `enabled:false` 신호를 일괄 활성화하거나 신규 엔진을 추가하는 것은 이번 단계의 성과 지표가 아니다.

## 블로그·SEO 운영

실제 본문 링크 계측을 먼저 배포한 뒤, Search Console에서 같은 길이의 변경 전후 기간을 비교한다. 페이지·쿼리·국가·기기를 나누고 시즌·순위 변화도 함께 기록한다. CTR 변화만으로 CTA 또는 본문 수정의 효과라고 단정하지 않는다.

우선 검토군은 진단·예산·보고 업무 글이다. 후보를 검색 노출 순으로 정렬하고, 글의 실제 질문과 연결된 도구의 데이터 요구를 대조한다. 글 제목/H1을 무작정 늘리거나 모든 글을 주간 리뷰로 보내지 않는다. 기존 도구 링크가 사용자 질문을 더 직접 해결하면 유지한다. 편집 시 KR/EN 본문·CTA·메타·실제 내부 링크 검증을 함께 수행한다.

검토표: 페이지 / 실제 유입 쿼리 / 노출·클릭 / 본문 도구 링크 노출·클릭 / 실제 CSV 완료 세션 / unknown·차단 비중 / 수정 가설 / 변경일 / 검증 결과. GSC·GA4 자료가 없으므로 이번에 노출 상위 글 또는 전환 상승을 주장하지 않는다.

## 구매·라이선스 착수 조건

무료 분석 정책은 유지한다. 월 5,900원·연 59,000원은 검토 가격이며 아직 확정되지 않았다. 다음 구현 전 판매 기능 범위, 결제 사업자, 확정 가격, 환불·해지, 라이선스 복구와 오프라인 유예를 결정해야 한다. 마케팅 데이터는 결제·라이선스 서버로 보내지 않는다.

먼저 인터뷰에서 현재 보고 업무, 실제로 가져간 보고서, 다음 주 재사용, 지불 이유를 확인한다. 기능 사용 횟수를 지불 의향으로 바꾸지 않는다. 결제 정책이 정해지기 전 가짜 구매 버튼이나 유료 기능 약속을 공개하지 않는다.

## 외부 자료가 있어야 끝낼 수 있는 항목

- 미실측 — 필요한 것: 동의받은 실제 캠페인 사례와 운영 담당자 참고 판정. 임계값 튜닝 결과는 아직 없음.
- 미실측 — 필요한 것: Search Console·GA4의 변경 전후 집계 자료. 검색/전환/유지율 개선 수치는 아직 없음.
- 미확정 — 필요한 것: 판매 범위·결제/가격/환불/라이선스 정책. 결제 구현은 아직 없음.
- 미실측 — 필요한 것: 실제 iOS Safari·Android 데스크톱 사이트 모드 및 Lighthouse 실행. Chromium 검증을 이 기기들의 실측으로 대신하지 않음.

## 구현 검증

- 로컬 전체 테스트 404파일·3316개 통과. 사용자 미추적 테스트 2파일·6개는 보존했으며 커밋하지 않는다. 원격의 예상 기준은 402파일·3310개다.
- lint 오류 0, 프리렌더 301페이지 빌드 통과. 실제 원격 결과는 PR의 Test plan으로 확인한다.
- 전체 Chromium E2E 95개 통과. 주간 경로는 KO 320/768/1440 다크와 EN 1440 라이트에서 실제 본문 링크 노출→업로드·매핑→완료 이벤트 귀속→보고서 복사→다음 기간 재사용을 검사한다. axe·가로 넘침·원본 행의 네트워크 누출 검사도 유지한다.
- 초기 브라우저 검증에서는 테스트용 gtag 함수가 동의 초기화 스크립트에 덮어써져 수집값이 비었다. 실제 이벤트 큐를 관찰하도록 검증 코드를 바꾼 뒤 통과했다. 외부 분석 서버로 테스트 이벤트를 보내지 않는다.
