계획서에 "만들자"고 적었던 재방문 장치 넷이 **전부 이미 구현돼 있었다.**

| 계획서 항목 | 실제 상태 | 위치 |
|---|---|---|
| B-3 복귀 화면 | **있음** | `LandingPage.jsx:213` `.dc-return` 섹션 (검토 대기 수·다음 검토일) |
| B-3 헤더 배지 | **있음** | `Header.jsx:72` · `Sidebar.jsx:88` `dueDecisionCount` |
| B-4 캘린더 `.ics` | **있음** | `decisionReview.js:152` `serializeDecisionReviewIcs` → `WeeklyReview.jsx:460`·`DecisionReview.jsx:369` |

**그리고 이 다섯 개가 전부 한 개의 플래그 때문에 꺼져 있다.**

```
decisionPersistenceEnabled: false     ← useDataStore.js:588 (기본값)
        ↓
새로고침하면 decisionRecords = []
        ↓
LandingPage의 .dc-return  →  decisionRecords.length > 0 이 거짓 → 섹션 자체가 안 그려짐
Header·Sidebar 배지        →  dueDecisionCount = 0 → 배지 없음
.ics 내보내기              →  내보낼 기록이 없음
주간 리듬 3단 CTA          →  3단계(REVIEW)에 아무것도 없음
```

**재방문 기능을 새로 만들 게 아니라, 만들어 둔 걸 켜는 일이다.**
이건 §16의 "신호를 계산해 놓고 판정에 안 쓰는 자리가 반복된다"의 가장 큰 사례다 —
계산도 화면도 다 있는데 데이터가 세션과 함께 사라져서 전부 빈 채로 돌고 있었다.

### 그래서 재방문 계획은 5개에서 1개로 줄어든다

| 옛 번호 | 항목 | 결정 |
|---|---|---|
| B-1 | 저장 기본 ON + 카피 + IndexedDB + 사생활 통제 | **유일하게 남는 작업** |
| B-2 | IndexedDB | B-1에 흡수 |
| B-3 | 복귀 화면 | **삭제 — 이미 있음** |

| B-5 | 랜딩 CTA | **삭제 — 이미 있음**. 켜진 뒤 실제 화면 보고 재판단 |

**B-1 착수 후 반드시 할 일**: 저장이 켜진 상태에서 위 다섯 화면을 실제로 열어볼 것.
지금까지 **아무도 데이터가 있는 상태의 이 화면들을 본 적이 없다.** 빈 상태로만 검증된 UI다.

## 2. 유입 — 여기가 진짜 남은 일

### 2.1 실측 현황

콘텐츠 분량은 이미 얇지 않다(8~16KB). **분량 문제가 아니라 주제 커버리지 문제다.**

| 클러스터 | 편수 | 실측 신호 |
|---|---|---|
| channels | 9 | 경쟁 최대(공식 문서·대행사 블로그 점유) |
| causal | 8 | 업리프트 6위 · 인크리멘탈 9.3위 ★ |
| **measurement** | **7** | **SKAN 질의 250+ 노출 · EN 40위내 10/15가 SKAN 계열** ★★ |
| diagnosis | 7 | — |
| creative | 5 | — |
| budget | 5 | CPI/CPA 8.3위인데 클릭 0 |

**이기는 두 곳(measurement · causal)에 편수가 가장 적게 들어가 있다.**

SKAN 용어사전은 이미 8편 있다(`att`·`skan`·`postback`·`conversion-value`·`crowd-anonymity`·
`attribution-window`·`attribution`·`probabilistic-attribution`). 블로그가 그만큼 안 따라갔다.

### 2.2 A-1 — pillar 재지정 (작음, 글 0편)

measurement 클러스터의 pillar가 `attribution-data-mismatch`(8KB)인데,
실제로 순위를 끄는 건 `ios-att-skan-guide`(12KB, SKAN 질의의 관문)다.

```
현재  pillar: attribution-data-mismatch  ← 데이터 불일치는 SKAN의 결과이지 입구가 아님
제안  pillar: ios-att-skan-guide         ← 검색이 실제로 도착하는 자리
```

`topicClusters.js:62` 한 줄 + 내부 링크 재배선. 클러스터 blurb도 SKAN 축으로 바꾼다.

### 2.3 A-2 — measurement 7 → 14편

기존 5편의 목차를 전수 확인해 **실제로 비어 있는 주제만** 골랐다.
(중복 회피: 창 3개 구조는 `skan4-migration-guide`, 64칸 설계는 `skan-conversion-value-schema`,
MMP 차이는 `skan-vs-mmp-attribution`, 포스트백 진단표는 `postback-integration-guide`에 이미 있다.)

| # | 주제 | 왜 비어 있나 |
|---|---|---|
| 1 | **crowd anonymity 티어** — 낮은 티어에서 값이 지워지는 구조와 대응 | 용어사전에만 있고 블로그 0편. 실무자가 "값이 왜 null이냐"로 가장 많이 막히는 자리 |
| 2 | **null·redacted 포스트백 읽는 법** | 위와 짝. "데이터가 없다"와 "익명화됐다"를 구분 못 하면 판단이 뒤집힌다 |
| 3 | **AdAttributionKit 전환 준비** | `ios-att-skan-guide`에 "다음 세대"로 한 줄만 있음. 전용 글 없음 |
| 4 | **iOS 캠페인 구조 제약** — source identifier·캠페인 수 상한 기준 설계 | 구조 설계가 측정 해상도를 결정하는데 다룬 글이 없다 |
| 5 | **컨버전 밸류 → LTV 연결** | 64칸 설계는 있는데 그 값을 사후에 매출로 되돌리는 방법이 없다 |
| 6 | **SKAN 스키마 변경 후 검증** — 바꾼 뒤 무엇이 정상인지 확인하는 절차 | 바꾸는 법은 있고 검증하는 법이 없다 |
| 7 | **매체별 SKAN 처리 차이** — 무엇이 표준이고 무엇이 매체 재량인가 | 매체 문서를 다 읽어야 알 수 있는 것. 한국어 문서 없음 |

**발행 리듬: 주 1~2편.** 편당 KO/EN 파일 2개 + 레지스트리 6곳(§12.24)이라 몰아 쓰면 반드시 빠뜨린다.
가드가 잡긴 하지만 리뷰가 무거워진다.

**정직성 제약**: 플랫폼 정책·수치를 말할 때는 `sources`에 공식 문서를 넣는다.
없는 출처를 만들지 않는다(`docs/aao-geo-operating-model.md`). SKAN은 버전마다 동작이 달라
"현재 기준"을 명시하지 않으면 금방 틀린 글이 된다.

### 2.4 A-3 — budget 클러스터 스니펫 수술 (작음)

평균 8.3위인데 클릭 0이면 **순위가 아니라 제목·설명 문제다.** 본문은 안 건드린다.

| slug | 현재 KO 제목 | 문제 |
|---|---|---|
| `cpi-cpa-cpm-difference` | CPI·CPA·CPM·CPC 차이: 광고 비용 지표 읽는 법 | 지표 나열형 — 검색자가 얻을 것이 안 보임 |
| `roas-improvement` | ROAS 개선 방법: 낮아졌을 때 예산보다 먼저 볼 4가지 | 상대적으로 양호 |
| `ltv-cac-ratio` | LTV:CAC 비율 계산법: 3:1 기준과 흔한 오류 3가지 | 양호 |
| `budget-scaling-limit` | 예산 증액 한계점: 언제부터 CPA가 튀기 시작하나 | 양호 |
| `performance-marketing-metrics` | 퍼포먼스 마케팅 지표: 처음 볼 4개부터 CPA·ROAS 진단까지 | 범위가 넓어 의도가 흐림 |

손댈 곳은 실질 2편(`cpi-cpa-cpm-difference`·`performance-marketing-metrics`)이다.
**`blogSeo.js`의 `KO_TITLES`/`EN_TITLES`에서 고친다** — `.md`의 title을 고쳐도 화면은 안 바뀐다(§12.24).
길이 한도는 테스트가 강제한다(KO 40자·EN 60자).

`answer`(AEO 발췌 블록)도 함께 본다. **본문이 이미 가진 숫자를 답변으로 끌어올린다** — 없는 숫자를 만들지 않는다.

### 2.5 A-4 — 도구 → 글 역링크

**이미 구현돼 있다**(`toolContentLinks.js` → `ToolEvidenceLinks` → `ToolPageOutro`).
계획에서 삭제한다. 다만 `SUPPLEMENTARY_BLOG_BY_TOOL`에 "전용 글이 없어 방법론이 겹치는 글로 연결"
이라고 주석된 도구가 7개 있다 — A-2로 SKAN 글이 늘면 그중 일부는 전용 글로 승격할 수 있다.
**A-2 발행 때마다 이 목록을 함께 본다.**

## 3. 아직 안 본 것 — 비검색 유입

여기까지 "유입"은 전부 검색이다. 실측 신호(GSC)가 거기밖에 없어서 그렇게 잡은 것이고,
**판단해서 뺀 게 아니라 안 본 것**이다. 검색은 결과가 3~6개월 뒤에 나오므로, 그동안 아무 일도
안 일어나는 위험이 있다.

후보만 적어 둔다. 어느 것도 검증하지 않았다.

- **커뮤니티 배포** — 도구 하나를 특정 질문의 답으로 소개(작성자가 직접, 스팸 아님)
- **오픈 자산 배포** — 컨버전 밸류 스키마 설계표처럼 **다운로드되는 물건**. 도구보다 공유되기 쉽다
- **템플릿 CSV의 유통** — 이미 `templateCatalog.js`가 있다. 사이트 밖으로 나갈 수 있는 형태인지 미확인
- **뉴스레터** — 계정·이메일을 만드는 순간 "모아두는 서버가 없다"는 정체성과 충돌한다. 신중히

**이건 별도 세션에서 봐야 한다.** 지금 계획에 끼워 넣으면 검증 없이 실행되는 항목이 생긴다.

## 4. 최종 순서

```
1주차   B-1a (사실 계약 + 기본값 ON)        A-1 (pillar 재지정, 반나절)
2~3주차 B-1b (IndexedDB + 90일)             A-2 시작 (주 1~2편)
        B-1c (/storage + 사생활 통제)
4주차   켜진 상태로 재방문 화면 전수 확인     A-2 계속

```

B-1c와 B-1b는 배포로 벌리지 않는다 — 원본이 디스크에 남는데 지우는 화면이 없는 배포분이
존재하면 안 된다.

## 5. 하지 않는 것

- **새 재방문 기능** — 다 있다. 켜고 나서 실제 화면을 보고 판단한다
- **새 분석 도구** — 20개에서 발견 문제를 세 번 고쳤다. 개수가 원인이라는 신호다
- **성공 계측** — 이번 범위 밖(결정 ③). 재방문율을 세려면 방문자 식별이 필요하다
- **수익화 배선** — 클릭 18/분기에 광고 최적화는 의미 없는 숫자만 만든다
- **계정·로그인·뉴스레터** — 정체성의 반대 방향
- **비검색 유입** — 별도 세션(§3)

## 6. 이 문서가 남기는 교훈 (하네스 후보)

> **"만들자"고 적기 전에 grep부터 할 것.** 재방문 장치 4개와 유입 장치 1개를
> 신규 개발로 계획했는데 전부 이미 있었다. 있는 줄 몰랐던 이유는 **기본값이 꺼져 있어
> 화면에서 한 번도 본 적이 없었기 때문**이다. 빈 상태로만 검증된 UI는 없는 UI처럼 보인다.
> §7의 "가드가 있다는 사실이 가드가 없다는 사실을 가린다"의 반대 방향 —
> **기능이 꺼져 있다는 사실이 기능이 있다는 사실을 가린다.**
