# 멀티터치와 잠식 상세 분석

승인 범위: 멀티터치는 독립 도구, 상세 구간 분석은 기존 잠식 진단의 보기로 추가한다. 기존 잠식·MMM 수학과 골든값은 유지한다.

| 위치 / 상태 | 현재와 영향 | 변경 | 보존 | 검증 |
|---|---|---|---|---|
| 신규 멀티터치 | 설치 raw의 contributor를 볼 도구 없음 | 설치 중복 제거 → 매체/캠페인 → 겹침 → 경로/시간 간격 | 원본 timestamp, 매칭 방법, 누락 정보 | 실제 AppsFlyer 헤더 골든, 업로드·필터 스모크/브라우저 |
| 잠식 진단 | 집계 시계열의 네 신호만 제공 | 기존 진단과 주간 성과 상세를 같은 경로의 보기로 연결 | 기존 엔진·CSV·게이트·결과 | 기존 스모크, ISO 주차/누락/드릴다운 골든 |

목적: 광고 중복 접촉과 유료·오가닉 반대 움직임을 관측 데이터로 좁혀 검증할 대상을 고른다. 핵심 질문은 어느 캠페인이 어떤 경로/구간에 함께 나타났는가다. 입력 파일 → 결론 → 분석 조건 → 선택한 매체·겹침·경로·시간 근거 순으로 배치한다. 주 행동은 대상 상세 선택이며 보고서 다운로드는 보조 행동이다. 사이트의 공용 셸·결론 카드·표·PNG·보고서·KR/EN을 재사용한다.

## 계산 계약

- 멀티터치: 한 앱 × AppsFlyer ID당 파일 내 가장 이른 설치 1건. 국가/기간/OS 필터보다 먼저 중복 제거한다. 클릭 귀속 설치와 클릭 contributor만 사용한다. 순서는 contributor 시간이 결정한다. 동일 채널도 원본 캠페인과 함께 남긴다. 전체 설치를 분모로 유지하고 probabilistic 제외는 contributor에만 적용한다. match type 미기록은 확인 불가로 남긴다.
- CTIT: 귀속 클릭 시각 → 설치, 선택한 전체 설치 중 timestamp 유효 건 기준. probabilistic 토글과 독립. 음수·누락 시각을 정상 CTIT에 섞지 않으며 분모·제외 건수를 표시한다.
- 터치 간격: 멀티터치 설치의 시간 유효 쌍만 분모. 음수 별도 구간, 나머지 상호 배타 구간과 합이 100%. 시간 없는 터치를 순서가 확정된 경로에 넣지 않는다.
- 지면: 입력에 af_channel이 있을 때 귀속 매체의 Meta/TikTok만 나눈다. contributor 쪽은 관측된 필드가 제공하는 채널까지 표시한다.
- 상세: 국가×OS×ISO 연도×주차로 같은 주차의 전년 대비 변화를 비교한다. ≥4주 연속 부호 반대 또는 직전 8개 연속 주의 중앙값 대비 추세 반대를 찾는다. 추세 구간의 그림/표는 시작 전 고정 기준을 공유한다. 연도 경계를 넘지 않는다.
- 주 자체가 누락되면 비교하지 않고 연속 구간을 끊는다. 채널/캠페인 누락을 0으로 간주하는 것은 사용자의 명시적 설정으로만 허용한다.
- 고객 구성 겹침은 같은 방향으로 움직인 성별/연령 그룹의 변화량 비중 중 작은 값의 합. 변화가 없는 그룹·미확인 구성은 별도로 표시하며 잠식 판정 임계값을 만들지 않는다. female_rr의 나머지를 자동으로 남성이라 부르지 않는다.

원본 설명서만 제공됐으므로 기존 스크립트와의 byte 동일 재현은 검증할 수 없다. 합성 데이터와 공개 raw 필드 계약으로 검증한다. 실사용 파일의 관측 제한과 브라우저 메모리 상한은 실제 데이터 제공 후 추가 확인 대상이다.

디자인 방향: 새 팔레트나 폰트를 만들지 않고 현재 사이트의 `--surface-container-lowest`, `--text-primary`, `--text-secondary`, `--primary`, `--text-muted`, `--border`와 글꼴·모서리 토큰을 사용한다. 매체/캠페인의 같은 설치 분모를 가까이 비교하는 것이 주 행동이며, 데이터 점검·PNG·보고서는 보조 행동이다. 선택한 보기에서 해당 근거를 바로 읽으며 새 정보 없는 재요약을 없앴다. 잠식 상세도 동일한 면·조건 정렬과 구역 이동을 사용한다.

## 구현과 검증

- 멀티터치: `5-30`, `/tools/multitouch-map`. 잠식 상세는 기존 진단의 보기(`5-18-cannibal-detail`, `/tools/cannibalization-diagnosis/detail`)이며 별도 도구 수에 산입하지 않는다. 서로 다른 CSV 저장 그룹을 사용해 기존 지출 패널을 보존한다.
- 직접 업로드는 네이티브/warehouse 헤더를 읽고 확인 후 분석한다. 같은 파일 이름·행 수로 교체해도 확인 게이트를 다시 닫는다. 예시 링크는 바로 결과를 연다. 필터·구간 선별은 같은 원본의 세션 안에서 보기 전환 후 유지되며, 원본에서 파생된 선택값을 서버나 localStorage로 보내지 않는다.
- 주차가 날짜인 열과 숫자 ISO 주차를 구분한다. 성별 코드와 OS 표기를 정규화하고, 분리된 연령 건수 열도 지원한다. 겹치는 연령 구간·부족한 구성은 추정 불가다. 숫자 오류로 일부 채널이 빠진 주의 부분 합계를 정상 전체로 비교하지 않는다.
- contributor 시각이 없거나 동률이면 순서를 확정하지 않는다. CTIT는 contributor 순서와 독립이다. 빠진 매칭 정보를 0% 제외 비율로 표현하지 않는다.
- PNG는 실제 분석 기간·국가/OS·대상·매칭 범위와 예시 여부를 남긴다. 작은 노드의 이름 공간은 흐름 두께와 분리하여 건수 비례를 보존한다. XLSX에는 원본·범위·집계·유효 시간 분모·구간 선별·계산 경계를 담는다.

검증 기준: 작업 중 추가된 `origin/main`의 주간 예산·Cost 예측 커밋 `75db4c6e`(#949)을 기존 변경과 함께 통합했다. 자동 병합에 충돌은 없었으며 주간 예산의 관측 종료 경계를 추가 확인했다. 원래 체크아웃의 로컬 2커밋과 미추적 파일은 그대로 보존했다.

|---|---|

| `npm run lint` | 오류 0 |

전체 브라우저 CI의 기존 대시보드 검사 6개는 범위 밖 기간을 적용해 데이터 부족을 기대하던 구 계약 때문에 실패했다. 현재 계약의 입력 차단·기존 결과 유지로 변경하고, CSV 내부에 실제 관측이 없는 기간은 별도 업로드 검사로 계속 보호한다. 레이아웃 검사의 흰색 면은 라이트 테마를 명시한다. CI와 같은 다크 기본값·320/768/1440 세 프로젝트에서 관련 검사 51개가 통과했다.

미확인: 회사의 실제 raw와 기존 비공개 스크립트/템플릿의 수치·화면 일치. 날짜 없는 raw, 제한된 contributor 또는 미관측 채널을 이 도구가 복원하지 않는다. Pro 브라우저 검사는 유효 이용권 응답을 모의했으며 실제 결제 승인을 검증한 것은 아니다.
