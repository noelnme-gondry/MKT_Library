# 리뷰를 사이트의 반복 업무 흐름으로 연결

기존 화면은 `.page-inner`에 대응하는 공통 여백이 없고, `.wr-card`가 상단 선만 그려 앱의 닫힌 작업 표면과 달랐다. 링크에는 기본 브라우저 색이 남았다. 업로더는 대시보드의 LTV·코호트 설명을 보여주고, 홈은 주간 리뷰를 주요 진입점에서 제외했다.

색과 폰트는 기존 체계만 사용한다: dark #121212 / #f8fafc / #adc6ff, light #f4f5f7 / #111827 / #2b6cb0에 대응하는 의미 토큰과 Wanted Sans. 공통 `.content` 여백, `--work-surface`, `--operator-line-strong`, 10px 카드 모서리, `.btn` 링크를 재사용한다. 독립된 시각 테마를 만들지 않는다.

홈: 도치로 분석 시작 | 주간 리뷰 이어가기 → 도구 찾기·계산·학습.
리뷰: 비교 데이터 준비 → 근거 확인·결정 저장 → 다음 검토일·재업로드 → 지난 결정 확인.

실제 관측이 없는 CPA는 —, 유효한 비용 0/양수 전환은 CPA 0으로 구분한다. 유지 목표의 제한은 입력 시 알리고 가드레일 근거는 별도로 남긴다. KR/EN 동일하게 검증한다.

화면 대조에서 두 가지를 추가 확인했다. 제목의 `__eyebrow` 이름이 전역 작은 글씨 선택자에 잡혀 18px 선언을 덮었고, KPI·분해 표에는 공통 `data` 클래스가 없었다. 제목 이름을 바로잡고 세 표 모두 공통 테이블 표면으로 맞췄다. 결과 화면은 결론을 먼저, 반복 검토 안내는 결정 기록 뒤에 둔다.

검증: Playwright 전체 99개 및 테이블 반영 후 주간 리뷰 8개가 통과했다. KO 320/768/1440과 EN 라이트에서 axe·업로드·결정·프로젝트 복원·보고서·다운로드·이력 연결을 확인했다. iOS Safari와 Android 실기기, 실제 재방문·결제 전환 효과는 미실측이다.
