# 유입·활성화·반복 사용 측정

2026-09-12 구현 기준. 현재 GA4 원시 데이터·유입량·코호트 리텐션은 미확인이다. 아래는 측정 정의이며 개선 효과나 목표 상승률을 산출한 결과가 아니다.

| 판단할 것 | 기존 이벤트와 조건 | 해석 |
|---|---|---|
| 콘텐츠에서 실제 분석으로 연결되는가 | `blog_cta_viewed` → `blog_tool_cta_clicked` → `analysis_completed`, `source=csv`, `result_state=ready` | 같은 세션·콘텐츠 귀속 범위 내 사용자 기준. CTA 클릭 수를 활성 사용자 수로 쓰지 않는다. |
| 첫 결과까지 도달하는가 | `data_import_start` → `mapping_confirmed` 또는 `dochi_mapping_confirmed` → `analysis_result_viewed`, `source=csv` | 계산 성공과 화면을 실제로 본 행동을 구분한다. 업로드 차단·매핑 이탈도 함께 본다. |
| 샘플이 실파일 사용으로 이어지는가 | `example_run_started` 이후 별도 `source=csv` 결과 조회 | 샘플 결과 `source=demo`는 활성화 분자에서 제외한다. 샘플만 본 방문과 구분한다. |
| 리뷰를 만들고 팀에 활용하는가 | `weekly_review_result_viewed` → `weekly_review_export`, `download_type=clipboard`, `state=completed` | `placement=verdict_summary`는 요약, `full_report`는 전체 복사다. 실제 Slack·Notion 전송/열람을 뜻하지 않는다. |
| 다음 행동을 기록하는가 | `weekly_decision_saved`, `source=csv` | 저장 성공만 집계한다. 저장 버튼 클릭이나 저장 창 노출은 제외한다. |
| 다시 데이터를 가져오는가 | 최초 실데이터 결과 조회 사용자가 다른 날짜에 `data_import_start` 후 실데이터 결과 조회 | 주간 제품이므로 최초 활성화 기준 D7 한 날짜와 7~13일 재사용을 별도로 본다. 업로드만 한 방문은 핵심 재사용과 구분한다. |
| 지난 결정을 실제로 검토하는가 | `decision_review_completed` | `weekly_review_completed`는 **계산 준비 완료**다. 사람이 지난 결정을 검토한 완료율에 사용하지 않는다. |

집계는 사용자·세션·코호트 기준을 고정하고 KO/EN, 최초 유입 콘텐츠, 모바일/데스크톱을 나눈다. 채널·화면 구성이 다른 모집단을 합쳐 효과로 해석하지 않는다. `with_history`는 저장 이력 보유 상태이며 재방문을 증명하는 값이 아니다. 브라우저 저장 삭제와 기기 변경은 동일 사용자 연결을 제한한다.

`elapsed_bucket`은 기존 계측의 구간값이다. 첫 도구 진입/매핑 확인부터 성공까지의 구간을 표시하므로 정확한 초 단위 평균·중앙값으로 환산하지 않는다. 별도의 사용자 내용·파일명·CSV 행·실제 성과 숫자를 GA4에 보내지 않는다. 요약 텍스트는 사용자가 누른 클립보드 복사에만 쓰인다.

출시 전 디버그 검증에서 샘플과 실파일의 `source`, 결과 조회의 가시성, 복사 성공/실패, 저장 성공, 실제 결정 검토를 각각 확인한다. localhost 검증은 운영 GA 태그를 주입하지 않으며 운영 내부 테스트는 GA4 내부/개발자 트래픽 필터로 제외한다. 필터의 운영 적용 상태는 미확인이다.

출시 후에는 변경 전후 같은 요일 구성의 완결된 코호트를 비교한다. 주간 재사용은 7~13일 관찰창을 모두 지난 사용자만 분모에 포함한다. 표본이 부족하면 개선 여부는 보류하고 업로드·매핑·결과 조회 중 어디에서 멈추는지부터 확인한다. 세션 길이 증가는 성공 지표로 삼지 않는다. 결과를 더 빨리 이해하고 반복 의사결정에 사용하는지가 목표다.
