# 이용권 분실·재발급 운영 절차

자동 갱신과 무관한 기존 1개월 이용권의 분실 대응이다. 운영자 전용 절차이며 공개 재발급 API는 없다.

1. 원래 브라우저에 유효한 쿠키가 있으면 구독 페이지에서 코드를 다시 다운로드한다.
2. 모두 분실한 고객에게 주문번호(있는 경우), 결제 날짜·금액, 영수증 확인 정보를 받는다. CSV·분석 결과·복원 코드·카드 전체 번호·비밀번호는 받지 않는다.
3. 주문번호·날짜·금액만으로 소유권을 확정하지 않는다. Toss 관리자 화면에서 영수증과 거래를 대조하고, 구매자가 결제 당시 사용한 연락 채널의 소유권 등을 독립적으로 확인한다. 주문에 검증 가능한 연락 정보가 없다면 그러한 경로가 있다고 가정하지 말고 결제사를 통한 구매자 확인 등 별도 검증을 진행한다. 증빙이 부족하면 재발급하지 않는다. 타인이 전달한 영수증 이미지 하나만으로 승인하지 않는다.
4. 지원 기록에 확인 방법, 주문번호, 담당자, 날짜, 케이스 ID를 기록한다. 증빙은 불필요하게 복사·보관하지 않는다.
5. 확인된 운영자가 앱의 결제 환경변수를 사용할 수 있는 신뢰된 환경에서 다음 명령을 실행한다. 연결 문자열·키를 명령줄 인수나 채팅으로 전달하지 않는다.

```sh
cd v2-migration
node scripts/reissue-payment-pass.mjs --order gop_UUID --verified-case CASE_ID --output /private/new-code.txt
```

명령은 현재 결제 상태를 Toss에 재조회하고 유효한 미취소 주문만 처리한다. 기존 만료일·금액은 바꾸지 않는다. 새 코드는 권한 0600의 새 파일에만 기록하며 stdout이나 지원 로그에는 기록하지 않는다. 기존 파일은 덮어쓰지 않는다. DB 갱신은 이전 해시와 일치할 때만 수행해 동시 환불·교체와 충돌 시 실패한다.

6. 확인한 구매자 채널로만 새 코드를 전달하고, 수령 확인 뒤 임시 파일을 삭제한다. 고객에게 구독 페이지의 복원 입력란을 안내한다. 프로젝트 데이터는 별도 백업으로만 복원된다.
7. 이전 코드는 이후 서버 검증부터 거부된다. 이미 내려간 오프라인 이용권 캐시는 최대 72시간 유지될 수 있으므로 즉시 모든 기기에서 차단된다고 안내하지 않는다.

네트워크 결과가 불명확하면 재실행 전에 DB의 변경 여부와 새 코드 파일을 확인한다. 파일을 잃었다고 곧바로 중복 재발급하지 않는다. 재발급 도구와 절차는 구현·테스트되었으며 실제 운영 주문에 실행한 것은 아니다.
