# 마케팅 반응 분석의 미래예측 모델

작성일: 2026-07-30
대상: `5-18 마케팅 반응 분석 → 예측 전용 회귀 · 미래 예측`
구현 기준: `v2-migration/src/components/tools/MarketingResponse.jsx`, `src/utils/annualAnalogForecast.js`, `src/utils/attributedForecastLiveMath.js`

## 1. 한 문장 요약

이 도구는 하나의 고정 회귀식을 모든 CSV에 적용하지 않는다. 업로드한 데이터에 **Spend가 있는지**, **Paid 성과가 분리돼 있는지**, **Android+iOS가 Total을 완전히 구성하는지**, **과거 구간과 현재 구간의 예측력이 어떤지**를 먼저 판정하고, 시간 순서가 보존된 nested rolling OOS에서 경쟁한 후보 중 하나만 미래 예측에 사용한다.

목표는 과거 적합도(R²)가 높은 선을 만드는 것이 아니라, **아직 보지 않은 미래 구간에서 같은 규칙으로 성과를 맞힐 수 있는 모델을 고르는 것**이다.

## 2. 이 문서에서 말하는 예측의 범위

- 단위: 주간 성과와 주간 Cost를 사용하는 브라우저 내 예측이다.
- 목표값: 가입, 유입, 재활성, 구매자, 매출 등 매핑된 하나의 KPI다.
- 미래 Cost: 사용자가 입력한 비용을 조건으로 하는 예측이다. Cost 자체를 예측하는 모델의 정확도를 주장하는 기능은 아니다.
- 데이터 처리: CSV는 브라우저 메모리 안에서만 처리한다. 서버로 전송하거나 저장하지 않는다.
- 해석: Cost와 성과의 **관측상 연관**을 이용한 예측이다. 증분 효과·인과효과의 증명은 아니다.

## 3. 먼저 선택하는 경로

도구는 아래 순서로 데이터 구조를 판별한다. 서로 다른 경로의 결과를 같은 숫자로 포장하지 않는다.

| 입력 구조 | 선택 가능한 예측 경로 | 출력 의미 |
| --- | --- | --- |
| long 형식이고 Organic/Paid 행이 명시됨 | 귀속형 Organic+Paid 자동 선택 | Organic 수준과 Cost 조건부 Paid 수준을 따로 예측한 뒤 합산 |
| Android+iOS가 있고 `PaidRegs`가 있음 | OS별 Paid·Organic 분리 회귀 | `Total = Organic 기저 + Spend 연관 halo + Paid 예측 수준` |
| Spend는 있으나 Paid 성과가 없음 | Cost 회귀: Direct Total 대 Android+iOS 합산 경쟁 | Total KPI의 Cost 조건부 예측 |
| Spend 이력이 없음 | Organic 추세·계절성 자동 탐색 | Cost 효과를 주장하지 않는 성과 수준 예측 |
| Cost 회귀를 안정적으로 만들 수 없음 | 수준 예측 자동 탐색을 **참고값**으로 사용 | Cost 시나리오는 열지 않음 |

플랫폼 열에 Total 행과 Android/iOS 행이 섞여 있으면 같은 성과를 두 번 더할 위험이 있다. 이 경우 모델은 임의로 합치지 않고 분석을 멈춘다. Web 등 다른 플랫폼이 있으면 Android+iOS 부분합을 전체 Total이라고 표시하지 않으며, Direct Total만 운영 경로가 될 수 있다.

## 4. Paid·Organic 분해의 정의

Paid 실적이 제공되는 가입 데이터에서는 OS별로 다음 항등식을 사용한다.

```text
Organic 실측 = Total 실측 − PaidRegs 실측
Total 예측 = Organic 기저 + Spend 연관 halo + Paid 예측 수준
```

- **Organic 기저**: Performance Spend를 0으로 둔 Organic 예측이다. Branding 채널이 매핑돼 있으면 그 효과는 기저에 남을 수 있다.
- **Spend 연관 halo**: 같은 Spend가 Organic 결과와 함께 움직인다고 회귀가 추정한 변화다. 인과적 organic uplift라고 단정하지 않는다.
- **Paid 예측 수준**: PaidRegs에 적합한 Cost 조건부 예측값이다. 회귀 절편이나 비매체 성분을 포함할 수 있으므로, “Paid 직접반응”과 동일어가 아니다.
- **합산**: Organic과 Paid는 서로 다른 실측 성분에 각각 적합하므로 중복 합산하지 않는다.

Paid가 누락됐거나 0~Total 범위를 벗어나면 이 분해를 만들지 않는다. 그때는 일반 Total 경로 또는 “분리 불가” 상태를 명확히 표시한다.

## 5. 후보 모델군

### 5.1 Spend가 없는 Organic 수준 예측

Spend가 없을 때에는 광고 회귀를 억지로 넣지 않는다. 아래의 bounded time-series 후보를 경쟁시킨다.

| 후보군 | 하는 일 |
| --- | --- |
| 최근 수준(Flat) | 최근 N주의 평균 수준을 유지 |
| 감쇠 추세(Local trend) | 최근 변화 방향을 보되, 미래로 갈수록 기울기를 감쇠 |
| 감쇠 Holt | 수준과 추세를 함께 갱신하는 짧은 시계열 예측 |
| 유사 시즌(Similar season) | 최근 상태와 비슷했던 과거 계절 구간을 이웃으로 사용 |
| 연간 아날로그 | 전년 동주 수준에 최근 기준점의 비율을 반영 |

이는 “연간 반복형을 기본으로 고정”한 것이 아니다. 연간 아날로그도 다른 후보 중 하나일 뿐이며, 충분한 이력과 더 나은 rolling OOS가 있을 때만 선택된다.

### 5.2 Spend가 있는 Paid 반응 예측

Paid 성과가 있으면 다음 Paid 후보를 자동 비교한다.

| 후보군 | 비용 처리 |
| --- | --- |
| Rate | 최근 Paid/Cost 비율을 사용하며, 오래된 관측치의 비중은 감쇠 가능 |
| Ridge 반응 | 채널별 또는 총 Cost의 raw/sqrt/log 변환을 ridge 회귀로 적합 |
| Adstock/포화 반응 | 후보 경로에 따라 Spend의 잔향과 비선형 포화를 반영 |

MMM 조건부 회귀 경로에서는 채널별 Spend에 대해 identity, `log1p`, Hill 포화와 adstock 후보를 비교하고, 정규화된 회귀계수·계절성·추세·구조변화 변수를 함께 적합한다. 변환 정책은 rolling 선택 때의 후보군과 최종 전체 이력 재적합 때 동일하게 유지한다.

### 5.3 Paid·Organic 하이브리드

Paid 성과가 명시된 Android/iOS 가입 데이터에서는 다음 두 계열을 공통 outer fold에서 경쟁시킨다.

1. Total 수준 예측 후보
2. Organic 수준 + Paid Cost 반응을 합친 후보

하이브리드는 Organic·Paid·Total 각각의 내부 후보를 먼저 고르고, 그 조합 비중도 `0%, 25%, 50%, 75%, 100%`에서 nested 방식으로 선택한다. 따라서 최종 하이브리드가 선택됐다고 해서 모든 CSV에 Paid·Organic 분해가 강제되는 것은 아니다.

## 6. 학습 기간도 후보이다

모델은 긴 이력을 무조건 더 좋다고 보지 않는다. 기본 후보 내부에는 최대 208주 범위의 여러 최근 학습창이 있으며, 별도 “현재 운영 기간 후보 찾기”를 요청하면 전체 이력과 208/156/130/104/91주 등의 최근 구간을 다시 비교한다.

더 짧은 기간은 다음을 모두 만족할 때만 **제안**한다.

```text
전체 이력의 개발 OOS wMAPE > 10%
짧은 기간의 개발 OOS wMAPE가 전체 이력보다 상대 20% 이상 개선
그리고 절대 3%p 이상 개선
```

추천이 나오더라도 자동 적용하지 않는다. 사용자가 추천된 기간을 수락해야 그 기간으로 재적합한다. 이 규칙은 오래된 운영 체계·측정 방식·CPA 구조가 현재 레짐을 흐릴 수 있다는 문제를 다루되, 과거 데이터를 임의로 버리지 않기 위한 장치다.

## 7. 검증: 선택과 채점을 분리하는 방법

### 7.1 Actual-Cost conditional OOS

각 검증 cutoff에서 다음 순서를 지킨다.

1. cutoff 뒤 H주 성과값을 숨긴다.
2. cutoff 이전 데이터만으로 후보를 적합한다.
3. 숨긴 H주의 **실제 Cost**와 그 시점에 이미 알려진 event/step 상태를 넣는다.
4. 예측과 실제 성과를 비교한다.

따라서 검증은 “미래 Cost까지 맞혔는가”가 아니라 “당시 실제로 집행된 Cost가 주어졌을 때 성과를 예측했는가”를 평가한다.

### 7.2 Nested rolling origin

마지막 H주는 최신 봉인 감사 구간이다. 이 구간의 KPI 정답은 후보·경로·학습창 선택에 쓰지 않는다.

각 outer cutoff에서는 그보다 더 오래된 독립 origin들만 사용해 다음을 다시 선택한다.

- Direct Total 또는 Android+iOS 합산 경로
- 학습 기간
- Organic/ Paid/Cost 후보 사양
- Cost 변환과 감쇠/정규화 정도
- event/step 처리 정책
- 하이브리드 결합 비중

그 뒤 선택된 사양으로 outer holdout을 예측한다. 개발 OOS는 이 outer fold들을 합쳐 계산하고, 최신 봉인 H주는 별도 감사로 표시한다. 최신 12주가 잘 맞았다는 이유만으로 모델을 다시 고르지 않는다.

### 7.3 공식 지표

주요 지표는 pooled wMAPE다.

```text
wMAPE = Σ |실제 − 예측| / Σ |실제| × 100
```

이 지표는 주별 단순 평균 MAPE보다 큰 주의 성과량을 제대로 반영한다. 함께 제공하는 값은 다음과 같다.

- 최신 봉인 구간 wMAPE, RMSE, MAE
- 전체 개발 rolling OOS wMAPE
- 개발 구간의 최악 fold wMAPE
- 최근 평균(persistence) 기준선 대비 승률과 최신 구간 비교
- Android/iOS 각 성분의 wMAPE (OS 합산 경로일 때)
- 잔차 ACF, drift, 분산 변화 진단

R²는 과거 적합의 보조 정보일 뿐, 인증이나 예산 변경 판단의 기준이 아니다. 높은 R²와 낮은 OOS wMAPE는 서로 보장하지 않는다.

## 8. 예측 인증과 Cost 시나리오 게이트

`통과`는 단순히 wMAPE 한 값이 낮다는 뜻이 아니다. 기본적으로 다음을 확인한다.

| 확인 항목 | 이유 |
| --- | --- |
| 최소 3개 이상의 개발 outer fold | 한 구간 우연을 피함 |
| 개발 pooled wMAPE < 10% | 평균적인 외부 예측 오차 확인 |
| 개발 최악 fold wMAPE < 10% | 특정 운영 구간 붕괴 방지 |
| 기준선 승률 50% 이상 | 단순 최근 평균보다 일관되게 나쁜 모델 차단 |
| 최신 봉인 H주 wMAPE < 10% | 가장 최근 운영 상태 감사 |
| 최신 구간이 persistence보다 나쁘지 않음 | 복잡 모델이 단순 기준선보다 못한 경우 차단 |
| OS 분해 시 Android/iOS 각각 통과 | Total에서 두 OS 오차가 상쇄되는 문제 차단 |

Cost 입력에 따른 OFF/증액/감액 시나리오는 추가로 채널별 독립 Cost 변동과 모델 사용 비중이 확인될 때만 열린다. 아래 상태에서는 기본 예측을 볼 수 있어도 예산 시나리오는 잠긴다.

- 모든 예측 주차에서 단순 기준선이 선택됨
- 최근 Cost가 함께 움직여 채널별 반응을 분리할 수 없음
- Cost 변동 자체가 너무 적음
- 최신 봉인 감사나 하위 성분이 인증 기준을 넘음
- Spend 없는 Organic 수준 예측만 가능한 경우

잠금은 “효과가 0”이라는 뜻이 아니다. 현재 CSV로 예산 변경의 영향을 정직하게 구분할 근거가 부족하다는 뜻이다.

## 9. 불확실성 범위

충분한 독립 outer OOS가 8개 이상일 때, 각 예측 주차별로 과거 절대오차의 P90을 구해 점 예측의 최소 참고폭으로 사용한다.

```text
lower = max(0, point forecast − horizon별 P90 절대오차)
upper = point forecast + horizon별 P90 절대오차
```

이는 예측오차의 경험적 참고 범위이지, “90% 포함 보장”이나 인과효과의 신뢰구간이 아니다. outer OOS가 8회보다 적으면 범위를 과장하지 않고 점 예측만 표시한다.

## 10. 살아있는 CSV 내보내기

예측 모델을 정확히 수식으로 표현할 수 있는 경우, CSV에는 Android/iOS별로 다음이 들어간다.

1. 미래 Cost 입력 표
2. 계수·평균·스케일·adstock·Hill 파라미터
3. 과거와 미래의 feature/adstock/변환 audit 열
4. Organic 기저·halo·Paid 예측 수준·OS 합계·전체 Total
5. lower/upper 참고 범위

사용자는 **OS별 미래 Cost 입력 표만 수정**하면 된다. 수정한 Cost는 같은 OS의 Organic halo와 Paid 수준 모델에 함께 들어가며, OS Total과 Android+iOS Total까지 Excel/Sheets 수식으로 연쇄 계산된다.

수식은 모델이 학습한 Spend 관측 범위 안으로 effective spend를 제한한다. 이는 관측하지 않은 극단의 예산을 근거 없이 외삽하는 것을 줄이기 위한 장치다.

다만 다음은 반드시 구분해야 한다.

- 수식으로 정확히 재현할 수 없는 Meridian/reach-frequency 계열은 살아있는 수식 대신 snapshot CSV로 내보낸다.
- Cost 수정 뒤 lower/upper는 다운로드 당시의 비대칭 오차폭을 유지한 참고 범위다. 새 Cost 시나리오로 다시 OOS 검증한 구간은 아니다.
- 사용자 CSV의 텍스트가 Excel 수식으로 실행되지 않도록 CSV 내보내기에서 안전하게 이스케이프한다.

## 11. 화면을 읽는 순서

1. **결론 카드**: 통과/보류와 예산 시나리오 가능 여부를 먼저 본다.
2. **선택 학습 기간·모델 사양**: 어떤 후보가 왜 선택됐는지 확인한다.
3. **개발 OOS와 최신 봉인 감사**: 서로 다른 숫자가 섞이지 않았는지 확인한다.
4. **Android/iOS 성분 검증**: 합계가 좋아 보여도 한 OS가 무너졌는지 확인한다.
5. **잔차 진단**: ACF·drift·분산 변화가 크면 다음 실험/홀드아웃을 우선한다.
6. **시나리오 표**: 게이트가 열린 경우에만 예산 변경의 조건부 예측으로 사용한다.

## 12. 이 모델이 하지 않는 것

- 모든 CSV에서 10% wMAPE를 만들겠다고 약속하지 않는다.
- 과거 R²가 높다는 이유만으로 미래 예측 또는 예산 변경을 승인하지 않는다.
- 관측 회귀계수를 인과적 증분 효과로 바꾸지 않는다.
- Paid/Organic이 실제로 분리돼 있지 않은 데이터에서 분해 결과를 지어내지 않는다.
- Android+iOS 외 플랫폼이 있는 데이터를 OS 합계만으로 Total이라고 표시하지 않는다.
- 최신 감사 구간의 정답을 후보 선택에 다시 사용하지 않는다.
- Cost가 없는 데이터에 광고 회귀를 억지로 적용하지 않는다.

## 13. 재현을 위해 남기는 정보

화면과 CSV에는 최소한 아래의 provenance를 남긴다.

- 선택 route, model spec, 학습 기간, horizon
- 선택용 fold 수와 fold 간격
- 개발 OOS/최신 봉인 OOS/기준선 비교값
- 모델별 후보 탐색 상태와 선택 사유
- event 정책, trend damping, interval 산출 방식
- Cost 시나리오 게이트의 상태와 잠금 사유

이 정보가 없으면 “wMAPE가 낮다”는 숫자를 재현하거나 다른 CSV에서 같은 판단을 검토할 수 없다. 이 도구의 결과는 예측값만이 아니라, 그 예측을 사용해도 되는지 판단할 근거까지 함께 제공하는 것을 목표로 한다.
