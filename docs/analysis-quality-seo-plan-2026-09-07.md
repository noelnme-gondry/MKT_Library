## 1. 이번에 구현한 범위

전면 감사의 상위 10개를 수정했다. 통계 엔진·골든값·서버 전송 정책·저장 기본값은 변경하지 않았다. 후속 분석 기능과 블로그 개편은 아래 제안 단계이며 이번에 구현한 것으로 세지 않는다.

범위 주의: 최소 행·기간 계약은 통일했지만, 추천 프로파일과 직접 도구의 모든 품질 진단이 동일해졌다는 뜻은 아니다. 엔티티별 관측·변동·실제 유효 지표 검증을 실행 직전까지 공통화하는 작업은 아래 품질 개선으로 남긴다. iOS/Android 실기기·Lighthouse·실제 검색 성과는 미실측이다. 수정은 로컬이며 커밋·push·배포하지 않았다.

## 2. 분석 품질: 도구 확대보다 판단 근거의 일관성이 먼저

공개 20개 도구를 아래 8묶음으로 모두 포함했다. 아키텍처·직접 열어 본 모듈을 기준으로 한 우선순위 제안이며, 모든 수학 엔진을 새 참조값으로 전수 검증한 결과는 아니다. 아래 노력은 KR/EN UI와 의미 있는 검증을 포함한 예상치다.

| ASA·ASO (5-26/5-27) | 운영 규칙 기반 CPT/Exact 후보, 퍼널·믹스/효율 분해 | ASA의 적은 탭/설치·최근 미성숙 전환을 별도 상태로 분리. ASO는 소스 구성 변동과 실험 효과를 구분 | 기존 도구 안에 품질·실험 안내, 2~4일 | 낮은 관측에서 기계적인 승격/제외를 확정하지 않음, 스토어 실험과 관측 전후 분석이 구분됨 |
| Aha·액션 생존 (5-20/5-28) | 행동 후보, KM·중도절단·RMST | 행동 관측창과 전환 평가창의 분리, 시간 누수 확인, 코호트 성숙도와 at-risk 표를 결론 가까이 표시 | 기존 입력·근거 개선, 3~5일 | 전환 이후 행동을 원인 후보로 사용하지 않음, 성숙 코호트와 미성숙 코호트 혼동 방지 |

우선순위는 공통 품질 계약 → 포화도/예산 추천의 안정성 → 실험 설계 점검 → MMM 결과 건강도 순이다. 순수 수학 변경은 이 제안의 후속 별도 작업이며, 독립 참조값과 합성 데이터 검증을 먼저 설계해야 한다.

Meridian 공식 건강도 문서는 적합도만으로 충분하지 않으며 여러 진단을 함께 보도록 안내한다. 여기서는 이 원칙을 참고하되 Meridian 전용 posterior·MCMC 기준을 현재 엔진에 그대로 복사하지 않는다. 출처: https://developers.google.com/meridian/docs/post-modeling/health-checks

## 3. 추가 분석 도구·라이브러리 도입 판단

새 독립 페이지를 늘리기 전에 현재 입력으로 할 수 있는 보조 분석을 기존 도구에 넣는 편이 낫다. 서버 업로드형 분석 서비스 도입은 제안하지 않는다.

| 후보 | 판단 | 이유·필수 입력 | 검증·보류 조건 |
|---|---|---|---|
| 공통 데이터 품질/실행 전 점검 | 최우선 도입, 독립 도구보다 공용 패널 | 행·기간·유효 분모·중복·엔티티 커버리지·단위 계약을 추천과 상세 실행에서 공유 | 실제 플랫폼 헤더·잘못된 CSV·경계 표본을 한 입력으로 양쪽 진입에서 검사 |

## 4. 블로그·SEO 개선: 기존 47쌍을 먼저 강화

실측 인벤토리: 발행 원고 KO 47편, EN 47편. 원고 frontmatter에 reviewer+reviewedAt이 명시된 것은 각 5편, sources 명시는 각 10편, answer 명시는 각 2편이다. 이것이 나머지 글에 답변·출처가 없다는 뜻은 아니다. blogEditorial의 답변 폴백과 blog.js의 본문 HTTPS 출처 수집이 있으며, 검토일은 없는 값을 만들어 노출하지 않는다.

직접 읽은 구체 사례: content/blog-en/aso-basics-guide.md FAQ는 전환율 30%→40%의 설치 증가율 약 33%와 CPI 감소율을 같은 비율로 설명한다. 본문은 CPI 25% 감소로 정확히 설명한다. 동일 광고비·동일 페이지 조회수라는 조건에서 1 - 0.3/0.4 = 25%가 맞다. 이 원고는 이번 10개 수정 범위 밖의 후속 편집 항목이다. KR/EN 둘을 함께 재검토해야 한다.

| 2 | 검토 책임·출처 보강 | 우선 ASO/ASA·SKAN·매체 규격 등 바뀌는 사실을 공식 문서로 재검토하고 실제 날짜/검토자만 기록 | 우선 5쌍 2~3일 | 직접 인용한 출처가 해당 주장·플랫폼 버전을 뒷받침 |

| 4 | 검색 의도별 연결 정리 | 정의(용어사전)·판단 기준(블로그)·실행(도구)·입력(템플릿) 간 양방향 링크 | 1~2일 | sitemap뿐 아니라 렌더된 본문에서 들어오고 나가는 링크 존재 |
| 5 | 첫 화면의 다음 행동 개선 | 현재 ASO 글처럼 직접 답 뒤 관련 도구 CTA. 용어사전 CPA는 첫 도구 링크가 첫 화면 아래인 문제를 표본 확장 | 1~2일 | 320/768/1440, KR/EN에서 답변을 가리지 않고 관련 도구가 보임 |
| 6 | 검색 성과와 과업 완료 연결 | 기존 blog_read_depth·blog_cta_viewed·blog_tool_cta_clicked를 활용한 퍼널 정의, 업로드/결과 도달과 비교 | 계측 점검 1~2일 + 관찰 4주 | 노출·클릭뿐 아니라 글→도구→업로드→결과 비율을 언어/글별로 비교 |

계측 시 CSV 원본·파일명·셀 값·행 텍스트·사용자 입력 쿼리를 외부로 보내지 않는다. 기존 동의 및 호스트 가드를 유지한다. 실제 Search Console/GA 데이터는 이번에 접근하지 않았으므로 트래픽 손실 규모·증가율·우선 검색어 수요는 미실측이다. 콘텐츠 우선순위는 현재 제품 연결성과 발견된 오류 기준의 제안이다.

새 글은 기존 소재 중복과 검색 의도를 먼저 비교한 뒤 결정한다. 후보는 “데이터가 부족해 분석이 보류될 때 채워야 할 것”, “포화도와 예산 배분 결과가 다를 때”, “ASO 전환율과 소스 믹스를 구분하는 실제 CSV”, “MMM이 계산되어도 예산 결정에 쓰면 안 되는 경우”다. 각 후보는 독립 새 글보다 관련 기존 글의 사례 확장이 충분한지 먼저 판단한다.

## 5. 최신 SEO 기준에 따른 투자 조정

- Google의 2026-05-15 가이드는 독자에게 고유한 경험·사례·유용성을 주는 콘텐츠와 명확한 기술 구조를 강조한다. 키워드 변형마다 별도 페이지를 대량 생성하지 않는다. https://developers.google.com/search/docs/fundamentals/ai-optimization-guide
- 같은 가이드는 llms.txt가 Google Search의 노출·순위에 긍정적 또는 부정적 영향을 주지 않는다고 명시한다. 현재 파일의 사실 정합은 유지하되 이것을 검색 성장 프로젝트의 중심에 두지 않는다.
- Google은 2026-05-07부터 FAQ 리치 결과를 종료했고 6월에 문서를 제거했다. FAQ는 사용자의 실제 질문에 답하는 콘텐츠로 유지하며, FAQPage를 추가하는 일을 검색 노출 확대 성과로 계산하지 않는다. https://developers.google.com/search/updates#may-2026
- canonical·hreflang·내부 링크·본문/메타 정합과 페이지 경험은 계속 관리한다. 검색/AI 노출·순위 향상은 보장하지 않는다.

## 6. 권장 실행 순서

1. 이번 수정 배포 후 업로드→결과 흐름과 저장 안내를 운영에서 확인.
2. 공통 실행 전 품질 계약과 기존 결과의 신뢰도 배선 정리. 같은 기간/분모에서 도구 간 모순을 먼저 줄임.
3. ASO 원고의 수치 오류 정정과 우선 5쌍의 출처·검토 갱신. 새 글 대량 작성은 뒤로 미룸.
4. 합성 CSV로 재현 가능한 사례 3쌍을 만들고 기존 글→도구 전환 계측을 검증.
5. 필요한 원본 필드가 확보되는 도구에 한해 SRM·전환 성숙도 같은 보조 진단을 추가. 신규 독립 도구는 이후 결정.

합격 기준은 기능 수가 아니라 잘못된 확정 결론 감소, 도구 간 근거 일치, CSV→결과 완료율, 재현 가능한 사례, 검색 유입의 실제 분석 도달이다.
