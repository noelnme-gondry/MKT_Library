# 운영 플래너 구현 검토

첫 요청의 대시보드 탭 검토 기록은 아래에 보존한다. 후속 요청으로 해당 탭은 제거했으며, 최종 구현 범위와 검증은 마지막 독립 도구 항목을 따른다.

사용자 요청: 승인한 통합 운영 시안의 흐름을 기존 홈페이지의 느낌과 조작 방식으로 구현한다.
대상: `/dashboard` · `/en/dashboard`, 기존 도구 ID `5-2`의 운영 계획 보기.

| 위치 / 상태 | 기존 상태와 사용자 영향 | 변경 | 보존할 정보·행동 | 확인 |
|---|---|---|---|---|
| 대시보드 결과 | 최근 실적·예산·성과 변동·소재가 다른 도구에 나뉨 | 공용 셸 안에 운영 계획 탭 추가 | 기본 시각화 진입, 모든 기존 상세 탭·업로드 게이트 | 실제 CSV 업로드와 탭 진입 스모크·브라우저 검사 |
| 예산 조정 | 실적과 예측을 혼동할 수 있음 | 같은 하루 예산의 유지안/조정안 예측 비교, 관측 단가 별도 열 | 기존 적합·최근 구간·한계효용 배분 엔진, 변경 한도, 안전 범위 | 합계 보존·한도·0% 유지·미래 이력 제외 계산 검사 |
| 기간 / 필터 | 차트 기간과 비교 기간이 동시에 보일 수 있음 | 운영 계획은 독립 분석/비교 기간 편집만 노출 | 국가·플랫폼·채널·지표·원본 통화 공용 상태 | 한·영 기간 적용, 결과 무효화와 재계산, 필터 스모크 |
| 캠페인 / 소재 | 같은 소재 ID 또는 캠페인 이름이 합쳐질 위험 | 국가·플랫폼·채널·유입·캠페인 식별자를 포함한 묶음 | 가중 단가, PVM 항등식, 단계별 기여, 전체 목록 진입 | 식별자 충돌·첫 관측·산술 분해 검사 |
| 데이터 부족 | 일부 대상을 빼고 전체 개선으로 오해할 위험 | 전체 예산 예측 보류와 대상/사유 표시 | 확인 가능한 실적과 소재 목록 | 일별 공백·주간 집계·결측·성과 0·국가 혼합·낮은 적합도 검사 |

목적 → 핵심 질문 → 근거 → 행동 → 배치 이유:

- 최근 단가가 오른 대상부터 확인한다. 기간·최근 단가·비교 가능한 대상 수를 결론 카드에서 읽는다.
- 같은 예산을 옮길 후보를 고른다. 기존 모형의 유지안/조정안 예측과 대상별 관측 단가를 함께 보고 변경 한도를 정한다. 예산 총액·모형의 자세한 조건은 기존 예산 도구로 이어진다.
- 선택한 캠페인의 단가 변화를 확인한다. 소재 구성/소재 내 효율과 단계별 기여를 기존 그림으로 보여 준다. 원인이라고 확정하지 않는다.
- 새로 관측된 소재를 살핀다. 첫 관측일·관측일 수·비용·성과·단가·같은 캠페인의 기존 소재 대비를 표에서 비교한다. 첫 관측은 실제 생성일이 아니다.
- 사용자가 선택한 변경만 기존 결정 기록 흐름으로 남긴다. 원본은 브라우저 안에서 처리한다. 광고 계정 실행 연결은 없다.

시각 검토: 1440px KO 라이트, 980px EN 라이트, 320px KO 다크. 실제 가상 CSV 업로드 결과로 숫자 끝선·한글/영문 줄바꿈·흰색 분석 면·모바일 표 가로 스크롤·변경 한도·기간 조작·캠페인 선택을 확인했다. 기존 공용 그림을 재사용하며 별도 색/폰트/라우트를 만들지 않았다. 설치 기준 예산 그림의 지표 연결 오류(CPA 표기)를 발견해 원래 지표 키를 넘기도록 수정하고 회귀 단언을 추가했다.

검증: `npm run test:all` 5,130개 통과·기존 4개 건너뜀, `npm run lint` 통과, `npm run build` 통과; 신규 브라우저 6건 통과(위 폭·언어·테마에서 정상/공백 상태), 해당 탭 패널·탭의 WCAG 2 A/AA 위반 0건. 최초 빌드의 외부 node_modules 심볼릭 링크 문제는 의존성을 작업 공간 안에 복제해 해결했다. 개발 서버와 빌드 산출물을 함께 쓰던 첫 브라우저 실행은 검증 근거로 사용하지 않고 빌드된 앱에서 다시 확인했다.

한계: 예상치는 인과 효과나 성과 보장이 아니다. 일별 관측이 완전하지 않거나 모형 조건을 충족하지 못하면 예산 개선치는 추정 불가다. 소재 생성일과 실제 운영 변경의 원인은 CSV만으로 확인되지 않는다. 실사용 CSV·실제 다음 기간 성과·구매 권한이 필요한 파일 다운로드는 이번 작업의 실측 검증 범위에 포함하지 않았다.

## 2026-10-10 후속 요청: 독립 도구와 첫 진입

| 위치 | 현재 문제와 영향 | 변경 방향 | 보존 | 검증 |
|---|---|---|---|---|
| 진입 | 대시보드 탭 안에 있어 발견하기 어려움 | 독립 운영 플래너, 홈 대표 버튼·시작 목록 연결 | 기존 도구와 공유 CSV | KR/EN 홈→예시·직접 업로드·재진입 |
| 데모 | 두 대상과 비슷한 소재 실적만 있어 실제 운영 판단이 빈약함 | 긴 일별 이력·4개 캠페인·단계별 악화·효율이 다른 신규 소재 | 가상 표시, 기존 계산과 보류 | 원본 동일성·합계·PVM·예산 제약 |

목적은 한 파일에서 다음 운영 변경의 우선순위를 정하는 것이다. 캠페인 악화, 예산 이동, 신규 소재의 관측 근거를 먼저 읽고 필요한 상세로 이동한다. 예산은 동일 예산의 조건부 조정이며 실제 광고 실행을 하지 않는다.

최종 구현: 독립 도구 `5-31`, `/tools/operations-planner` 및 EN 대칭 라우트. 공용 셸·효율 CSV 그룹·업로드/분석 게이트·필터/기간·기존 예산/PVM/단계 분해 엔진을 재사용한다. 홈 대표 CTA와 예시 CTA, `/start`와 분석 목록을 연결했다. 기존 통합 분석의 예시는 `/start?example=1`로 계속 진입한다.

데모: 동일한 결정적 원본의 98일·4개 캠페인·406행이다. 후기 영상과 기능 비교 이미지가 최근 7일에 처음 관측되며 기존 소재보다 낮은 단가를 갖는다. 리타기팅은 최근 CPI가 38.2% 상승하며 클릭→설치 단계의 기여가 가장 크다. 기본 ±20% 조정안은 같은 하루 예산에서 유지안 459.0건→조정안 475.0건, 모형 예상 개선 3.5%로 계산된다. 관측 실적·모형의 유지안·조정안을 구분하며, 수치는 고정 카피로 작성하지 않았다. 홈 미리보기, 실행 예시와 무료 데모 CSV 다운로드가 같은 원본을 쓴다.

시각 검토: 320px KO 다크와 EN 라이트의 단일 열 우선순위·숫자 줄바꿈·표 스크롤, 980px EN 라이트의 공통 정렬·흰색 분석 면, 1440px KO 다크의 결론/예산과 일별 단가 추세/PVM 그림을 실제 브라우저 이미지로 확인했다. 변경 한도·기간 편집·캠페인 선택·같은 CSV로 이동·기존 데이터의 예시 교체 확인을 검증했다. 같은 경로에서 예시를 쓸 때 활성 CSV 미러가 갱신되지 않는 문제를 발견해 공용 `setCsvData`를 쓰도록 수정하고 회귀 검사를 추가했다.

검증: 전체 테스트 5,144개 통과(기존 4개 건너뜀), lint 통과, production build 통과. 빌드된 앱에서 320/980/1440px의 홈/예시/실제 업로드/공백 보류/키보드 진입/기존 예시 연속성 42건과 주간 리뷰 등 기존 진입 회귀 9건이 통과했다. 마지막 예시·원본 CSV·유료 권한 모의의 실제 PNG 다운로드 9건도 통과했다. 새 도구의 KR/EN WCAG A/AA 검사 위반은 0건이다.

미확인: 실제 운영 파일과 다음 기간 성과를 통한 예측 정확도, 실제 구매 계정의 권한 확인·전체 보고서 다운로드. 광고 계정의 예산 변경은 연결하지 않았다. 모델 개선치는 조건부 추정이며 소재·단계 기여는 원인의 인과 증명이 아니다. 브랜치 `codex/operations-brief`는 현재 `origin/main`과 같은 기준 커밋이며 작업은 미커밋·미배포 상태다. 원래 체크아웃의 사용자 변경과 미추적 파일은 보존했다.

최종 통화 검사: 예시를 열 때 이전 USD 표시 설정을 원본 KRW 선언으로 바꾸며 환산하지 않는다. 실제 설정 DOM에 `data-currency-scope="declare"`를 남기고 KR/EN 회귀에서 이를 검증했다. 마지막 전체 검사·lint·빌드도 모두 통과했다.

## 2026-10-10 재검토: 차트 중심 화면과 주간 리뷰

사용자는 앞선 결과가 기존 사이트의 느낌을 유지하지 못했고 텍스트 중심이라 판단과 행동에 부족하다고 지적했다. 위 시각 검토는 당시 검증 기록이며 사용자 승인으로 해석하지 않는다.

| 위치 / 상태 | 현재 문제와 영향 | 변경 방향 | 보존할 정보·행동 | 확인 |
|---|---|---|---|---|
| 첫 결과 | 우선순위 문단·긴 예측 설명·표가 차트보다 먼저 나옴 | 예산 전후 막대, 장기 단가/비용/성과 추세를 상단에 배치 | 실제 계산, 동일 예산, 한도 변경, 추정 보류 | 차트 데이터·한도 0·모바일·KR/EN |
| 캠페인 | 목록에서 읽고 아래로 내려가야 악화 정도와 기여를 대조 | 전후 단가 비교와 선택 캠페인의 단계별 워터폴·소재 구성/단가 기여 | 공통 축, 전체 대상, 산술 항등식, 원인 미확인 | 선택 배선·PNG·결측 |
| 소재 | 신규 소재와 기존 소재 차이를 긴 표에서 찾음 | 비용×단가 버블과 신규 소재 실적 행, 전체 원자료 표 | 성과량·첫 관측일·동일 캠페인 비교 | 점의 좌표/크기·결측·키보드 |
| 주간 리뷰 | 범용 저장 버튼만 있어 어떤 변경을 이어갈지 불분명 | 차트 옆 후보를 선택해 대상·행동·실측 기준값·기간·질문을 기존 결정 폼에 전달, 주간 리뷰 링크 | 기존 저장 권한·세션/기기 정책, 데모 저장 금지 | 실제 저장→리뷰 진입·대상별 자동 비교 금지 |

목적은 비교한 데이터를 구체적 변경 후보와 다음 기간의 검토로 연결하는 것이다. 예산의 현재/조정안, 관측 추세, 캠페인 악화와 기여, 소재의 비용·단가·성과를 차트로 먼저 비교한다. 기존 면·색·폰트·필터·결과 카드·표·저장 폼을 사용한다. 전체 예산 후보는 동일 범위의 다음 기간 실측과 비교하며, 캠페인/소재 후보는 현재 자동 비교 계약이 대상 식별자를 지원하지 않으므로 직접 재분석해 검토한다.

실제 변경: 상단 4개 실측/모형 수치 아래에 예산 전후 막대와 98일 추세, 캠페인 전후 단가와 선택 캠페인의 단계별 워터폴·소재 구성/단가 기여, 비용×단가 버블과 신규 소재 비교를 배치했다. 추세는 CPI/CPA·광고비·성과수로 전환한다. 차트 점·버튼과 키보드 선택이 같은 대상을 바꾸며 전체 수치는 아래 표에 유지한다. 차트 색은 기존 `CHART_THEME`·`chartCommonOpts`에서 가져오며 공용 셸과 스타일 토큰을 사용한다.

주간 리뷰 연결: 차트 옆 예산/캠페인/소재 버튼으로 실제 관측 기준값·대상·행동·검토 질문·동일 길이의 다음 검토일을 준비한다. 내 파일에서는 기존 결정 폼과 로그인/Pro·프로젝트·기기 저장 절차를 사용하고, 저장 후 `/weekly-review#wr-history`에서 같은 결정과 원본 파일을 다시 연다. 모형 예상 CPI를 실측 기준값으로 저장하지 않는다. 전체 예산은 기존 비교 범위를 사용하고 캠페인/소재는 자동 비교를 허용하지 않는다. 데모는 계획 미리보기만 제공하며 가상 결정을 저장하지 않는다. 후보 변경 시 기존 미저장 입력 확인을 유지하고, 이동 후 제목에 포커스를 주며 모션 감소 설정을 따른다.

## 2026-10-10 결과와 행동 우선 배치

사용자가 지정한 `design-preview/20261010-lean-brand/tools-comparison.html`의 요약·근거·설정·업로드 구성과 실제 생성 함수를 읽었다. 결론과 핵심 차트, 다음 행동을 먼저 읽고 설정·원자료를 필요할 때 여는 정보 순서를 적용한다. 참고 파일의 별도 브랜드 스타일이나 모의 적용·저장 동작은 가져오지 않으며, 현재 공용 셸·결과 카드·차트·표·필터·주간 리뷰 계약을 유지한다.

분석 전에는 데이터 준비를 펼친다. 분석 후에는 적용 조건 요약→결론/수치→행동 탐색→예산/추세·캠페인·소재 차트→주간 리뷰→접힌 원자료 순서로 읽는다. 설정을 바꿨을 때 이전 결과를 최신처럼 남기지 않으며, 기존 자동 재계산·분석 게이트를 그대로 사용한다. 계산 엔진과 수치는 변경하지 않는다.

실제 변경: 업로더를 재마운트하지 않고 같은 분석 조건 안에 유지해 매핑 편집 중 분석 게이트가 바뀌어도 기존 편집 창 상태가 보존된다. 분석 전 데이터 준비는 펼치고, 분석 완료·예시 진입에서는 조건을 기본 접는다. 최근/직전 기간·출처·행 수·지표·통화·선택 필터는 접힌 상태에서도 보인다. 중복된 공통 원본 행 수 상자는 이 도구에서 제거했으며 저장 설정 적용/검토 알림은 유지했다. 결과의 행동 링크는 해당 제목/영역으로 이동하며 키보드 포커스를 전달한다. 비교 실적이나 소재 ID가 부족할 때 행동 요약도 `비교 불가`·`소재 식별 부족`으로 표시한다. 상세 표를 접어도 내보내기용 계산 데이터는 유지한다.

검증: 전체 583개 파일·5,155개 검사 통과, 기존 1개 파일/4개 검사 건너뜀. lint 오류/경고 0건, production build 통과. 최종 빌드에서 KO/EN·320/980/1440px 운영 플래너와 기존 대시보드의 브라우저 검사 57건 통과. 실제 업로드→분석 후 설정 접기, 키보드 링크/포커스, 매핑 창 열기/닫기와 호출 버튼 복귀, 14일 변경 후 합계 갱신, Meta 필터 선택/초기화, 원자료 표 펼치기, 예산 한도·공백 보류·PNG/원본 CSV 다운로드, 결정 저장→주간 리뷰를 확인했다. 기본 결과의 공용 디자인 스캐너 6건과 설정/표를 동시에 펼친 상태의 상자 중첩·겹침·안쪽 여백·정렬 검사도 통과했다. 신규 화면 WCAG A/AA 위반 0건. jsdom은 닫힌 native details의 접근성 가시성을 실제 브라우저처럼 판별하지 못하므로 닫힘/숨김은 Playwright에서 검증했다.

시각 확인: production 페이지의 라이트 기본 진입에서 중복 상자 제거·한 줄 조건·결론/KPI·행동 탐색을 확인했고, 데스크톱 다크 결과와 차트 배치 및 편집된 기간의 결과 화면을 검토했다. 마지막 빌드의 `operations-result-first-overview.png`·`operations-result-first-conditions.png`를 대화 시각화 폴더에 보관했다. 공용 셸·차트·표·색·서체는 유지했으며 참고 파일의 별도 스타일과 모의 저장/적용 동작은 복사하지 않았다. 모든 디자인 판단이나 임의 실사용 CSV를 검증했다는 뜻은 아니다. 실제 유료 계정·구매·다음 기간 예측 정확도는 미확인이다. 변경은 `codex/operations-brief`에 미커밋·미배포 상태이며 원래 체크아웃의 사용자 변경/미추적 파일은 보존했다.

## 2026-10-11 사용자 스크린샷 다섯 항목 수정

기존 검사는 사용자가 지적한 진행 표시·제목 여백·기간 구분·점 겹침·PNG 밀집을 충분히 검사하지 못했다. 사용자 요청에 따라 공통 진행 표시와 제목 면, 모든 공용 그림의 내보내기 배치를 같은 작업에서 수정한다. 제품 계약의 기존 막대 전용 지침도 사용자가 요청한 구획된 진행 면으로 갱신했다.

실제 수정: 공통 진행 표시를 하나의 테두리 면과 네 구획으로 바꾸고 폰에서도 단계 이름을 2×2로 유지했다. 공통 제목 면은 흰색/테마 표면과 24px·16px 안쪽 여백을 갖는다. PNG는 제목 뒤 독립 행으로 배치하며 직접 버튼을 사용하던 대시보드·소재·포화도·유입 변화·결과 작업대에도 같은 클래스를 적용했다. 기간 차트는 실제 직전 범위에 사선/점선, 최근 범위에 채움/실선을 그리고 실제 날짜를 범례에 표시한다. 캠페인의 단가 x좌표는 유지하고 직전 원/최근 삼각형을 행 안에서 위/아래로 분리해 동일·미세 변화도 두 값을 읽을 수 있게 했다. 값·변화율·표식 범례·선택·툴팁을 함께 확인했다. 홈 예시의 작은 출처 라벨이 제목 위에 붙어 있던 문제도 제목 아래로 정리했다. 계산 엔진은 변경하지 않았다.

회귀 증거: 수정 전 실제 브라우저에서 KO/EN 제목 안쪽 여백이 0px로 실패했다. 새 PNG 간격 검사는 포화도의 응답곡선/규모 비교와 소재 분석의 직접 버튼 밀집을 실제로 탐지했다. JSX 전체를 AST로 읽는 커버리지 검사는 기존 공용 그림 머리를 우회한 직접 사용처 6곳을 추가로 찾아냈다. 검사에 예외를 붙이지 않고 사용처를 고쳤다. 초기 전역 실행에서 발견한 활성 단계의 라이트 대비 4.49:1도 공통 본문색으로 수정했다. 새 주간 리뷰 검사는 빈 프로젝트 화면에서 곧바로 진행 표시를 기대했던 잘못된 준비를 고치고 실제 ‘주간 성과 비교’ 진입을 밟는다.
