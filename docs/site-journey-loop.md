# 사이트 전체 분석·재검토 흐름

## 확인한 끊김

- 홈은 분석을 시작하라고 하지만 도치 접수처는 LandingPage 전체 다음에 렌더된다. 모바일에서는 도구 목록·읽을거리 아래, 데스크톱에서는 별도 고정 패널이며 동의 배너가 있으면 숨겨진다. 모든 폭에서 본문 상단 접수 영역으로 통합했다.
- 모바일 헤더는 주간 리뷰 이름을 숨겨 시계 아이콘만 남긴다. 사이드바에서는 원인 찾기 뒤의 네 번째 목적지다.
- 도치 작업대의 실제 계산에는 분석 시작·완료·결과 노출 계측이 없고 결정 저장도 상세 도구로 이동해야 한다.
- 기존 블로그 어트리뷰션은 같은 tool_id일 때만 이어진다. 도치→다른 도구→리뷰처럼 목적지가 달라지는 전체 여정에는 사용할 수 없다.
- 리뷰 완료 이벤트는 보고서 계산 완료다. 읽음·결정 저장·다음 방문·다음 기간 비교는 별도로 확인해야 한다.

## 구현 기준

홈에서 제품 약속→데이터 접수→가능한 분석 순서로 시작한다. 공통 여정은 데이터 준비→분석 근거→결정 저장→다음 리뷰이며, 단계 표시는 방문 위치만 설명하고 완료를 지어내지 않는다. 리뷰는 모바일에서도 이름을 보이고, 내비게이션에서는 분석 바로 다음에 둔다. 결과에서는 저장 가능한 실제 결론을 기록하고, 저장 후 다음 검토일과 결정 이력으로 연결한다. 콘텐츠의 관련 도구 연결은 보존하고 그 분석이 리뷰로 이어진다는 메시지를 함께 제공한다.

기존 색상·글꼴·카드·44px 조작 기준을 사용한다. 새로운 독립 테마나 강제 가입·결제·서버 업로드는 도입하지 않는다. KO/EN은 같은 구조를 사용한다.

## 측정 기준

GA4의 기존 이벤트를 유지하면서 데이터 접수 위치, 최초 유입면, 현재 단계, 도치 계산, 리뷰 재사용을 구분한다. 익명 GA 세션과 이벤트 순서로 퍼널을 읽으며 별도 사용자 ID·파일 식별자·프로젝트명·캠페인명·결론·지표값을 보내지 않는다. 데모와 실제 데이터를 분리한다. 최초 유입면은 30분 비활동 만료의 탭 세션 범주만 보관한다.

검증은 코드 이벤트 발생, 로컬 브라우저 전 과정, GA 관리 화면 확인을 구분한다. 전송 호출 성공을 GA 보고서 수신으로 표현하지 않는다.

## 실제 GA 관리자 점검 (2026-09-09)

- growthoptplaybook 속성(542428327), 운영 도메인 웹 스트림의 측정 ID `G-DK12TNR0GW`가 코드와 일치한다.
- 최근 28일 수신 이벤트 36개를 확인했다. 업로드 시작/완료, 분석 시작/완료/결과 노출, 결정 이력 노출은 있다. 주간 리뷰 전용 이벤트와 결정 저장 이벤트는 목록에 없다. 사용 여부·처리 지연과 구현 문제를 이 목록만으로 구분할 수는 없다.
- 맞춤 측정기준은 `content_type`, `group`, `tool` 3개다. 코드의 `tool_id`와 다르며 신규 여정 구분 항목도 미등록이다. 추가 설정은 사용자 답변 대기 중이다.
- Enhanced Measurement의 브라우저 방문 기록 기반 페이지뷰가 켜져 있어 앱의 수동 페이지뷰와 중복될 수 있다. 해당 옵션 해제는 사용자 답변 대기 중이며 관리자 설정은 임의 변경하지 않았다. GTM 내부 트리거는 미실측이다.
- 신규 이벤트의 배포 후 GA 수신은 별도 검증 대상이다. 로컬 테스트는 외부 GA로 실제 운영 데이터를 보내지 않는다.

## 검증 결과

- 전체 Vitest 406개 파일 / 3,338개 통과(기존 로컬 미추적 테스트 2개 파일·6개 포함), ESLint 오류 없음.
- 운영 빌드 및 301페이지 프리렌더 통과.
- 전체 Playwright 99개 통과. KO 320/768/1440과 EN 라이트에서 도치 접수→실제 분석→결정 저장→리뷰→이력 펼치기, 기존 검색 유입 예제·다운로드·접근성 검증을 실행했다.
- 실제 브라우저에서 홈 CTA가 본문 접수 영역으로 이동하고, 도구 목록을 가리지 않는 것을 확인했다. E2E는 DOM 순서뿐 아니라 실제 배치와 고정 패널 제거도 검증한다.
- 초기 전체 검증에서 발생한 사이드바 라이트 대비 회귀를 수정했다. 동시 실행 부하에서 발생한 테스트 시간초과는 단독 전체 재실행에서 해소됐다. 실패 단언을 삭제하거나 타임아웃을 늘리지 않았다.
- 동의 기본값이 gtag 큐를 먼저 설치한 실제 초기화 순서도 수정 전 실패/수정 후 성공으로 검증했다. 운영 제품 이벤트는 기존 큐 여부와 무관하게 측정 목적지를 명시한다.
- 실제 iOS Safari·Android 기기, Lighthouse 점수는 이번 변경에서 미실측이다.
