# 예산 배분 소진 플래너 보강

2026-10-08 요청: 주간/D7 처리 → 최근 운영 패턴 구간 → 기존 유지와 전체 재배분 비교. Excel의 Cost 입력만 바꿔 화면 곡선의 예측값을 계산할 수 있어야 한다.

화면은 기존 셸·폰트·색·표를 사용한다. 관측 단위/기준일은 데이터 설정, 구간 선택은 곡선 설정, 두 배분안은 결과 근거, Cost 입력은 Excel의 시나리오 시트에 둔다. KO/EN 동등하게 연결하며 320·980·1440과 라이트/다크를 검토한다.

사용자 화면 코멘트 4건을 반영해 결과를 배분안·예산 비교·곡선·확인 탭으로 통합했다. 변경 요약·전체 배분표·비중은 같은 배분의 대체 보기로 전환하고, 효율 관측점과 지출·성과 곡선도 번갈아 본다. 별도의 상단 수치 카드와 하단 총합 카드를 제거하고 결론의 수치로 모았다. 배분 점검·진단·기간 민감도·계산 방법은 확인 탭에 넣었다. 데이터·범위·방법의 확인 항목은 중복 문구를 제외한 한 개수로 표시하고, 판단 저장·다음 기간 검토·공유는 분석 영역 뒤에 배치했다. 탭은 ARIA 소유 관계와 화살표/Home/End 이동을 지원하며 보기 변경은 곡선 재적합을 일으키지 않는다.

스킬 원본의 엔진·method 파일은 아직 제공되지 않았다. 기존 `ALLOC_MATH` 계산을 재사용하고 새 관측/구간/워크북 계약을 순수 모듈로 분리한다. 사내 쿼리·데이터를 가져오거나 서버로 전송하지 않는다.

실제 업로드에서 `week_start`의 V1 date 매핑은 통과했지만 V2 의미는 week여서 실행이 차단됐다. 예산 배분기에만 date/week 호환을 선언하고 사용자 의미 확인 후에도 같은 period-start를 엔진 date 입력으로 투영한다. 다른 일별 도구의 date 계약은 그대로 유지한다.

Excel 검증은 4개 모델 × 두 분배 보기 × 0·50·200·350·800·음수 Cost, 모델 없음까지 실제 XLSX를 재계산해 확인했다(60개 행 사례). 재계산에는 LibreOffice Calc를 사용하고 캐시값을 제거해 수식을 평가했다. Microsoft Excel 앱에서 직접 조작한 검증은 미실행이다. 현재 배분 결과의 `BUDGET_PLAN`은 엔진 출력이고 `COST_INPUT`의 Cost 시나리오는 고정된 현재 곡선의 수식 예측이다. 월예산 ÷30 계약은 유지한다.

최종 검증: `test:all` 5,050 통과·4 skip, lint·build 통과. 통합한 예산 배분과 새 업로드 흐름의 브라우저 검사 20개 통과(320·980·1440, KO/EN, 라이트/다크 포함). 탭 ARIA·키보드·단일 확인 개수·분석 뒤 검토 순서·보기 전환 중 배분 보존·필터 공유·PNG 다운로드를 검사했다. 주간 파일은 V1 매핑·V2 준비 상태·실제 업로드·분석·설정 변경까지 확인했다. 기존 사용자 파일은 별도 작업트리에서 보존했고 기존 `allocationMath.js` 골든 계산은 수정하지 않았다.
