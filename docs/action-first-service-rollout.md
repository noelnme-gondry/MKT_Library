# 서비스 전체의 판단·행동 흐름 정리

2026-11-05 · 승인된 운영 플래너 HTML을 실제 제품과 다른 화면에 적용한다.

## 설계 기준

목적 → 현재 판단 → 실제 근거 → 다음 행동 → 검토 순서로 읽는다. 예산은 실행 금액과 같은 모형으로 계산한 예상 성과를 함께 비교한다. 소재는 관측 기간·선정 이유·다음 확인을 보여 주며 투입·종료의 인과 효과를 예측하지 않는다. 도구마다 질문이 다르므로 같은 대시보드를 복제하지 않는다.

| 위치 / 상태 | 기존 문제와 영향 | 변경 방향 | 보존할 정보·행동 | 검증 |
|---|---|---|---|---|
| 홈·탐색 | 플래너 진입이 작은 데모 링크에 묻힘 | 할 수 있는 일과 실제 예시를 먼저, 파일 입력과 플래너 직접 연결 | 기존 분석 찾기·가이드·무료 분석·저장 조건 | KO/EN, 첫 진입과 파일/예시 경로 |
| 플래너 | 결론이 세 번째 탭, 고정 총액만 계획 | 유지·증액·감액, 적용 기간·총액 → 실행안·예상 성과 → 선택한 대상의 근거 | 원본·계산·보류·전체 변화·실행 기록 | 금액 보존·방향 제약·부족 데이터·실제 조작 |
| 캠페인·소재 | 평면 나열, 같은 대상의 선택 가능 여부 불일치 | 전 항목 동일 선택, 선정 이유와 성과 기간, 선택 대상의 근거·액션 | 전체 목록·미확인 시작일·예측 한계 | 선택·필터·기간 변경·모바일 |
| 결과 공용 부품 | 결론·핵심 수치·행동이 비슷한 무게, 행동이 상세 아래 | 핵심 결과와 도구가 계산한 다음 행동을 가까이, 상세/저장/다운로드 위계 | 기존 통계값·공유·다운로드·검토 | 소비처 조사, 상태 분기 스모크 |
| 표·선택·변화 | 컬럼 경계 약함, 조작 후 바뀐 정보 찾기 어려움 | 약한 세로 구분, 일관된 선택, 바뀐 결과에만 짧은 전환 | 숫자 정밀도·접근성·전체 데이터 | 좁은 폭·키보드·reduced-motion |
| 검토·가이드·계정 | 화면 목적별 다음 행동 점검 필요 | 분석 화면과 같은 정보 위계, 각 화면의 원래 과업 유지 | 저장·요금·로그인·문서 계약 | 해당 소비 화면에서 실제 확인 |

## 구현·검증 기록

- 시작: 이전 작업과 최신 main의 파일 내용 동일, 사용자 변경·미추적 파일 없음. `codex/action-first-service`를 `origin/main`에서 생성.
- 실제 계산 엔진·골든은 유지하고 계획 조건과 표시 계층을 분리한다.
- 공용 컴포넌트 소비 목록은 코드/라우트 레지스트리에서 조사한다. 적용과 실제 화면 확인을 구분해서 기록한다.
- `ResultActionCard` 정의를 제외한 소비 컴포넌트 23곳에 공용 위계를 적용했다. `AdvancedMarketingAnalysis`처럼 레지스트리로 여러 분석을 렌더하는 화면도 같은 부품을 사용한다. 파일 수를 개별 화면 육안 확인 수로 해석하지 않는다.

## 적용한 내용과 이유

- **홈**: 도구 설명과 실제 계산한 예산 예시를 먼저, 다른 분석 목록과 공용 업로드를 아래에 배치했다. 주 버튼은 플래너 예시로, 내 데이터 버튼도 같은 플래너로 연결한다. 캠페인 변동·포화도에서 운영 계획으로 이어지는 링크도 플래너를 가리킨다. 기존 예산 배분 도구의 주소·고급 설정은 보존하되 플래너의 다음 단계로 다시 보내지 않는다.
- **운영 플래너**: 결론을 탭 밖 맨 위에 두고, 유지·재배분 / 증액 / 감액과 적용 기간·총액을 연결했다. 증액안은 캠페인을 감액하지 않고 감액안은 증액하지 않는다. 명시한 총액이 필터 후 남은 캠페인의 제약을 벗어나면 보류한다. 기존 적합·예측·배분 엔진은 변경하지 않았다.
- **날짜와 단위**: 원본의 일·주·월 표기를 읽고, 선택한 집계 단위와 비교 기간을 반영한다. 주·월 합계를 일별 관측점으로 복제하지 않는다. 기간이 잘린 원본 합계·혼합 단위·불충분한 추세는 보류한다. 월별 추세는 30일 환산, 원본 최소·최대는 실제 월 합계라고 구분한다.
- **캠페인 근거**: 좌우 예산 이동 목록은 같은 행 트랙을 공유한다. 화살표는 두 열 사이에 놓고, 현재·조정안 차트 라벨은 둘 다 그림 위에 고정한다. 범례는 아래로 옮겼다. 변화 분해는 기존 소재의 성과 비중 / 기존 소재 단가 / 새로 성과를 낸 소재 / 성과가 없어진 소재로 나눈다. 관측 기여를 투입·종료의 인과 효과로 표현하지 않는다.
- **소재**: 모든 항목을 선택할 수 있다. 이번 기간에 처음 확인된 소재를 먼저, 나머지는 지출 순으로 제시하며 선정 이유를 써 둔다. 성과 합산 기간과 파일에서 처음 확인한 날짜를 구분한다. 별도 소재 분석에서도 즉시 교체 경고가 없는 피로 신호는 재확인·교체 시점 결정으로 안내한다.
- **공용 결과**: 결론 문장이 다운로드 도구에 눌리지 않도록 도구줄을 아래로 옮겼다. 실제 계산된 주요 수치 → 다음 액션·검토 질문 → 근거 그림 순서다. 강조 수치는 화면의 판정에 맞춰 고르며, 0개 교체 경고를 가장 크게 보여 주지 않는다. 미확인·부족 상태를 정상으로 바꾸지 않는다.
- **실행과 검토**: 예산안의 기간·총액을 실행 기록까지 넘긴다. 실제 광고 플랫폼 예산 설정값과 관측 지출을 구분하고, 수동 액션·전체 관측 변화·후속 검토를 보존한다. 주간 검토의 다음 결정 버튼을 요약 복사보다 우선한다.
- **탐색·가이드·계정**: 분석 찾기의 결과 수는 실제 필터 결과를 보여 준다. 가이드는 운영 단계와 문서 링크, 계정은 계정·프로젝트·매핑 관리의 구분을 강조했다. 문서·설정 화면에 예산용 차트를 복제하지 않았다. 저장·Pro·결제·권한 계약은 유지한다.

## 강조와 움직임의 규칙

1. 크기·위치로 결론과 주요 수치, 색과 테두리로 선택·증액·감액·검토 상태를 구분한다. 색만으로 의미를 전달하지 않는다.
2. 표는 옅은 세로선, 분해 항목은 독립된 행 박스, 선택된 대상은 같은 테두리 규칙을 쓴다. 그룹 제목과 선택된 행은 다르게 보인다.
3. 결과가 실제로 바뀌었을 때만 210ms 동안 나타나는 움직임을 준다. 숫자를 중간의 가짜 값으로 카운트하지 않는다. 화면 밖·동일 값·움직임 줄이기 설정에서는 실행하지 않는다.
4. 차트는 최대 280ms, 기여 막대는 280ms로 연결한다. 클릭한 대상과 바뀐 근거의 관계를 드러내는 용도이며 장식용 반복 재생은 없다.
5. 모바일은 같은 캠페인 정보를 상단·표에 중복하지 않고, 실행 가능한 전체 표에서 모두 제공한다. 목록 내부 스크롤을 줄이고 문서 흐름으로 읽게 한다.

## 미확인 범위와 보존 사항

- 모든 공개 라우트의 모든 언어·테마·데이터 조합을 육안 확인한 것은 아니다. 공용 부품 소비처는 전체 테스트, 주요 대표 화면은 실제 브라우저로 검증했다.
- 로컬 계정 연결이 없어 로그인 후 계정 보관·결제·Pro 내보내기는 실계정으로 실행하지 않았다. 해당 기능의 기존 테스트는 전체 검사에 포함됐다.
- 날짜가 일자로 적힌 주·월 합계는 날짜 간격만으로 확정할 수 없다. 화면에서 원본 날짜 형식을 맞추도록 안내한다. 소재 변경·초기 학습과 예산 변화의 인과 효과를 분리한 예측은 아니다.
- 첫 검토본은 `origin/main`과 같은 기반에서 만든 `codex/action-first-service`의 로컬 변경이었다. 이후 사용자 머지 요청에 따라 이 구현과 검증 기록을 PR로 제출한다. 배포 결과는 이 검토 기록에 포함하지 않는다.
- 작업 시작 시 사용자 변경과 미추적 파일은 없었다. 개발 서버 실행 뒤 확인된 `v2-migration/AGENTS.md`의 제목 단계 변경은 이 작업의 구현에서 제외하고 보존했다.
- 검토 화면: `http://127.0.0.1:3158/`, `http://127.0.0.1:3158/tools/operations-planner?example=1`. 실제 Next.js 앱이며 별도 HTML의 가짜 수치가 아니다.

## 머지 전 추가 검증

- 예전 접기 영역·탭 이름을 찾던 브라우저 검사를 실제 홈 주 버튼 → 예산안 → 실행·검토 → 상세 데이터 경로로 갱신했다. 원본 CSV 독립 집계, 키보드 조작, 유료 PNG 출력, 실제 저장·후속 검토 검사는 유지했다.
- 브라우저 회귀에서 확인한 소재 관찰 액션의 대상 이름 누락, 라이트 모드 보조 글자·상태색 대비, 성과 설명 목록의 DOM 구조, 상세 데이터 제목 여백을 수정했다.
- 비교 기간이 잘못돼도 완전한 현재 기간의 원본 입력 근거는 확인할 수 있다. 비교·예산 추천 보류와 실제 입력 내역을 분리했으며 회귀 검사를 추가했다.
- 공용 액션 영역의 왼쪽 끝선을 핵심 수치와 맞췄다. 도구 목차는 화면 고정 좌표 대신 도구 본문 안의 열에 배치해 오른쪽 광고 영역과 겹치지 않게 했다. 목적 있는 하위 구획은 제품 계약과 DOM 표식에 사유를 남겼고 겹침·대비 검사는 유지한다.
- 추가 단위·컴포넌트 검사 50개 통과. 브라우저 검사에서 데스크톱·320px KO/EN의 홈, 플래너, 저장·검토, 차트 출력, 공용 대시보드 흐름을 확인했다. 최종 PR 자동 검사는 GitHub 검사 결과를 따른다.
- 공용 결과 확장 검사에서 생존 분석의 독립 수치 배열에 맞춰 액션 영역 끝선을 조정하고, 대시보드의 중립 상태 글자를 의미 색상 토큰으로 맞췄다. 설문 검사는 현재 노출된 예산 조작의 포커스 보존을 확인한다. KO/EN 생존 분석·대시보드·설문과 홈·분석 안내 확대 검사의 관련 10개 사례가 통과했다. 확대 검사에서 한 번 발생한 넘침은 단독 재현과 관련 재검사에서 나타나지 않아 코드 변경 없이 간헐 이력으로 남긴다.
- CI 전체 테스트 634 파일·5,863개, lint, production build가 통과했다. 전체 브라우저 검사에서는 중복 제목 상자 제거·홈 진입·버튼 이름 변경을 반영하지 못한 검사와 검색창 범위 충돌을 수정했다. 제목 검사는 투명한 영역의 페이지 여백·정렬을 검증하고, 채워진 상자의 내부 여백 검사는 디자인 가드에 유지한다. 홈의 내 데이터 버튼에 기존 `landing_data_start_clicked` 이벤트를 연결해 업로드부터 검토까지 홈 유입 기록도 이어지게 했다.
- Railway PR 도메인은 기존 `proxy.js` 정책에 따라 운영 도메인으로 301 이동한다. PR 배포 체크 성공을 새 UI의 외부 브라우저 검증으로 간주하지 않는다.
- 후속 재현에서 영문 라이트 모드의 어두운 푸터 광고 안내 대비도 수정했다. 실패했던 브라우저 29개 사례는 관련 재검사에서 모두 통과했고, 홈 컴포넌트 23개와 수정 파일 lint도 통과했다. 최종 CI 전체 브라우저 결과는 PR에 기록한다.
