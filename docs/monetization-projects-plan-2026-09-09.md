### 1.4 프로젝트는 1개 고정 — 저장 계층부터 막혀 있다

```
src/lib/weekly-review/snapshotStore.js:20  PROJECT_META_KEY  = "weekly-review:project"   ← 단일 키. 덮어쓰기만
src/lib/weekly-review/snapshotStore.js:19  SNAPSHOT_META_KEY = "weekly-review:snapshots" ← 배열 1개. projectId 없음
src/store/useDataStore.js:707              decisionRecords: []                           ← 평평한 배열. projectId 없음
```

프로젝트는 `{name, metric, basis, currency, target, period}` 한 벌뿐이고(`snapshotStore.js:162` `saveReviewProject`), 두 번째 캠페인을 잡으면 첫 번째를 덮어쓴다. **스냅샷과 결정 이력에는 소속 개념이 아예 없어서 A 고객 집계와 B 고객 결정이 한 통에 섞인다.** 즉 "여러 프로젝트 일괄 관리"는 UI 작업이 아니라 저장 계층 공사다.

저장 위치는 워크스페이스 IndexedDB의 `meta` 스토어(`src/lib/workspace-storage/db.js:1·44`, DB 버전 1). **키만 추가하면 되므로 DB 버전을 올릴 필요가 없다** — 마이그레이션 위험이 그만큼 낮다.

### P1 — 저장 스코프 (A안)

**스키마**

```
meta["weekly-review:projects"] = {
  activeId: "p_xxx",
  projects: [{ id, name, metric, basis, currency, target, period, createdAt, updatedAt }]
}
meta["weekly-review:snapshots"] = { snapshots: [{ ...기존, projectId }] }
store.decisionRecords = [{ ...기존, projectId }]
```

**마이그레이션(가장 위험한 지점).** 읽기 키가 바뀌므로 마이그레이션이 없으면 **기존 사용자에게는 데이터가 사라진 것으로 보인다.** 구 `weekly-review:project` 단일 레코드를 읽어 `id: "default"` 프로젝트로 승격하고, 기존 스냅샷·결정 전부에 `projectId: "default"`를 채운 뒤 구 키를 지운다. 구 키가 없으면(신규 사용자) 빈 목록으로 시작한다. **이 경로는 골든으로 고정한다** — 구 레코드 → 새 구조가 byte 단위로 재현되어야 한다.

**만료.** `RETENTION_MS`(90일) 정리가 프로젝트 단위로도 돌아야 한다. 프로젝트 레코드만 만료되고 그 스냅샷·결정이 남으면 **고아 데이터가 어느 화면에도 안 보이는 채로 저장소를 차지한다.** 정리는 프로젝트 목록에서 파생할 것(§7 "목록을 두 곳에 나열하지 말고 파생시켜라").

**주의**

- 활성 프로젝트는 store 한 곳이 소유하고 나머지는 전부 파생. 프로젝트 목록을 두 번째 배열로 복제하지 말 것.
- 결정 이력·스냅샷 조회는 **전부** `projectId` 필터를 타야 한다. 한 곳이라도 빠지면 다른 고객 데이터가 섞여 보인다 — 읽기 경로 전수를 grep으로 셀 것.
- `/weekly-review`는 `TOOL_GROUP`에서 `efficiency`(`src/lib/toolGroups.js:11`). CSV 그룹 계약은 건드리지 않는다.
- 수학 엔진 불변. 저장·필터층만.

### P2 — `/projects` 보관함 (B안)

`routeMap.js`에 `{ id: "projects", slug: "/projects", component: "ProjectsPage", publication: "preview" }`. **사용자 데이터 화면이므로 `/storage`(`routeMap.js:79`)와 같은 noindex 취급** — sitemap·rss 대상이 아니다.

카드 목록(정렬: **검토 기한 임박순**):

| 열 | 내용 |
|---|---|
| 프로젝트명 | 사용자 입력 |
| KPI · 통화 | `metric`/`basis`/`currency` |
| 마지막 업로드 | 최신 스냅샷 `period.end` |
| **다음 검토 기한** | D-N. 지난 것은 강조 |
| 미완료 결정 | `status !== "reviewed"` 개수 |
| 최근 판정 | 마지막 결정의 결과 |

여기가 "매주 돌아올 이유"의 자리다. 프로젝트 이동은 기존 `serializeProject`(`src/lib/project/serializeProject.js`)를 확장해 **내보내기/가져오기**로 시작한다 — 계정 없이 된다.

**주의**: 관측이 없는 칸은 비워 둔다. 스냅샷이 없는 프로젝트의 "다음 검토 기한"을 추정하지 말 것(§8·§11 fabricate 금지). KR/EN 동시(§2.11).

### P3 — 무료 한도 게이트 + 수요 측정

**한도**: 무료 = 프로젝트 **1개**. 두 번째를 만들려는 순간에만 `/upgrade`가 열린다.

**회수 금지 (정직성).** 이미 만든 프로젝트를 잠그거나 지우지 않는다. 제한은 **"새로 만들기" 진입에서만** 걸고, 기존 데이터 접근·내보내기는 무료에서도 영구히 열어 둔다. 저장층이 아니라 생성 진입점에서 거는 이유가 이것이다.

**측정 — 게이트 조회가 곧 전환 신호**

```
upgrade_gate_viewed   { source: "project_limit" | "nav" | "direct", locale }
upgrade_interest_clicked { source, locale }
```

**`source` 없이 페이지뷰만 재면 안 된다.** 푸터·⌘K 등 다른 경로로도 이 페이지에 닿으면 "n개 이상 만들려 했다"는 해석이 깨진다. GA4 주요 이벤트는 **`source = "project_limit"` 조건부로** 만들 것 — 이 조건이 곧 "무료 한도를 실제로 넘으려 했다"의 정의다. 조건식은 P0에서 만든 파생 이벤트 문서에 같이 적는다.

**화면 문구.** 가짜 결제 버튼 금지(§8, #812 본문에서 이미 못박은 계약). "사전 신청" 또는 "키 요청"으로 정직하게 쓰고, 가격은 **검증 전 가설**임을 명시한다(월 29,000원 단일 플랜 가설). 결제 폼·카드 입력 없음.

### P4 — 수동 키 해제

**서버 없는 오프라인 검증.** 키 = `{plan, expiresAt, label}`를 Ed25519로 서명한 토큰. 공개키는 번들에 넣고 `crypto.subtle.verify`로 브라우저에서 검증한다. 네트워크 요청 0 — §2.2(서버 전송 금지)를 그대로 지킨다.

**정직하게 말할 것**: 이건 DRM이 아니다. 번들을 읽으면 우회할 수 있고, 그렇게 설계한 것이다(전문가 대상 제품의 신뢰 기반 해제). **"안전하게 보호된다"고 쓰지 않는다.** 화면 카피에 보안을 주장하지 말 것.

**키 안에 개인정보를 넣지 않는다.** `label`은 사용자가 붙이는 표시용 문자열이며, 이메일·회사명을 강제하지 않는다. 검증 결과는 store에 `entitlement: {plan, expiresAt}`로만 남긴다.

**만료 처리**: 만료 후에도 기존 프로젝트는 읽기·내보내기 가능(P3의 회수 금지와 동일). 새로 만들기만 다시 잠긴다.

전달은 수동(계좌이체/인보이스 → 키 발급). PG 연동은 이 단계에 없다.

### P5 — 코드 밖 선행조건

돈을 실제로 받기 전에 필요한 것. **수동 키·계좌이체라 PG는 없어도 되지만 아래는 면제되지 않는다.**

- 사업자 등록 · 통신판매업 신고
- 이용약관 · **환불 정책**(전자상거래법 청약철회)
- 개인정보처리방침 갱신 — 결제·인보이스로 수집하는 항목 명시. **CSV는 계속 브라우저에만 있고 서버로 가지 않는다는 기존 문장은 그대로 유지된다**(수동 키 구조라 실제로 참이다).
- 파일럿: 5~10명 4주. 측정 지점은 2주차 업로드 → 지난 결정 검토 → 보고서 활용 → 실제 결제.

`lib/brandFacts.js`의 "무료·가입 없음" 문장은 P3~P4에서 **한정 표현으로 바뀌어야 한다**(분석 도구는 계속 무료·가입 없음 / 프로젝트 2개 이상은 유료). SSOT를 먼저 고치고 코드가 그 사본을 따르게 할 것(§2.12).
