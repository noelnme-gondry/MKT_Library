목적은 계산에 사용된 관측과 컬럼을 확인한 뒤 캠페인·예산을 검토하는 것이다. 핵심 질문은 “이 지표는 어떤 입력으로 계산됐고, 관측이 부족한가?”이며, 새로운 목표·권고 엔진을 만들지 않는다. 관련 입력과 값은 하나의 콘텐츠 면에 두고 기존 결과 다음에 배치한다. 매핑 수정은 보조 행동, 실제 캠페인 선택·기존 예산 비교가 다음 행동이다.

실제 운영 CSV는 제공되지 않았다. 검증에는 기존 제품 데모와 결측·0·음수·범위 충돌을 포함한 테스트 픽스처를 사용한다. 실행 결과와 화면 확인 범위는 작업 완료 시 아래에 기록한다.

## 검증 결과

- `npm run test:all`: 5,676 통과, 4 건너뜀. 기존 리뷰 스모크의 JSDOM `scrollIntoView` 누락은 해당 테스트 파일 안에서 대역·정리·실제 rAF 호출 검증으로 보완했다. 제품 리뷰 코드는 변경하지 않았다.
- `npm run lint`, `npm run build`, `git diff --check` 통과. 수학 엔진·골든값·라우트·그룹 계약은 변경하지 않았다.
- 내부 브라우저에서 KO 다크 320·980·1440px의 실제 화면을 캡처·검토했다. 문서 가로 넘침은 없고 좁은 입력 표는 기존 DataTable의 내부 가로 스크롤을 사용한다. EN 라이트의 주요 면은 실제 흰색이며 페이지 배경과 구분됨을 확인했다.
- 지표 선택 시 실제 의존 컬럼 표 변경, ARIA 제어 대상 존재, 매핑 진입 시 기존 조건 펼침·포커스, 검토 목록 선택 시 같은 캠페인 분석·포커스, 7→14일 변경 후 기간·합계 동기화, 예산 변경 한도 0%에서 같은 예상값을 확인했다. 브라우저 실행 오류 0건.
- 입력 근거와 레지스트리 계산값은 기존 워크북 출력에도 연결했다. 신규 통신·수집·가상 목표·순매출·소재 미디어 연결은 추가하지 않았다.
- 실제 운영 CSV·실계정 결제/보고서 다운로드는 미검증이다. 기기 저장·과금 권한과 기존 표/차트 내보내기 경로는 기존 구현을 유지했다. 커밋·push·PR·배포는 수행하지 않았다.

## 좌우 균형 수정 (2026-10-24)

- 사용자 지적: 큰 CPI 카드와 2×2 선택 카드에 비해 오른쪽 표 두 행만 남아 부실해 보임.
- 변경: 선택 영역을 좁은 5행 목록으로 줄이고, 오른쪽을 선택 결과 → 분자/분모 실제 합계와 ÷·단위 배율 → 원본 컬럼·검증 상태 순서로 구성했다. 합계는 계산식으로 이동해 표에서 중복하지 않는다. 계산식의 표시 반올림과 원본 합계 사용을 명시하며 기존 지표 계산기는 변경하지 않았다.
- 실제 화면: 내부 브라우저에서 KO 라이트 320·980·1440px, EN 라이트/다크 1440px 검토. 문서 가로 넘침 없음. 980px는 가로 선택, 320px는 목록 내부 가로 스크롤과 계산식 줄바꿈을 사용한다. 라이트 콘텐츠 면은 실제 흰색, 다크 면은 배경과 구분된다. CTR·CPM·CPI 선택에 따라 결과·합계·단위 배율·원본 표가 함께 바뀌며 브라우저 오류 로그는 0건이다.
- 자동 검사: 집계·실제 도구 스모크 22개 통과. 결측을 0으로 표시하지 않는지, 실제 분모 0은 유지하면서 지표 결과는 계산 불가로 남는지 검증했다. 반응형 스케일 14개 및 전체 lint 통과. 새로 추가했던 600px 경계는 기존 640px 스케일로 바로잡았다.
- 최종 전체 회귀: `npm run test:all` 5,677 통과·4 건너뜀(614 파일 통과·1 건너뜀), `npm run lint`·`git diff --check` 통과.
- 변경 위치: `OperationsMetricEvidence.jsx`, 해당 구역의 `globals.css`, 연결 스모크, 제품 계약. 다른 도구는 새 CSS 클래스의 소비처가 없다. 최종 캡처는 작업 아티팩트의 `service-balanced-1440.png`이며 실제 운영 CSV는 여전히 미검증이다. 이번 렌더·스타일 수정 뒤 빌드는 재실행하지 않았고 직전 기능 구현의 빌드는 통과했다.
- Git: `codex/csv-evidence-workbench`, HEAD와 `origin/main` 차이 0/0 위의 미커밋 변경이다. 커밋·push·PR·배포는 하지 않았다. 기존 기본 체크아웃의 사용자 변경·미추적 파일과 앞선 기능 구현 변경을 보존했다.

## 나머지 후보의 밀도·균형 전수 점검 (2026-10-24)

범위는 승인한 CSV 후보가 연결되는 운영 플래너의 전체 결과 흐름이다. 실제 결과를 만든 뒤 예산·추세, 지표·입력, 캠페인 차트·관측 목록, 두 분해, 소재 차트·신규 목록·선택 상세, 주간 리뷰와 전체 상세 표의 정보·행동을 대조했다.

|---|---|---|

후보 화면의 주간 리뷰를 확인하면서 공용 레거시 접근성 보강기가 이미 의미를 가진 `PillGroup` 바깥 래퍼까지 라디오 그룹으로 만들고 있음을 발견했다. 실제 DOM의 중첩 그룹 2개를 재현한 실패 테스트를 남긴 뒤, 자식 그룹이 직접 관리하는 경우 보강기만 건너뛰도록 수정했다. 공용 `PillGroup`·기존 레거시 선택기의 동작을 유지하며 새 지표·임계값·외부 데이터는 추가하지 않았다.

- 실제 브라우저: KO 라이트 1440/980/320, EN 라이트 1440, EN 다크 980/320. 모든 주요 결과 구역의 페이지 가로 넘침 0. 모바일의 넓은 표만 기존 내부 가로 스크롤을 사용한다. 표 선택으로 이동한 상세는 90px 위치에서 읽히고 실제 포커스를 받는다. 정상·노출/클릭 미매핑·소재 ID 미매핑, 예산 0%, 신규/기존 선택, 리뷰 종류 전환을 확인했다.
- 집중 검사: 관련 집계·실제 도구·차트·레거시 보강기 31개 통과. 라디오 그룹 회귀는 수정 전 1개 실패, 수정 후 통과를 확인했다. 예산 추정 보류와 소재 ID가 있지만 성과 0으로 차트를 그릴 수 없는 상태의 한 열 분기는 도구 스모크에서 검증했다. 실제 성과 0은 0으로 남고 단가는 계산 불가로 표시된다.
