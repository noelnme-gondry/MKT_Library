## 사용자 흐름 개선

1. 분석은 무료로 시작한다. 첫 저장에 체험이 필요하면 프로젝트 체험을 시작하고 작성 중인 리뷰로 돌아온다.
2. 저장 완료는 실제 기기 저장 성공을 뜻한다. 저장 실패 때 입력을 유지하고 같은 창에서 재시도한다. 후속 작업 실패는 이미 저장된 사실과 구분한다.
3. 저장한 CSV만 열어 둔 경우 불필요한 전환 확인을 생략한다. 미저장 파일·리뷰·보고서 초안이 있으면 확인한다.
4. 저장한 수동 모델 입력은 CSV 업로드·비교 단계 없이 적용한다. 복원이 진행 중이면 설정 적용을 기다려 뒤늦은 복원이 사용자 입력을 덮어쓰지 않게 한다.
5. 결제 쿠키 조회가 늦게 끝나도 로그인 계정의 유효한 체험 권한을 지우지 않는다. 프로젝트 생성 직전 계정 상태를 확인한다.
6. 기존 결정의 실제 결과·배운 점 편집과 내보내기 진입점을 복원했다. 샘플에는 실제 계정 기록을 섞지 않는다.
7. KR/EN에 같은 저장·오류·재시도·비교 흐름을 적용했다.

## 검증

로컬 최종 검증: `npm run test:all` 496개 파일·4,168개 테스트 통과, 선택적 DB 통합 테스트 2개는 로컬 DB 미설정으로 제외. `npm run lint`, `npm run build` 통과. 관련 브라우저 7개 스펙의 기존 흐름 48개 통과 후, 새 저장 실패 테스트의 모달 접근성 선택자를 보정하여 영향받은 3개 스펙 20개 통과(기기 크기별 제외 2개). 설정 복원은 태블릿·데스크톱 각 3회, 총 6회 추가 통과. 전체 브라우저 및 PostgreSQL 통합 검사는 PR CI에서 확인한다. 실제 저장 실패를 브라우저에서 주입하여 초안 유지 → 같은 입력으로 재시도 → 새로고침 후 보관값 복원까지 검사한다. 단순 메모리 상태 테스트만으로 저장 성공을 판단하지 않는다.
