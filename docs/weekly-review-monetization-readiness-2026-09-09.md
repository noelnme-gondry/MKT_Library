## 수익화로 이어가기

후속 구현과 운영 기준은 [주간 리뷰 개선 실행안](weekly-review-improvement-operations-2026-09-09.md)에 정리했다. 실제 본문 CTA와 주간 업로드·완료·내보내기 계측을 연결하며, 실사용 자료가 필요한 검증과 결제 정책 결정은 별도 조건으로 남긴다.

**판매할 가치는 추가 통계 도구 수가 아니라 매주 끝나는 업무다.** 사용자는 같은 매핑·KPI로 다시 분석하고, 지난 결정을 확인하고, 이번 결정을 저장한 뒤 팀에 보낼 보고서를 얻는다. V1의 프로젝트 1개·저장 집계·보고서·캘린더가 이 반복을 만든다.

구매 버튼보다 먼저 확인할 것은 다음 세 가지다.

| 확인할 질문 | 현재 반영 | 다음 실측과 판단 |
|---|---|---|
| 첫 보고서까지 도달하는가? | 실제 CSV 업로드→결론→보고서 경로, `weekly_review_completed` | 실사용 CSV 완료율·완료까지 시간 측정. 데모와 분리 |
| 다음 기간에도 다시 쓰는가? | exact-period 저장 집계 fallback, 프로젝트·매핑 유지 | `data_continuity=saved_snapshot` 완료 건수와 사용자 인터뷰. 단순 reload 이벤트를 재방문 사용자 수로 오인하지 않음 |
| 보고서가 실제 업무를 줄이는가? | `weekly_review_export`(clipboard/print), `weekly_decision_saved` | 복사/인쇄 시도와 실제 활용을 구분하여 인터뷰. 인쇄 버튼 클릭은 PDF 저장 완료가 아님 |

이벤트에는 파일명·프로젝트명·캠페인명·지표값을 넣지 않는다. dedupe 키는 브라우저 메모리의 해시이며 서버 payload가 아니다. 기기 밖 계정 연결 없이 사람 단위 장기 유지율을 정확히 측정했다고 주장하지 않는다.

**추가 분석 도구 도입:** V1에는 신규 엔진을 더 붙이지 않는다. PVM 분해는 기존 엔진을 재사용하며, ROAS·전환량 변화에 CPA 분해를 끼워 넣지 않는다. 소재·예산·MMM·구성 변화 연결은 실제 주간 작업에서 반복되는 질문이 확인될 때 기존 도구로 확장한다. 지금 `enabled:false`인 라우터 신호는 제공 기능으로 홍보하지 않는다.

**분석 품질을 높일 다음 작업:** 동의받은 실제 캠페인 데이터로 5%·z 1.5·30전환 기준의 오탐/미탐을 검토한다. 원본은 브라우저에서만 처리하고 결과는 사용자와 확인한다. 집계 기간·귀속 지연·전환 정의가 다른 데이터를 섞지 않는다. 임계값을 통계적 유의성이나 효과 없음의 증거로 바꾸지 않는다.

**블로그 개선:** 대량 발행보다 기존 글→맞는 도구→주간 리뷰 완주를 우선한다. #811의 검색 제목/H1 분리는 유지하면서 파싱된 실제 결과까지 검사한다. 실제 본문 인바운드 0 글을 보완하고 진단 글 KO/EN에 주간 리뷰 CTA를 넣었다. 검색 노출·CTR·쿼리 이동은 Search Console의 변경 전후 자료 없이는 실측할 수 없다. 추후 노출 많은 진단·예산·보고 업무 쿼리부터 CTA 노출→클릭→실제 분석 완료를 비교한다.

**구매·라이선스 다음 단계:** 붙여넣은 논의의 월 5,900원/연 59,000원은 가격 가설이며 확정 상품이 아니다. 판매 범위, 결제 사업자, 가격, 환불·취소 정책, 라이선스 검증·분실 복구·오프라인 유예를 확정한 다음 별도 구현한다. 결제나 라이선스 검증이 생기더라도 캠페인 CSV와 분석 결과는 그 서버로 보내지 않는다. 이번 PR에는 가짜 결제 링크·동작하지 않는 유료 약속을 넣지 않았다.
