# 운영 플래너 액션 루프 — 구현·검증 메모

2026-11-04 · `codex/operations-action-loop` · 내부 구현 기록

## 변경 전 → 변경 후

선택한 최근/직전 기간의 결과와 예산 표를 읽고 다른 화면에 결정을 남기던 흐름을, 운영 플래너 안에서 **변화 확인 → 액션 결정 → 실제 실행 기록 → 전후 관측 → 후속 액션**으로 연결했다.

| 사용자 요구 | 구현 위치·동작 |
| --- | --- |
| 비교 문제부터 수정 | `planSnapshot.js`에 통화·국가·채널·OS·일별 집계 조건 보존. `planReview.js`에서 조건 불일치·날짜 누락·숫자 누락은 비교 보류. `allocationActions.js`는 동일 모형의 유지안과 조정안을 비교하고, 이동이 없으면 배분 효과를 만들지 않음. |
| 직접 저장한 액션과 관측 변화 모두 확인 | `changeHistory.js`의 전체 기간 탐색과 기존 결정 기록을 `OperationsActionLoop.jsx` 타임라인에 통합. 출처와 계획/실행 상태 구분. 최근/직전 날짜 선택은 탐색 범위를 자르지 않음. 국가·채널·OS 대상 필터는 유지. |
| 한곳에서 명료하게 전달 | 첫 화면은 예산·소재 액션과 다음 검토. 전체 이력과 상세 표·차트는 같은 화면의 별도 탭. 기존 상세 근거·다운로드 진입 유지. |
| 소재 효과 수치 예측 금지 | 공개 예산 예측에서 소재 추가·종료·피로 가정을 제외. 소재는 피로·부진 신호와 확인/교체 액션만 제공. CPRR 근거는 관측 mix/rate와 지출–단가 추세 모형. 기존 수학 엔진·골든값은 수정하지 않음. |
| 실행 이력과 다음 검토 연결 | `OperationsActionEditor.jsx`, `operationLoop.js`, `actionContract.js`: 예산/소재 추가·교체·종료/관찰, 실제 실행일, 전후 예산, 기존·교체 소재, 메모, 검토 일수 저장. 실행일 기준으로 검토일 재계산. 관측 기록은 기존 episode와 durable commit 사용. 후속 액션은 부모 기록에 연결. |

## 판정 범위

- 전체 기간의 각 지점을 탐색한다. 비용·단가 후보는 전후 각 7일의 관측이 모두 있는 지점에서 20% 이상 변화할 때 표시한다. 같은 유형의 후보는 7일 간격으로 묶는다. 최근 14일로 제한하지 않지만 모든 일별 흔들림을 변화로 표시하지도 않는다.
- `daily_budget`가 있으면 연속 관측일의 설정 변경을 별도로 표시한다. 관측 지출을 설정 예산으로 단정하지 않는다. 제안에서 액션을 만들 때 변경 전 설정 예산은 사용자가 확인해서 입력한다.
- 소재 첫 지출·3일 연속 지출 미관측·재관측은 관측 사실이다. 실제 투입/종료를 확정하지 않으며 캠페인 자체의 날짜 공백은 소재 종료 근거로 쓰지 않는다.
- 검토는 저장한 동일 대상·성과 기준·통화의 전후 매일 관측을 요구한다. 누락값을 0으로 채우지 않는다. 캠페인 ID를 우선 사용하며 이름 변경이나 같은 이름의 다른 국가·OS를 합치지 않는다.
- 증액 뒤 비용과 단가가 함께 악화하고 이전 설정 예산이 확인된 경우 감액 재검토 액션을 제시한다. 인과관계나 감액 효과를 확정하지 않는다. 소재 액션에도 전후 관측을 보여주지만 해당 액션의 CPRR 효과로 명명하지 않는다.
- 이전 형식의 예산 기록은 비교 조건이 없으므로 보존하되 자동 비교하지 않는다. 운영 액션은 광고 계정을 변경하지 않으며, 검토 알림은 데이터 재분석과 화면 재방문 시 표시한다.
- CSV는 브라우저 메모리에서 분석한다. 액션 메타데이터만 기존 기기 저장 계약을 사용한다. 분석 무료/액션 저장 Pro·로그인·기기 저장 조건과 데모 저장 제한은 유지한다.

## 화면 검토

목적은 첫 화면에서 할 일과 다음 검토를 읽고, 필요할 때 같은 화면 안에서 근거를 확인하게 하는 것이다. 기존 공용 셸·탭·모달·숫자 입력·차트 테마를 재사용했다. 제목·본문을 같은 면에 두고, 작은 폭에서는 입력과 액션 행을 한 열로 쌓는다.

| 실제 확인 범위 | 확인 내용 |
| --- | --- |
| KO · 다크 · 1440px | 기본 액션, 전체 이력, 대상별 예산 제안 및 근거 진입 |
| KO · 다크 · 980px | 관측 비교 모달, 전후 기간·mix/rate 배치 |
| KO · 다크 · 320px | 액션 입력 모달의 세로 스크롤·가로 잘림 |
| EN · 라이트 · 320px | 긴 라벨 줄바꿈, 탭·액션 쌓임, 흰 콘텐츠 면 |
| EN · 다크 · 1440px | 지출–단가 산점도와 추세선, 공용 테마 적용 |

다크 모드에서 페이지 배경과 주요 면의 계산된 색상을 확인했다. 산점도의 기존 공용 index 툴팁이 서로 다른 x값을 같은 행으로 묶는 문제를 발견해 nearest 방식으로 분리하고 회귀 테스트를 추가했다. 최종 production 빌드에서도 예시 98일 전체 범위와 변화 후보 18건이 표시되는 것을 확인했다.

## HTML 디자인 시안

사용자 요청에 따라 앱 구현과 별개로 단일 HTML 시안을 제작했다. 현재 액션 카드들은 대상별 제안과 검토 근거를 따로 찾아야 한다. 시안은 액션 목록과 선택한 액션의 근거를 같은 작업 면에 두고, 실행 기록·다음 검토를 바로 아래에 연결한다. 전체 변화는 날짜 전체를 유지한 타임라인으로, 상세 분석은 별도 보기로 보존한다.

설계: 현재 제품의 밝은 페이지 `#eef2f7`, 흰 면 `#ffffff`, 본문 `#172232`, 보조 글자 `#53647a`, 행동 파랑 `#2b64d8`을 사용한다. Wanted Sans의 기존 크기 토큰과 400/600/700 굵기, tabular 숫자 정렬을 따른다. 동일한 요약 카드 반복 대신 선택 목록–근거–행동 관계를 중심으로 배치한다. 사이드바·상단 문맥·주 콘텐츠 가장자리를 정렬하고 좁은 폭에서는 근거를 선택 목록 아래로 잇는다.

목적 → 먼저 검토할 대상을 고른다. 핵심 질문 → 왜 이 액션이 필요한가, 무엇을 기록하고 언제 다시 볼 것인가. 근거 → 전후 관측, 소재 피로 신호, 동일 모형의 예산안. 주 행동 → 계획/실행/검토 기록. 보조 행동 → 전체 이력과 산점도 확인. 수치는 가상 데이터와 기존 엔진 출력이며, 소재 신호를 보여 주기 위해 가상 TikTok의 클릭·노출 추세만 조정한다. 실제 데이터나 저장 계정을 사용하지 않는다. 시안 조작은 현재 창 메모리에만 남긴다.

시안 검증: KO/라이트 1440px의 액션–근거 배치, KO/라이트 980px의 분해·산점도, EN/다크 320px의 긴 문구와 액션 입력창, KO/라이트 320px의 근거 화면을 실제 렌더로 확인했다. 좁은 화면의 문서 가로 넘침 없음, 모달 내부 잘림 없음, 탭 ARIA 소유 관계 정상, 중복 ID 없음. 본문과 흰 콘텐츠 면의 실제 계산 색상을 확인했다. 지출 증감은 중립색, CTR 하락은 악화색으로 구분한다.

직접 조작 검증: 소재 교체 계획 기록 → 실행일 10.05 입력 → 검토일 10.12 반영, 직접 예산 기록의 음수 거부·콤마 금액 처리, 9.29 실행 기록의 전후 비교·검토 메모 저장, 직접 기록 필터, 캠페인 선택·추세 슬라이더를 확인했다. 검토 비교는 시안 가상 데이터에 기존 엔진으로 계산한 7/14/28일 결과를 사용한다. 인라인 JavaScript 구문 검사 통과, 브라우저 오류 로그 없음. 폰트·라이선스·데이터가 포함된 단일 HTML로 전달한다. 앱 소스 변경이 없는 별도 시안이므로 전체 앱 테스트·빌드는 재실행하지 않았다. 앱 반영·운영 배포는 하지 않았다.

### 여러 실행 후 검토가 쌓이는 경우

사용자 지적: 첫 시안은 검토 1건을 상단 액션으로 고정하고 하단 실행 기록 2건을 따로 보여 주었다. 검토가 많아지면 같은 기록이 두 곳에 나타나고, 어느 목록에서 처리해야 하는지 모호해진다.

수정: 하단 실행 기록 표를 제거하고, 실행별 기록과 새 제안을 하나의 선택 목록–상세 작업 면으로 통합했다. ‘검토할 결과 / 새 액션 / 진행 중 / 완료’의 건수는 실제 시안 상태에서 파생한다. 가상 예시는 검토 6건·진행 중 3건·완료 1건과 새 제안 2건으로 구성했다. 검토일이 오래된 건부터 정렬하고 캠페인 필터와 5건 단위 페이지 이동을 제공한다. 좁은 화면은 목록 높이를 제한하며 선택 후 상세로 포커스와 스크롤을 옮긴다.

기존 정보 보존: 실행별 대상·액션·실제 실행일·다음 검토일·전후 관측·mix/rate는 상세에 둔다. 검토 기록을 저장하면 그 기록만 완료로 이동하고 다음 미처리 기록을 선택한다. 완료 메모에서 후속 계획을 만들고 이전 검토로 돌아갈 수 있다. 전체 기간 변화 이력과 예산/소재 제안, 산점도 보기는 유지한다. 검토일이 지나도 전후 관측이 부족하면 ‘데이터 확인 필요’로 남기며 검토 저장을 열지 않는다.

확인: 실제 브라우저에서 6→5건 이동과 메모 보존, 6건 전부 처리 후 빈 상태, 마지막 페이지 처리 후 페이지 보정, 완료→후속 계획→실행→관측 대기, 캠페인 필터별 건수, 새 액션 상세를 검증했다. KO/라이트 1440px, EN/다크 980px, KO/라이트·EN/다크 320px에서 실제 배치를 검토했다. 320px 문서·상세 가로 넘침 없음, 선택 후 상세 포커스 정상, 중복 ID 없음, ARIA 제어 대상 존재, 브라우저 경고/오류 없음. 인라인 JavaScript 구문 검사와 git diff 공백 검사 통과. 이번 수정은 독립 HTML과 이 설계 메모에 한정하므로 앱 전체 테스트·빌드를 다시 실행하지 않았다. 실제 앱 적용·배포는 이번 수정 범위에 포함하지 않았다.

계산 진단: Meta 리타겟팅의 전체 관측은 98일이나 자동 구간 선택은 09.29–10.06이다. 이전 90일과 구간 내 특이값 1일을 제외한 7일로 2차식을 적합했다. 기존 시안은 전체 관측 최저 지출까지 `predictSafeCpr`를 확장했고, 이 함수의 꼭짓점·관측 범위 보정으로 평평한 선이 생겼다. 확인한 값: 적합 범위 148,143–267,093원, 지출 160,786.835원에서 원모형 3,606.0189876원과 보정값 3,558.6505691원. 값을 맞추려고 엔진이나 관측점을 변경하지 않는다.

코멘트 반영 결과: 상태별 목록을 액션 종류의 실제 제목으로 묶었다. ‘결과 검토’ 그룹명은 과거 실행 기록과 새 액션을 혼동하지 않게 한다. 그룹 안의 검토일 정렬을 유지하며 캠페인 필터·저장·후속 액션은 기존 상태를 사용한다. 한 페이지(8건 이하)에서는 페이지 영역 전체를 없애고, 여러 페이지에만 ‘전체 9건 중 1–8번째 / 전체 9건 중 9번째’처럼 읽을 수 있는 표시를 쓴다. 데스크톱은 페이지 내 그룹을 모두 펼치고, 모바일은 스크롤 가능한 목록을 표시한다.

산점도는 원모형의 예측을 적합 관측 최소–최대 지출 사이에서 그린다. 기본은 실제 계산에 쓴 점과 제외된 특이값이며, 이전 구간은 ‘이전 관측도 함께 보기’로 같은 축에 추가한다. 실제 적합 관측은 채운 원, 이전 구간은 빈 원, 제외 관측은 ×로 구분한다. 기간·관측 수·제외 수는 실제 모형에서 파생한다. 슬라이더의 원모형 예측과 예산 계산용 보정값이 다르면 금액과 보정 의미를 따로 설명한다. 관측이나 기존 배분안은 수정하지 않았다. SVG는 실제 컨테이너 크기에 맞춰 다시 그려 모바일에서도 눈금과 선택 값의 글자 크기를 보존한다.

검증 결과: 별도 시안 검사 11건 통과. 수정 전 산점도가 적합 범위·원모형 예측 계약에서 실패함을 확인한 뒤, 네 캠페인의 선과 원모형 식을 대조했다. 이전/이후의 관측 행·배분안·전후 비교·분해 수치 동일성, 적합/이전/제외 날짜의 전체 관측 분할, 그룹별 건수와 연속 배치, 한 페이지 탐색 제거, 15건의 페이지 분할·선택, 완료 이동, 한영의 전문 용어 제거, 7+90+1점 표시, 마지막 1건의 범위 문구를 확인했다.

### 승인 시안의 앱 반영 및 홈 진입 (2026-11-04)

이전 절의 HTML 전용 단계 이후 사용자 요청에 따라 실제 앱에 반영했다. 액션 그룹 제목이 개별 검토 행과 비슷했던 문제는 색이 있는 구분선·옅은 배경·제목 크기·그룹 간 간격으로 해결했다. 시안의 제목은 16px, 앱은 기존 글자·굵기 토큰을 사용한다.

- `OperationsActionQueue`는 상태 선택, 대상 필터, 액션 종류별 목록과 선택 상세를 하나로 묶는다. 아래쪽의 별도 실행 표는 제거했다. 8건 이하는 페이지 표시가 없고 여러 페이지면 전체 건수와 현재 범위를 설명한다. 누락된 관측·통화/성과 기준 불일치는 검토를 열지 않는다. 모바일은 선택한 상세와 목록으로 포커스·스크롤을 옮긴다.
- 실제 계정 기록을 가상 데모 데이터와 비교하지 않는다. 저장은 기존 프로젝트 commit 경로와 Pro·로그인·기기 저장 조건을 따른다. 검토 한 건 완료, 후속 액션의 부모 연결, 실행일 기준 검토일 재계산은 실제 상태 연결 테스트로 확인했다.
- `OperationsCharts`도 원모형 예측과 적합 관측 범위로 수정했다. 리타겟팅은 사용 7개·이전 90개·제외 1개이며, 지출 하한에서 적합 CPI 3,657원과 예산 보정값 3,559원을 구분한다. 기존 예산 계산과 수학 엔진의 골든값은 유지했다. 분해 라벨과 설명은 한영에서 성과 비중·성과당 비용으로 교체했다.
- 홈은 기존 상황 선택·파일 업로드를 보존한다. 현재 프로젝트에 저장한 운영 액션이 있으면 상단에 검토 예정·진행 건수와 ‘플래너에서 이어가기’를 표시한다. 기존 일반 결정 요약에서는 같은 운영 기록을 제외해 중복을 없앴다. 공개 예시는 ‘운영 액션’을 기본 탭으로 하고, 실제 가상 데이터 계산값·전체 98일 범위·예시 진입을 보여 준다. 예시 제안이 없는 소재 액션을 임의로 만들어 내지 않는다.

검증: `npm run test:all` 630개 파일 통과·1개 건너뜀, 테스트 5,830개 통과·4개 건너뜀. 첫 전체 검사에서 새 CSS 굵기와 breakpoint 2건이 규칙을 벗어나 실패했으며, 기존 토큰·경계값으로 고친 뒤 전체 통과했다. 이후 홈 중복 방지·4탭 레이아웃·모형 없는 산점도 표시를 보완하고 관련 45개 검사 및 수정 파일 lint를 통과했다. 전체 lint와 배포 build(374페이지 생성) 통과. 새 목록 검사는 KO/EN 6건 중 특정 1건만 완료 이동, 17건 페이지 순회, 관측 부족 비활성, 날짜·상태 분리, 범위·보정값과 원모형의 차이를 확인한다. 홈 요약의 실제 건수·로케일 경로·빈 상태를 별도 테스트했다.

실제 화면: 앱 KO/다크 1440px·320px, EN/라이트 320px, 홈 EN/라이트 980px·320px, KO/라이트 1440px를 검토했다. 액션 선택·상세 포커스, 대상 선택, 이전 관측 토글, 슬라이더 양 끝, 4탭의 1행/2행 전환을 확인했다. 모바일 가로 넘침과 깨진 ARIA 연결 없음, 확인한 브라우저 오류·경고 없음. HTML 시안의 그룹 제목도 실제 배경·16px·3px 구분선을 확인했다. 실제 계정의 Pro 저장·유료 다운로드는 미검증이며, 저장 경계는 테스트 대역으로 검증했다. 운영 배포 상태는 PR 머지 뒤 별도로 확인한다.

머지 전 보강: 기존 보고서 바로가기 기반 E2E를 액션·이력·근거 탭과 홈 4탭으로 전환했다. 계획 저장 → 실제 실행 → 전후 검토 저장 → 후속 액션 → 홈 이어가기를 검증한다. 기간 변경 후 근거 탭이 닫히는 현상을 재현 테스트 실패로 확인하고, 탭 선택 상태를 계산 결과 바깥에 보관하도록 수정했다. 수정 후 플래너 스모크 17개와 수정 파일 lint 통과, 실제 브라우저에서 7일 → 14일 변경 후 근거 탭 유지 확인. 그룹 제목은 옅은 바탕과 굵은 아래 구분선으로 표시한다.
