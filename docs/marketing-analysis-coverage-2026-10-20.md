# 마케팅 분석 범위와 확장 기준 — 2026-10-20

## 반영 범위

마케팅 분석을 찾는 진입점을 기존 `/guide`·`/en/guide`에 추가했다. 운영 SOP를 유지하면서 측정, 성과, 검색 광고/스토어, 소재, 전환 경로, 리텐션, 고객 가치, CRM, 실험, 증분, 미디어 믹스, 예산/예측, 브랜드, SEO/AI 검색, 시장/가격, B2B, 도달/품질, 커머스를 탐색한다.

분야·방법·참고 자료의 정본은 `v2-migration/src/lib/marketingAnalysisLibrary.js`다. 이번 검토 기준 18개 분야, 38개 방법, 30개 1차 자료를 연결했다. 방법 카드는 실행 도구 연결 18개, 내부 가이드 5개, 외부 참고 자료 15개이며, 연결된 **고유 실행 도구는 기존 공개 도구 22개**다. 방법 수는 제품 도구 수가 아니다.

각 카드에는 실무 질문, 필요한 관측 단위와 데이터, 해석 한계, 내부 글, 해당하는 실행 도구와 방법 문헌을 넣었다. 검색어·분야·제공 범위 필터는 브라우저 내부 상태만 사용한다. 원본 고객 데이터나 검색어의 전송·저장은 추가하지 않았다.

## 기존 구현과 대조한 결과

- A/B에는 표본 설계·SRM·선택 동등성·O’Brien–Fleming 중간 판독 계획이 이미 있다. CUPED나 임의 중단에 대한 always-valid 판독 엔진이 있다는 뜻은 아니다. `AbTestHoldout.jsx`, `experimentQuality.js`, `sequentialTest.js`까지 확인했다.
- MMM에는 여러 추정·검증·지역 처리 경로가 이미 있다. 이를 Google Meridian 또는 Meta GeoLift의 동일 구현으로 소개하지 않는다. GeoLift의 시장 선택·검정력·합성 통제 실험은 별도 요구사항이다.
- 멀티터치 맵은 관측된 AppsFlyer contributor와 귀속 설치를 연결한다. 완전한 사용자 여정, Shapley/Markov 귀속 배분이나 인과 기여도 엔진으로 소개하지 않는다.
- Aha는 전환 전 행동과 이후 결과의 연관 후보다. 개인별 처치 효과를 추정하는 CRM 업리프트와 구분한다.
- 생존 도구의 중도절단 처리, 집계 코호트와 사용자 순서 퍼널, 관측 가치와 예측 CLV를 구분한다. 비슷한 도구로 갈 수 있다는 이유만으로 미구현 방법에 실행 링크를 붙이지 않는다.
- 네이버·Google·다른 AI 서비스의 측정 범위를 동일하다고 가정하지 않는다. 특히 Google의 2026-06-03 [생성형 AI 노출 보고서 발표](https://developers.google.com/search/blog/2026/06/gen-ai-performance-reports)는 2026-08-31 전체 사이트 제공으로 갱신돼 있다. 전용 노출 보고서가 없다는 오래된 안내를 재사용하지 않았으며, 노출·인용·클릭·전환을 구분했다. 실제 이 서비스의 계정 데이터 수신은 이번 검토 대상이 아니다.

## 추가 엔진의 구현 우선순위

## 참고 자료 검토 원칙

문헌은 개념·가정·설계를 설명하는 자료다. 참고 문헌을 연결했다고 동일한 알고리즘·성능·인과 식별을 제품에 보장하지 않는다. 문헌의 제목·URL·확인일은 지도 정본에서 관리하며 목록을 이 문서에 다시 복사하지 않는다.

- 실험: Microsoft Research의 SRM·CUPED, O’Brien–Fleming 원논문, Johari 등의 always-valid inference.
- 인과·미디어: Google Meridian의 인과 가정·mROI, Meta GeoLift의 시장 선택·검정력, Google lift studies.
- 고객·전환: GA4 퍼널·코호트 정의, NIST Kaplan–Meier, Fader/Hardie 고객가치 모형, CRAN RFM, Uber CausalML.
- 시장·채널: Apple AdAttributionKit·ASA·스토어 지표, AppsFlyer 원본 계약, Pew 설문 설계, Sawtooth 선택 실험, HubSpot 단계 퍼널.
- 검증·검색: Hyndman/ Athanasopoulos의 시간순 예측 검증, Search Console·생성형 AI 노출 공식 문서.

## 검증 기록

정본 파생 검사로 공개 도구 전체 연결·KO/EN 대응·내부 글 실존·출처 키·고유 앵커를 확인했다. 실제 가이드 렌더, 검색·필터·초기화·미지원 방법의 상태와 서버 HTML을 검사하고, 브라우저에서 키보드 펼치기·도구 진입·320px/다크/라이트 접근성을 확인했다.

- `npm run test:all -- --maxWorkers=2`: PostgreSQL 통합 검사를 포함해 599개 파일, 5,336개 테스트 통과. 최초 검사에서 발견한 CSS 반경 토큰 위반을 수정한 뒤 전체 재검사했다.
- `npm run lint`, `npm run build`, `git diff --check`: 통과.
- Chromium: 새 지도와 초기 HTML·번들 상한 검사 통과. WebKit·Firefox는 각각 KO/EN 사용자 흐름과 서버 HTML 3개 검사 통과.
- 새 지도의 axe 접근성 검사에서 위반 0, 320px 가로 넘침 0. 실제 사용자 기기의 육안 확인을 대신하지 않는다.
- 출처 30개 중 직접 HTTP 확인은 27개 200 응답이었다. Microsoft Research 2개는 403, PubMed 1개는 자동 접근 확인 페이지를 반환했다. 이 3개의 원문 내용은 웹 검색/열람 도구로 별도 대조했으며 직접 HTTP 검사 통과로 세지 않았다.
- 검증 로그는 `.local-data/verification-20261020/analysis-library/`에 보관한다. Playwright가 비우는 기본 출력 폴더와 분리하며 커밋하지 않는다.
