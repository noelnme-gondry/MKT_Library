# 2026-09-21 UX·계정 매핑·감사 후속 조치

기준: `origin/main` efaaa4b1. 사용자 제공 `daily-audit-2026-09-20.md`의 주장을 코드·재현 테스트·공식 결제 명세와 대조했다. 운영 DB나 실제 거래를 변경한 검증은 포함하지 않는다.

## 사용자 경험 변경

- 튜토리얼 버튼의 스크롤 감지·위치 탐색·일시 숨김을 제거했다. 고정 위치를 유지하고 실제 모달·입력 상태에서만 가린다.
- 공개 화면의 `<details>/<summary>` 아코디언을 제거했다. 설명과 근거는 본문, 짧은 도움말은 마우스·터치·키보드 팝오버, 결정·데이터 수정은 별도 편집창으로 옮겼다. 무거운 분석 선택은 탭으로 유지한다.
- 분석 완료 후 대시보드는 결과부터 보여준다. 매핑 설정을 수정할 때만 편집창을 열고, 변경 후 다시 분석한다.
- 결제수단을 카드형 선택지로 바꾸고 처리 중 중복 진입을 막았다. 모든 수단의 실제 사용 가능 여부는 상점 계약·환경 설정을 따른다.
- 공개 비밀번호 로그인 폼을 제거했다. Google 로그인 및 기존 계정용 이메일 링크는 유지한다.
- 보고서 브랜딩의 용도·저장 범위·출력 미리보기를 추가했다. 계정 보관 미리보기에는 내부 JSON 대신 결정·목표·근거·관측 이력을 표시한다.
- 한국어·영어에 동일하게 반영했다. 누락되어 있던 영문 마이페이지 진입도 복구했다.

## Pro 계정 컬럼 매핑

- 마이페이지에서 컬럼 이름과 표준 필드 연결만 저장·삭제·가져오기·내보내기 한다. CSV 헤더 가져오기도 브라우저에서 처리한다.
- 계정 소유자별 최대 200개 규칙을 보관한다. Pro 권한은 서버에서 검증하며 만료 후에도 조회·삭제할 수 있다.
- CSV·XLSX·Google Sheets 공통 입력 경로에서 계정 규칙을 가져온다. 해당 도구에서 쓰는 필드에만 적용하고 모호한 중복 연결은 건너뛴다. 자동 매핑과 충돌하면 의미 매핑과 실제 계산용 매핑을 함께 교체한다.
- CSV 행·셀 값·파일명은 매핑 API로 보내지 않는다. 개인정보처리방침과 Pro 기능표를 함께 갱신했다.
- 기존 기기 규칙은 사용자가 명시적으로 가져올 수 있다. 자동으로 계정에 업로드하지 않는다.

## NICEPAY 공식 명세 확인

- 망취소 요청은 `orderId`가 맞다. [취소 API](https://raw.githubusercontent.com/nicepayments/nicepay-manual/main/api/cancel.md)
- 네이버페이 카드 요청은 `naverpayCard`, 통보의 `payMethod`는 `naverpay` 체계다. [결제창](https://github.com/nicepayments/nicepay-manual/blob/main/api/payment-window-server.md), [웹훅](https://raw.githubusercontent.com/nicepayments/nicepay-manual/main/api/hook.md)
- 웹훅 본문은 JSON이다. 브라우저 반환의 폼 형식과 다르므로 JSON 수신은 유지한다. 성공 응답은 공식 요구에 맞춰 HTTP 200, 본문 `OK`, `text/html`로 수정했다. 통보 내용만 믿고 이용권을 부여하지 않고 공급자 조회 결과로 검증하는 기존 경로를 유지한다.
- 운영 상점의 실제 취소·가상계좌 입금·간편결제 통보는 별도 실거래 검증 대상이다. 이 문서는 이를 완료했다고 주장하지 않는다.

## 전체 브라우저 검사에서 추가 확인한 회귀

- 펼친 분석 범위가 결과 카드의 제목 열을 0px로 밀었다. 제목 아래 독립 영역으로 배치해 한국어·영어 보고서 예제에서 제목과 실제 수치를 확인했다.
- Linux 브라우저에서 입력창→추가 버튼으로 포커스가 옮겨갈 때 튜토리얼이 다시 나타나 mouseup을 가로챘다. 폼·필드셋 작업 동안 숨김을 유지하고 포인터 누름→버튼 포커스→해제 순서로 회귀 검사한다. 스크롤 위치 추적은 재도입하지 않는다.
- 홈 사이드바 검색 문구·단축키가 테마의 대비 기준을 어겼다. 공용 테마 색상으로 교체했다.
- ASA 입력의 이벤트 연결 전에 값을 입력하면 빈 설정이 저장될 수 있었다. 연결 완료까지 입력을 비활성화하고 서버 렌더 검사 및 저장·복원 35회 반복 검사로 검증했다.
- 리뷰 편집창을 닫은 뒤 공유·다운로드로 이동하는 실제 경로에 맞춰 브라우저 검사를 갱신했다.

## Railway 반영

새 환경 변수는 필요 없다. 기존 계정·결제 PostgreSQL 연결을 사용한다. 시작 마이그레이션에 `scripts/account-mappings.sql`을 추가했다. 로컬에서 `ignore-scripts=true`일 때 prestart가 생략됨을 확인하여, `npm start` 명령이 마이그레이션을 직접 실행한 뒤 서버를 켜도록 바꿨다. 배포 시 `gop_account_mappings`가 생성되어야 한다. 운영 배포 로그와 다른 기기 로그인 후 규칙 재조회는 배포 후 확인 대상이다.

## AI·크롤러 대응 판단

이번 변경에서는 크롤러를 일괄 차단하지 않았다. 싱가포르 유입 수나 국가만으로 봇 여부를 판정할 수 없으며, 운영 요청 로그·요청 빈도·경로·응답 시간은 아직 확인하지 않았다.

1. Railway/프록시 로그에서 요청 경로·빈도·상태 코드·User-Agent·응답 시간과 비용을 먼저 비교한다. 인증 토큰·결제 본문·업로드 데이터는 수집하지 않는다.
2. 과도한 반복 요청이 확인되면 경로별 제한·WAF를 적용한다. 결제 웹훅과 OAuth 반환 경로를 일반 방문자 챌린지에 넣지 않는다. 검색 크롤러는 검증된 식별 방법을 사용한다.
3. 학습용 수집 거부와 검색 유입 유지 여부는 따로 결정한다. `GPTBot`과 `OAI-SearchBot`은 목적이 다르고 별도로 제어할 수 있다. [OpenAI 봇 문서](https://developers.openai.com/api/docs/bots)
4. `Google-Extended` 차단이 Google 검색 순위·포함 여부에 영향을 주지는 않지만 Gemini·Vertex의 그라운딩 사용에도 적용된다. 따라서 “학습만 차단하므로 모든 AI 검색 노출에 영향 없음”이라고 말할 수 없다. Google 검색 AI 기능은 Googlebot 제어를 따른다. [Google 크롤러](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers), [검색 AI 기능](https://developers.google.com/search/docs/appearance/ai-features)
5. robots.txt는 협조하는 크롤러의 수집 지침이며 공격·비협조 봇의 접근 방어가 아니다. 서버 렌더 비용은 접근 로그를 확인한 뒤 정적 생성·캐시 후보별로 측정한다.
