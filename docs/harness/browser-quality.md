# 브라우저 품질 하네스

> 읽는 시점: 화면 계층, 핵심 사용자 경로, 반응형, 접근성, sticky 구조를 변경할 때

## 목적

Vitest는 계산과 렌더 분기를 지키고, Playwright는 **사용자가 실제 브라우저에서 과업을 끝낼 수 있는지** 지킨다. 스크린샷의 모양을 무차별 고정하지 않고, 맥락 → 판단 → 결론 → 주 행동의 계층과 연결을 검사한다.

## 대표 경로

1. `/start` → 실제 효율 CSV → 운영 대시보드 결과
2. `/tools/aso-store-conversion` → 실제 App Store Connect 형식 CSV → 판정
3. 운영 대시보드 결과 → 결정 저장 → `/weekly-review`

대표 fixture에는 기밀값을 넣지 않는다. 실제 플랫폼의 헤더·형식만 보존한 합성 데이터여야 한다.

## 자동 계약

- 320×800, 768×1024, 1440×1000에서 같은 과업을 끝낸다.
- `main`의 `h1`은 하나다.
- 문서 전체에 가로 스크롤이 생기지 않는다.
- 같은 위치의 sticky 객체끼리 겹치지 않는다.
- 현재 판단 영역의 primary action은 하나다.
- 첫 Tab 대상은 화면 안에 있고 2px 이상의 focus outline을 가진다.
- 핵심 상태에서 axe serious/critical 위반이 없다.
- 다크 모드를 기본으로 실행한다. 테마 자체의 CSS 계약은 기존 Vitest 가드가 별도로 검사한다.

## 실행

```bash
cd v2-migration
npx playwright install chromium
npm run test:e2e
```

실패 시 `playwright-report/`와 `test-results/`의 trace·실패 스크린샷만 확인한다. 기준 이미지를 대량 저장하거나 사람이 이미 확인한 화면을 반복 캡처하지 않는다.

## 변경 시 규칙

- 접근 가능한 이름과 역할로 요소를 찾는다. 불가피한 경우 안정적인 구조 클래스나 `data-*`를 쓴다.
- 문구 전체를 고정하지 말고 사용자가 인식하는 행동 이름과 결과 상태를 고정한다.
- 새 대표 경로는 기존 세 경로로 잡히지 않는 상태 전이 또는 데이터 계약이 있을 때만 추가한다.
- E2E 실패를 감추기 위해 대기 시간을 늘리지 않는다. 상태 또는 접근 가능한 결과를 기다린다.
- 색상 대비는 브라우저별 계산 차이가 있어 axe 자동 검사에서 제외하며, 기존 파생 대비 테스트와 사람 검증을 유지한다.
