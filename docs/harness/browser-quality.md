# 브라우저 품질 하네스

> 읽는 시점: 화면 계층, 핵심 사용자 경로, 반응형, 접근성, sticky 구조를 변경할 때

## 목적

Vitest는 계산과 렌더 분기를 지키고, Playwright는 **사용자가 실제 브라우저에서 과업을 끝낼 수 있는지** 지킨다. 스크린샷의 모양을 무차별 고정하지 않고, 맥락 → 판단 → 결론 → 주 행동의 계층과 연결을 검사한다.

## 대표 경로

1. `/start` → 실제 효율 CSV → 운영 대시보드 결과
2. `/tools/aso-store-conversion` → 실제 App Store Connect 형식 CSV → 판정
3. 운영 대시보드 결과 → 결정 저장 → `/weekly-review`

대표 fixture에는 기밀값을 넣지 않는다. 실제 플랫폼의 헤더·형식만 보존한 합성 데이터여야 한다.

## 자동 계약

- 320×800, 768×1024, 1440×1000에서 같은 과업을 끝낸다.
- `main`의 `h1`은 하나다.
- 문서 전체에 가로 스크롤이 생기지 않는다.
- 같은 위치의 sticky 객체끼리 겹치지 않는다.
- 현재 판단 영역의 primary action은 하나다.
- 첫 Tab 대상은 화면 안에 있고 2px 이상의 focus outline을 가진다.
- 핵심 상태에서 axe serious/critical 위반이 없다.
- 다크 모드를 기본으로 실행한다. 테마 자체의 CSS 계약은 기존 Vitest 가드가 별도로 검사한다.

## 실행

검증 범위는 [AGENTS.md §6.1](../../AGENTS.md#61-구현-흐름-pr)을 따른다. 작은 스타일·카피·국소 수정은 관련 테스트·수정 파일 lint·필요한 화면 확인으로 종료한다. 기능 추가, 여러 영역에 걸친 동작 변경, 변경량이 많거나 영향 범위를 좁히기 어려운 큰 변경에만 전체 검사를 실행한다. 작업 마지막이라는 이유만으로 전체 검사나 build를 돌리지 않는다. 새 실패·미해결 위험이 생기면 그 영향 범위부터 재검사한다.

```bash
cd v2-migration
# 작업 브랜치와 미커밋 변경에 영향받는 Vitest 검사
npm run test:changed
# 파일의 정적 import 관계를 따라 관련 검사만 실행
npm run test:related -- src/components/LandingPage.jsx
# 화면은 수정 중 dev 서버로 대상 파일만 검사
npm run test:e2e -- e2e/marketing-analysis-hub.spec.js --project=desktop-1440
# 배포 산출물 확인이 필요한 변경을 빌드한 경우
E2E_SERVER=production npm run test:e2e -- e2e/marketing-analysis-hub.spec.js
```

`test:changed`의 기준은 작업 전에 fetch한 `origin/main`이다. CSS, 파일 시스템으로 읽는 콘텐츠, 동적 로딩은 import 추적만으로 영향 범위를 완전히 알 수 없다. 결과에 대상 검사가 포함됐는지 확인하고 해당 브라우저·콘텐츠 검사를 명시한다. 작은 변경의 완료 조건은 필요한 관련 검사의 통과이며, 전체 검사 생략을 미완료로 취급하지 않는다. CI 설정 변경 여부는 별도로 명시한다.

전체 사용자 경로에 영향을 주는 큰 변경의 브라우저 검사는 아래처럼 실행한다.

```bash
cd v2-migration
npx playwright install chromium
npm run test:e2e
```

실패 시 `playwright-report/`와 `test-results/`의 trace·실패 스크린샷만 확인한다. 기준 이미지를 대량 저장하거나 사람이 이미 확인한 화면을 반복 캡처하지 않는다.

## 변경 시 규칙

- 접근 가능한 이름과 역할로 요소를 찾는다. 불가피한 경우 안정적인 구조 클래스나 `data-*`를 쓴다.
- 문구 전체를 고정하지 말고 사용자가 인식하는 행동 이름과 결과 상태를 고정한다.
- 새 대표 경로는 기존 세 경로로 잡히지 않는 상태 전이 또는 데이터 계약이 있을 때만 추가한다.
- 테스트 내부에서 폭을 320px로 고정한 모바일 전용 경로에는 `@mobile-only`를 붙인다. `mobile-320`에서만 실행하며, 태블릿·데스크톱 프로젝트에서 같은 320px 검사를 반복하지 않는다. 실제 반응형 검사는 모든 해당 폭에서 유지한다.
- E2E 실패를 감추기 위해 대기 시간을 늘리지 않는다. 상태 또는 접근 가능한 결과를 기다린다.
- 색상 대비는 브라우저별 계산 차이가 있어 axe 자동 검사에서 제외하며, 기존 파생 대비 테스트와 사람 검증을 유지한다.
