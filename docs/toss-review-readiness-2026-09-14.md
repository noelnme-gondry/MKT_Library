# 토스 상점 심사 보완 · 2026-09-14

기준 커밋: `d20c942d` (PR #875). 사용자 제공 토스 상점 심사 화면을 읽고 공개 응답과 코드를 확인했다. 이 문서는 보완 작업 기록이며, 토스에 제출했거나 재심사를 통과했다는 뜻이 아니다.

2026-09-14 후속 지시: 사용자가 제공한 주소 이미지에 따라 `서울특별시 동대문구 천호대로41길 26, 402호(용두동, 천우네오젠)`로 교체했다. 이후 사용자가 토스 계약과정 FAQ를 제공하며 진행을 요청해 심사용 테스트 위젯 경로를 추가한다. **심사 계정 설정과 실결제 활성화는 보류 상태를 유지한다.** 아래 결제·가입 응답은 수정 전 조사 기록이다.

## 후속 상태와 출시 전 필요한 것

PR #876 (`f3a00063`) 배포 후 KO/EN 공개 푸터의 상세 주소, 비로그인 테스트 위젯과 5,900원 BC 페이북 인증창 진입을 확인했다. 인증 완료·승인·청구·이용권 발급은 실행하지 않았다. 아래 최초 조사 표의 “진입할 수 없음”은 수정 전 상태다.

| 시점 | 필요한 일 | 현재 상태·담당 |

토스 어드민은 결제수단 2열/3열 배열, 카드사·색상·기능 및 약관 구성을 지원한다. 영문 약관은 별도 구성한 약관 `variantKey`로 연결해야 하며 기본값은 국문이다. [공식 어드민 설정 안내](https://docs.tosspayments.com/guides/v2/payment-widget/admin) (2026-09-14 확인).

## 접수된 보완 요청과 확인 결과

| 보완 요청 | 확인한 상태 | 남은 작업 |
|---|---|---|
| 홈페이지 푸터에 사업자 정보 표시 | KO/EN 공통 푸터가 `SellerInformation` → `SELLER`를 사용한다. 상호·대표자·사업자번호·주소·전화·이메일 표시가 있다. | 정보가 없다고 새 블록을 중복 추가하지 않고 기존 표시를 수정한다. |
| 사업자등록증과 일치하는 상세 주소(층·호수 포함) | 사용자 제공 이미지의 주소 `서울특별시 동대문구 천호대로41길 26, 402호(용두동, 천우네오젠)`를 SSOT와 코드 사본에 반영했다. KO/EN 모두 동일한 주소 원문을 사용한다. | 공개 배포 뒤 주소의 실제 표시를 확인한다. 토스 재심사 통과 여부는 별도다. |
| 심사자가 상품과 결제창을 확인할 수 있어야 함 | 공개 `/api/payments/config`: `enabled:false`, `mode:test`, `requiresAccount:true`, `accountAvailable:true`. | 현재 심사자가 운영 사이트에서 결제창에 진입할 수 있다고 안내하면 안 된다. |
| 회원 구매만 가능한 경우 테스트 계정 안내 | 공개 `/api/account/session`: `enabled:true`, `signupRestricted:true`, `mailEnabled:true`. Google 로그인과 기존 계정의 이메일 로그인 링크를 사용하며 서비스 자체 ID/PW 로그인은 없다. | 심사 접근 방법을 실제로 마련하고 새 브라우저에서 확인해야 한다. 존재하지 않는 공용 ID/PW를 만들었다고 안내하거나 개인 Google 비밀번호를 전달하지 않는다. |

위 공개 응답은 비로그인 상태에서 확인한 결과다. 실제 Google 로그인, 결제 인증·승인, 상점 심사자 접근, 사업자등록증은 확인하지 않았다. `mode:test` 응답만으로 실제 키가 유효하게 설정됐다고 판단할 수 없다.

## 결제 경로의 제약

- `paymentServer.js`는 운영 빌드의 테스트 키 신규 주문·승인과 테스트 이용권 조회를 차단한다. 현재 비활성 응답은 이 조건과 일치하지만 키·DB 설정을 직접 확인한 것은 아니다.
- `accountServer.js`는 Railway 비운영 환경에서 계정 기능을 차단한다. 기존 PR 미리보기 주소를 심사용으로 넘기는 것만으로 로그인·구매 경로가 열리지 않는다.
- 실결제는 아직 테스트 단계라는 사용자의 기존 지시를 유지한다. 이번 보완 요청만으로 라이브 결제를 켜거나 일반 가입 제한을 전면 해제하지 않는다.
- 심사용 경로는 `/subscription#purchase`와 `/en/subscription#purchase`의 테스트 위젯이다. 운영 환경의 `test_gck_` 공개 클라이언트 키만 사용하며, 실제 구매 `enabled` 값은 그대로 둔다. 로그인 없이 실제 상품의 금액·결제수단·테스트 결제창을 확인한다. 실제 주문을 생성하지 않고 승인 API·Pro 발급·운영 메일·구매 이벤트를 호출하지 않는다. 테스트 복귀 식별자는 전용 API에서 제거한 뒤 구독 페이지로 보낸다.
- 테스트 키가 설정돼 있지 않거나 토스에서 거부되면 창을 확인할 수 없다. 실제 위젯 확인과 결제 경로 자료 준비 전에는 재심사 준비 완료로 표시하지 않는다.

## 제출 전에 채울 사실

1. 등록증과 대조한 사업장 전체 주소, 공개 푸터 반영 URL.
2. 심사자가 사용할 실제 접속 URL과 로그인 절차. 계정 비밀값은 저장소·공개 문서에 남기지 않는다.
3. 위 접속 방법으로 상품 가격·이용기간·환불 안내·토스 결제창까지 진입한 검증 결과.
4. 테스트 결제의 인증·승인 범위와 운영 구매 권한에 영향을 주지 않는지 확인한 결과.

토스 요청 화면에는 재심사 요청 버튼이 있지만, 이 작업에서 요청을 제출하거나 토스에 메시지를 보내지 않았다.

추가 확인: 사용자가 제공한 [계약과정 FAQ의 결제창 연동 항목](https://tosspublic.notion.site/FAQ-78932357c9c34620bb8e1f311b2b14cc#6c98a7f626d24c759d0c4682313149a1)은 직접 개발 시 신형 결제위젯을 사용하도록 안내한다. 기존 SDK의 `widgets`·`renderPaymentMethods`·`requestPayment`가 이 방식과 일치한다. 같은 FAQ는 메인→상품→결제→결제창 흐름의 PPT 제출을 요구하며, 비회원 접근 또는 심사 계정으로 창이 확인돼야 한다고 설명한다. 현재 작업은 비회원 테스트 경로를 사용한다. 카드사 심사 제출·승인은 별도이며, 자료를 대신 전송하지 않는다.
