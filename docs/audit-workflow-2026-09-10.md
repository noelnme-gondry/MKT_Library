## 감사 판정

| 항목 | 판정과 조치 |

| A-1 | 미구성 시 구매 막힘은 사실. 현재 운영은 테스트 구성됨. 결제 장애를 무료 권한으로 바꾸지 않고 구매 모달에 불가 상태·고객센터 경로 추가. |

| B-2 | 주문/웹훅에 프로세스별 분당 상한 추가. 다중 인스턴스 공유 제한과 제공사별 웹훅 인증은 별도 필요. 재조회 검증은 유지. |
| B-3 | 사실. 네트워크 호출 중 DB 잠금을 유지함. 잠금 제거만 하면 승인 경합 위험. 영속 승인 상태·재시도 작업자 설계와 장애 테스트가 필요한 후속 작업. |

| D-1 | 제목 Pretendard preload 해제, 본문 Wanted Sans 유지. 폰트 전체 파일 자체는 여전히 존재. 실제 전송량/Lighthouse 개선 수치는 미측정. |
| D-2 | 컴포넌트 내 메모화 및 비교 불가 시 생략. 감소를 증가로 쓰는 고정 문구도 노출 방지. |
| D-3 | 사용자 승인 샘플 비교의 예외를 문서화. 임의 수치는 여전히 금지. |
| D-4 | 뒤쪽 중복 library 토큰을 최초 정의로 통합. 역할이 다른 기존 토큰 연결 블록은 유지. |

## 약한 연결: 기능이 아니라 작업의 연속성

첫 방문에는 질문/CSV/샘플/콘텐츠라는 서로 다른 의도가 있다. 모두 도치 결과로 보내지 않는다. 분석 후에는 결과 읽기, 결정 기록, 재방문, 유료 보고서가 목적별로 갈라져야 한다. 특히 보고서 버튼 → 구매 → 원래 작업 복귀의 연결이 없었다. 이번 변경은 공개 도구 경로만 세션에 보관하고 구매 페이지에 돌아가기 링크를 제공한다. CSV 자동 보존이나 다시 실행 없이 결과 복원을 약속하지 않는다.

| 사용자 상황 | 주 행동 | 다음 행동과 성공 기준 |
|---|---|---|
| 무엇을 봐야 할지 모름 | 질문 선택 | 필요한 데이터·추천 도구를 이해하고 해당 도구로 진입 |
| 파일이 있음 | CSV 가져오기 | 매핑 확인 → 가능한 분석 실행 → 핵심 변화 확인 |
| 학습 목적 | 블로그/SOP 읽기 | 관련 질문·도구로 이동, 업로드 강요 없음 |
| 결과를 확인함 | 결정 기록 | 다음 행동·검토일을 남기고 프로젝트 저장 여부 확인 |
| 외부 공유가 필요함 | 보고서 다운로드 | 유료 범위를 미리 이해 → 구매/복원 → 원래 분석으로 돌아감 |
| 다음 주 재방문 | 프로젝트 열기 | 새 기간 데이터로 지난 결정 검토 |
| 기기 변경 | 이용권 복원 + 프로젝트 백업 가져오기 | 권한과 데이터가 별개임을 이해하고 각각 복원 |

## 다음 UX 작업 우선순위

1. 결과 하단에 핵심 행동을 `결정 기록`으로 정리하고 `보고서 받기`·`상세 분석`은 보조 행동으로 둔다. 사용자가 결정을 내렸는지와 단순 계산 완료를 구분한다.
2. 구매 전 원본이 미저장 상태면 프로젝트 저장/백업을 안내한다. 결제 리다이렉트는 메모리를 잃을 수 있으므로 링크만으로 작업 보존 문제는 완전히 해결되지 않는다.
3. 재방문 홈은 프로젝트·검토할 결정을 먼저 제시한다. 최초 방문용 설명과 같은 화면 밀도로 반복하지 않는다.
4. 퍼널은 방문→질문/파일 진입→분석 완료→결정 저장→다음 주 검토로 본다. 구매 전환만 최적화하면 무료 분석의 가치를 놓친다.

미구현인 제안을 완료로 읽지 말 것. 이번 변경은 감사에서 확인한 안전한 수정과 구매 복귀 링크이며, 결과 행동/재방문 화면 재설계는 후속 범위다.

## 사용자 승인 후 반영한 작업 연결

- 실제 데이터 성공 결과에서 결정 입력기를 여는 주 버튼 추가(기존 입력·검토 계약 재사용).
- 결정 저장 후 프로젝트 보관 링크와 다음 기간 검토 안내 추가.
- 홈의 기존 재방문 패널을 히어로 앞으로 이동하고 프로젝트 열기 추가. 기록 없는 신규 방문에는 노출하지 않음.
- 구매 모달에 페이지 이동 전 프로젝트 보관·백업 안내 추가. 자동 저장은 구현하거나 약속하지 않음.
- 위 네 항목은 이제 구현됨. 자동 프로젝트 선택/자동 파일 보관, 결제 리다이렉트 후 분석 결과 자동 재구성은 여전히 후속 범위.
