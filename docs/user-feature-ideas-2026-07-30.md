## 0. 전제 — 이 제품의 제약이 곧 필터

| 제약 | 출처 | 기능 설계에 미치는 영향 |
|---|---|---|
| 클라이언트 사이드 100%, 서버 전송 0 | CLAUDE.md §2.2 | 계정·클라우드 저장·팀 협업·이메일 알림 = **구조적 불가**. "저장/공유"는 **파일 또는 URL 인코딩**으로 풀어야 함 |
| 로그인 없음 | 현행 | 온보딩 = 첫 화면에서 즉시 가치. 리텐션 훅을 계정에 걸 수 없음 |
| 전부 무료 + 광고 | §12.26 | 유료 전환 압박 없음 → **재방문 빈도**가 유일한 성장 지표. 리텐션 기능이 곧 매출 |
| localStorage 영속 최소 | §7 | 자동 저장은 **명시적 옵트인**만. 원본 CSV는 어떤 경우도 영속 금지 |
| 통계적 정직성 | §8 | 벤치마크·예측·인과 단정형 기능은 근거 없으면 **만들지 않는다** |

**결론**: SaaS 기능 중 "계정 기반"은 전부 탈락. 대신 **파일·URL·로컬**로 같은 유저 니즈를 푸는 설계가 이 제품의 차별점이 된다("업로드 안 해도 되는 분석 도구").

## A. 퍼포먼스 마케팅 SEO 렌즈 — 검색 의도 → 기능

현 SEO 자산: 블로그 33 + 용어 26 + 도구 12 + `SearchTopicHub`/`ContentActionPanel` 전환 경로.
**갭**: 검색 유입 대부분이 "읽고 끝". 도구 진입에 **CSV라는 큰 문턱**이 있어 전환이 샌다.

### A1. 무CSV 단품 계산기 (`/calculator/*`) ★ 최우선
- **니즈**: "LTV CAC 계산", "ROAS 계산기", "AB테스트 표본수" — 검색 의도가 명확하고 즉시 충족 가능한 질의. 지금은 이 검색을 받을 페이지가 없다.
- **무엇**: 숫자 3~5개 입력 → 즉답 + 해석 한 줄 + "더 깊게 보려면 이 도구" CTA. 엔진은 **기존 순수함수 재사용**(신규 수학 0).
  - LTV:CAC · 페이백 기간 (`ltvMath.js`)
  - 손익분기 ROAS / 목표 CPA 역산 (`metricRegistry.js`)
  - A/B 표본수·MDE (`abTestMath.js` — 이미 5-4에 있으나 CSV 없는 진입점이 없음)
  - 예산 → 예상 설치 (`allocationMath.js` 곡선, 단일 채널)
- **왜 SEO에 강한가**: 계산기 페이지는 백링크가 붙고 체류·재방문이 높다. 도구 전환의 **저마찰 사다리**(계산기 → 결과 → "CSV 넣으면 채널별로 다 나옴").
- **비용**: 페이지당 소(엔진 재사용). 라우트·`routeSeo`·sitemap 배선이 실작업.
- **리스크**: 계산기 남발 시 얕은 페이지 양산 → 5~6개로 제한하고 각각 해설 본문을 붙일 것.

### A2. 증상 기반 진단 라우터 (`/diagnose`)
- **니즈**: 실무 검색은 지표명이 아니라 **증상**으로 온다 — "CPI가 갑자기 올랐어요", "설치는 느는데 매출이 안 늘어요", "오가닉이 줄었어요".
- **무엇**: 3문항 → 원인 가설 + 확인 순서 + 해당 도구 딥링크. `lib/analysis-router/evaluateEligibility.js`가 이미 도구 적합성을 판정하니 **증상→도구 매핑 레이어만** 얹으면 된다.
- **부가**: FAQPage/HowTo JSON-LD → 검색 리치 결과.

### A3. 템플릿·체크리스트 허브 (`/templates`)
- **니즈**: "이벤트 택소노미 템플릿", "미디어 플랜 양식", "주간 리포트 포맷" — 다운로드 의도 검색은 전환·공유가 강하다.
- **무엇**: `buildToolTemplateCsv`(도구별 빈 헤더 CSV)를 **SEO 랜딩으로 승격** + SOP에서 파생된 체크리스트(택소노미 설계·포스트백 QA·신규 매체 온보딩) 다운로드.
- **원칙**: 이메일 수집 없음(리드마그넷 아님) — 광고 모델과 일관.

### A4. "결과가 어떻게 나오는지" 공개 샘플 리포트
- **니즈**: 도구 페이지는 CSV 없으면 빈 화면 → 검색 유입자가 가치를 못 보고 이탈. 데모는 있으나 **인덱싱되는 정적 URL**이 아니다.
- **무엇**: 도구별 데모 결과를 SSR 정적 페이지로(`/sample/<tool>`). 실제 차트·판정 카드 노출 → 검색 스니펫·OG 카드가 제품 화면 그 자체.

### A5. 비교·의사결정형 콘텐츠 확장
- 이미 `adjust-vs-appsflyer` 1편. 비교형은 상업적 의도가 높은 질의.
- 후보: MMM vs 어트리뷰션 vs 증분(셋 다 도구가 있음) · UAC vs Advantage+ · 인앱 vs 웹 전환 측정.
- **전환 SSOT**(`contentToolRegistry.js`)에 글↔도구 매핑 필수(§12.24 레지스트리 3종 정합).

### A6. 결과 공유 카드 (OG 이미지 생성)
- **니즈**: 분석 결과를 슬랙/노션에 붙이는 순간이 곧 바이럴 지점.
- **무엇**: 판정 카드(Decision Tape)를 **PNG 1장**으로 내보내기 + "이 도구로 만들었습니다" 워터마크.
- **주의**: 유저 데이터가 포함된 이미지는 **로컬 생성만**(서버 렌더 금지, §2.2).

## B. SaaS 제품 렌즈 — 활성화·리텐션·확산

현 상태: 새로고침하면 **모든 분석이 사라진다**. SaaS 기준으로는 이게 가장 큰 구멍이다.

### B1. 세션 저장·복원 (프로젝트 파일 내보내기/불러오기) ★ 최우선
- **니즈**: 어제 한 분석을 오늘 다시 못 본다. 매핑을 매번 다시 한다. 실무자는 같은 CSV를 주 단위로 반복 분석한다.
- **무엇**: `.gop.json` 프로젝트 파일 = 매핑 + 필터 + 커스텀 지표/차트 + 뷰 설정 (**원본 CSV 미포함**, 파일은 다시 물림). "설정만 저장" 방식이라 §2.2와 충돌 없음.
- **연계**: 옵트인 자동 임시저장(로컬) — "이 브라우저에 저장" 체크박스, 원본 데이터 제외.
- **비용**: 중(store 직렬화 스키마 + 버전 마이그레이션 — `persistMigrate` 골격 이미 존재).

### B2. 주간 리포트 빌더 ★ 임팩트 최대
- **니즈**: 마케터의 실제 잡(job)은 "분석"이 아니라 **주간 보고서 제출**이다. 지금은 도구마다 따로 보고 손으로 옮겨 붙인다.
- **무엇**: 여러 도구 결과(대시보드 WoW + PVM 변동 요인 + 포화도 + 예산 제안)를 **한 문서로 조립** → PDF/PNG/마크다운 내보내기. 섹션 선택·순서 조정.
- **재료 존재**: `ResultActionCard`(Decision Tape)가 이미 도구별 결론을 표준 형태로 갖고 있다 → **결론들을 모으는 컨테이너**만 만들면 된다.
- **리텐션 효과**: 주 1회 반드시 돌아올 이유가 생긴다(광고 모델의 핵심 지표).

### B3. 인쇄/PDF 최적화 (`@media print`)
- B2의 축소판이자 선행 단계. 사이드바·필터·광고 숨김, 차트·표만 정렬. 비용 소, 체감 큼.
- (`docs/tool-roadmap.md`에 이미 제안되어 있으나 미구현.)

### B4. 다중 파일 병합·기간 이어붙이기
- **니즈**: 실무 CSV는 매체별로 쪼개져 나온다(구글·메타·틱톡 따로). 현재는 1파일 전제라 유저가 엑셀에서 미리 합쳐야 한다 — **최대 마찰 지점**.
- **무엇**: 파일 여러 개 드롭 → 컬럼 정합 확인 → 행 결합(중복 기간 감지·경고). `lib/data-import/*`의 컬럼 프로파일러가 이미 정합 판정 재료를 갖고 있다.

### B5. 저번 업로드 대비 변화 감지(로컬 스냅샷 diff)
- **니즈**: SaaS의 "알림"에 해당하는 가치를 서버 없이. "지난번 분석 대비 CPA 22% 악화, 원인은 채널 B"
- **무엇**: 스냅샷(집계 결과만, 원본 아님)을 로컬에 옵트인 저장 → 다음 업로드 시 자동 비교.
- **정직성**: 기간·모수가 다르면 비교 거부(§8).

### B6. 온보딩 — 첫 3분 성공 경험
- **무엇**: 최초 방문 3스텝(질문 선택 → 데모로 결과 확인 → 내 CSV 넣기) + 진행 체크리스트. 데모 자동로드는 있으나 **"이제 뭘 하면 되는지"** 안내가 없다.
- **측정**: `lib/analytics.js` 퍼널 이벤트(구조 메타만, 값 금지).

### B7. 모바일 결과 보기
- 마케터는 회의 중 폰으로 본다. 현재 대시보드 8탭·넓은 표는 모바일에서 사실상 사용 불가.
- **무엇**: 모바일에서는 **결론 카드 + 상위 3개 지표**만, 표는 가로 스크롤 컨테이너. 전면 반응형이 아니라 "결론만 보여주기" 축소판.

### B8. 대용량 CSV 논블로킹 (엔진 Web Worker화)
- 10~20만 행에서 메인 스레드가 멈춘다(§7 기록). 파싱은 워커로 갔지만 **계산은 아직 메인**.
- 리텐션 직결: 한 번 멈추면 안 돌아온다.

### B9. 접근성·오류 회복
- 잘못된 CSV·빈 컬럼·기간 부족 시 **무엇을 고쳐야 하는지** 문장으로. 현재 일부는 빈 화면.

## D. 만들지 말아야 할 것 (원칙 충돌 — 사전 차단)

| 아이디어 | 왜 안 되는가 |
|---|---|
| 계정·클라우드 저장·팀 워크스페이스 | §2.2 클라이언트 100% 위반. 유저 CSV = 사내 민감 자료 |
| 업종별 벤치마크(유저 데이터 익명 집계) | 데이터 수집 자체가 §2.2 위반. **출처 명시 외부 인용**만 가능하며, 자체 집계인 척하면 §8 위반 |
| 이메일 리포트·이상 알림 | 서버·주소 수집 필요. 로컬 스냅샷 diff(B5)로 대체 |
| "AI가 원인을 찾아드립니다"류 자동 인과 판정 | §8 — 관측 데이터로 인과 단정 금지. 증분/홀드아웃(5-23)의 역할 |
| 예측 정확도·성공 확률 단정 표기 | 엔진이 산출하지 않는 수치는 표기 금지(§8, 9-x 사례) |
