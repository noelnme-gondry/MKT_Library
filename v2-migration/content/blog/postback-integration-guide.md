캠페인은 잘 돌아가는데 매체 대시보드엔 설치가 계속 0으로 찍힌다면, 십중팔구 포스트백 연동 문제예요. [MMP](/glossary/mmp)가 어트리뷰션 결과를 매체에 다시 알려주는 이 파이프라인이 하나라도 어긋나면, 매체의 자동입찰 알고리즘은 학습할 신호 자체를 못 받습니다.

## 포스트백이 하는 일

포스트백은 MMP가 "누가 어디서 와서 무엇을 했는지"를 매체에 되돌려주는 통로다.

- **Install Postback**: 신규 설치가 발생하면 MMP가 매체에 알려줘요. 매체 머신러닝 최적화의 핵심 학습 신호예요.
- **In-App Event Postback**: 가입·구매 같은 인앱 이벤트가 일어나면 마찬가지로 전달한다. 목표 기반 입찰(행동당 비용·매출당 비용)을 쓰려면 필수예요.

이 신호가 끊기면 매체는 눈을 감고 입찰하는 셈이 돼요. 그래서 포스트백은 측정용이자 곧 최적화용입니다.

## 매체마다 연동 방식이 갈린다

- **SAN(Self-Attributing Network)**: Meta·Google·TikTok처럼 매체가 자기 클릭·노출 데이터를 스스로 MMP에 알려주는 방식이다. 대형 매체 대부분이 여기 속해요.
- **S2S(Server-to-Server)**: 매체가 SAN이 아닐 때 MMP가 서버 대 서버로 직접 연동한다. Apple Search Ads처럼 API 연동이거나, 소형 매체는 클릭 URL에 값을 심는 방식을 쓰기도 해요.

이 둘을 헷갈리면 안 되는 이유가 있어요. **SAN 매체에 별도 클릭 URL을 발급하면 이중 트래킹**이 돼서, 정상 광고 유입이 오가닉으로 잘못 분류됩니다. 매체 입장에선 "우리 광고로 온 게 하나도 없다"가 되는 거죠.

## 자주 터지는 문제 3가지

- **설치가 0으로 보인다**: MMP 파트너 설정에서 Install Postback이 꺼져 있거나, SAN 매체에 실수로 클릭 URL을 따로 발급한 경우다. 후자면 위에서 말한 이중 트래킹으로 오가닉 분류돼요.
- **비용(Cost) 데이터가 안 들어온다**: 노출·클릭·설치 연동과 별개로, 지출 데이터는 매체별 API 키를 따로 등록해야 하는 경우가 많다. 최초 동기화까지 하루이틀 걸릴 수 있어요.
- **확률적 매칭 비율이 비정상적으로 높다**: iOS에서 유저가 추적 동의를 거부하면 고유 식별자 없이 [확률적 매칭](/glossary/probabilistic-attribution)으로 넘어가는데, 이 비율이 과도하면 그 매체를 SKAN 단일 채널로 전환하는 걸 고려해야 해요.

## 정직하게

포스트백은 한 번 세팅하고 끝나는 게 아니다. 매체 정책·API가 바뀌면 조용히 깨질 수 있어서, 새 캠페인을 켤 때마다 샌드박스로 설치·이벤트가 실제로 매체 대시보드에 찍히는지 확인하는 습관이 필요해요. 세부 매체별 표·URL 매크로 사양은 [매체별 포스트백 연동 매뉴얼](/guide/postback-integration)에 정리돼 있어요.
