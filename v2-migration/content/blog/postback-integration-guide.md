포스트백 문제는 “설치가 0이다”만 보면 오래 걸립니다. **앱에서 이벤트가 났는지, MMP가 받았는지, MMP가 매체에 보냈는지, 매체가 자기 규칙으로 집계했는지**를 순서대로 확인하세요. 마지막으로 정상인 지점이 원인 범위입니다.

## 포스트백은 무엇을 전달하나

포스트백은 MMP 또는 측정 시스템이 매체에 설치·인앱 이벤트·매출 신호를 전달하는 흐름입니다. 매체는 이 신호를 보고 전환 보고와 자동입찰 학습을 합니다. 비용 데이터는 보통 별도 API 연동이므로 전환 포스트백과 같은 장애로 보지 마세요.

`광고 클릭 또는 노출 → 앱 설치·실행 → MMP 어트리뷰션 → 이벤트 수집 → 매체 포스트백 → 매체 보고·학습`

![앱 이벤트가 매체 보고까지 도달하는 포스트백 흐름](/blog-assets/postback-integration-guide/postback-flow.svg)

## 먼저 SAN과 S2S를 구분하세요

SAN(Self-Attributing Network)은 매체가 자신의 광고 상호작용 데이터를 MMP와 직접 대조하는 방식입니다. S2S는 MMP와 매체가 서버 간 전송 규칙으로 데이터를 주고받는 방식입니다. 실제 설정은 MMP·매체 조합마다 다르므로, 링크·파트너 토글·앱 ID를 임의로 복제하지 말고 공식 파트너 안내를 기준으로 맞추세요.

iOS 프라이버시 측정은 일반 사용자 수준 포스트백과 다릅니다. Apple AdAttributionKit은 설치·재참여 후 제한된 시간 창과 프라이버시 조건에서 네트워크로 포스트백을 보냅니다. 테스트 시 실제 운영 지연을 즉시 오류로 보지 마세요. [Apple의 postback 흐름](https://developer.apple.com/documentation/adattributionkit/receiving-ad-attributions-and-postbacks)을 확인하세요.

## 증상별 진단표

| 증상 | 마지막으로 확인할 정상 지점 | 자주 놓치는 원인 | 다음 확인 |
|---|---|---|---|
| 설치 0 | 앱 설치·첫 실행 | 앱 ID, 파트너 활성화, SAN/S2S 설정 | MMP 원시 설치 로그와 매체 테스트 설치 비교 |
| 이벤트 0 | 앱 이벤트 수집 | 이벤트명 매핑, 포스트백 토글, 필터 | MMP 이벤트 로그와 매체 수신 이벤트 비교 |
| 매출 0 | 구매 이벤트 | `value`, `currency`, 매출 이벤트 설정 | 거래 ID·금액·통화·중복 확인 |
| 비용 0 | 매체 API 연결 | 권한, 계정 연결, 시간대, 동기화 지연 | 비용 API 상태와 계정 권한 확인 |

![마지막 정상 지점으로 분리한 0 데이터 진단](/blog-assets/postback-integration-guide/zero-data-diagnosis.svg)

## 설치가 0일 때

1. 테스트 기기에서 앱 설치·첫 실행이 실제로 발생했는지 확인합니다.
2. MMP에서 설치가 어트리뷰션 또는 오가닉으로 기록됐는지 봅니다.
3. 매체 파트너 연결, 앱 ID, OS, 캠페인 계정이 맞는지 확인합니다.
4. 매체가 설치를 받는 방식이 SAN인지 S2S인지 확인합니다.
5. 같은 테스트의 MMP 시간·매체 시간·전환 윈도우를 비교합니다.

## 이벤트·매출이 0일 때

이벤트는 앱에서 발생했다고 해서 자동으로 매체에 전달되지 않습니다. 이벤트명이 MMP에 들어왔는지, 해당 이벤트가 파트너 포스트백 대상으로 선택됐는지, 매체가 요구하는 값이 있는지 나눠 확인하세요.

구매 이벤트는 `transaction_id`, 숫자 `value`, ISO 4217 `currency`를 함께 점검합니다. 중복 결제 콜백을 막지 않으면 매출이 0이 아니라 과대 집계될 수도 있습니다. 이벤트 설계 자체는 [이벤트 택소노미 설계](/blog/event-taxonomy-guide)에서 먼저 고정하세요.

## 비용 0은 별도 흐름입니다

비용은 매체 API 토큰·광고 계정 권한·계정 연결·리포팅 지연에 좌우됩니다. 설치와 이벤트가 정상인데 비용만 0이면 포스트백을 다시 만들기보다 비용 API 연결과 계정 범위를 확인하세요. 비용을 포함한 성과 수치가 맞지 않으면 [어트리뷰션 데이터 불일치 원인](/blog/attribution-data-mismatch)에서 집계 기준을 분리합니다.

## 새 캠페인 QA 체크리스트

- [ ] 앱 ID·OS·매체 계정·MMP 파트너 연결 확인
- [ ] 테스트 설치가 MMP에 기록되는지 확인
- [ ] 가입·구매 이벤트가 MMP 로그에 값과 함께 도착하는지 확인
- [ ] 이벤트별 포스트백 활성화와 매체 수신 여부 확인
- [ ] 매출의 거래 ID·금액·통화·중복 규칙 확인
- [ ] 비용 API 권한·계정 범위·시간대·지연 확인
- [ ] iOS 프라이버시 포스트백은 별도 지연·집계 규칙으로 해석

## 결론

포스트백은 한 번 켜고 끝나는 설정이 아닙니다. 새 캠페인·SDK·이벤트 버전·매체 권한이 바뀔 때마다 테스트 설치 하나를 끝까지 따라가야 합니다. 앱→MMP→매체의 마지막 정상 지점을 기록하면 “설치 0”도 빠르게 해결할 수 있습니다.
