# claude-ux.md — 비전문 유저용 인터페이스 제작 가이드

> **읽는 시점**: 유저가 "유저 친화적으로 개선", "너무 복잡", "이해 안 됨", "전문용어 많음", "직관적이지 않음" 언급 시 **이 문서 먼저 읽고** 원칙대로 진행. (AGENTS.md §15.5 트리거)
>
> **대상 유저**: 마케팅 운영하나 통계·데이터 분석 비전문. 데이터는 있으나 통계값·전문용어 그대로 보면 이해 못함, 분석 흐름도 모름.
>
> 5-18(마케팅 반응 분석) 카니발 진단 UI 비전문가용 재설계로 확립한 원칙. 다른 도구·화면에도 동일 적용.

---

## 0. 대원칙 — "결론 먼저, 근거는 접어서"

화면 **2층** 구조.
- **1층 (메인, 항상 노출)**: 짧은 평어 결론 + 액션. 통계값·전문용어 **없음**.
- **2층 (토글/아코디언, 기본 접힘)**: 통계 검정·계수·p값·방법론. 원하는 사람만 펼침.

전문가용 원값 **버리지 않음** — 2층 배치 또는 흐린 작은 글씨로 강등. "숨김 = 삭제" 아님, "숨김 = 위계 하향".

**네이티브 `title` 속성 단독 사용 금지**: `<span title="...">(마우스오버)</span>`처럼 브라우저 기본 툴팁만 쓰면, hover 가능 시각 단서(점선 밑줄·아이콘 등) 없어 유저가 존재 자체 모름(실사용에서 확인된 함정). 원값은 기본으로 **바로 보이는 흐린 작은 글씨**로 두거나, hover UI 쓸 거면 점선 밑줄(`border-bottom:1px dotted`)·`cursor:help`·(i) 아이콘 등 명확한 어포던스 같이 줄 것.

## 1. 여정(flow) 먼저 보여줌

유저는 전체 과정 흐름 모름. 도구가 여러 단계(탭)면, 각 단계를 **§번호·전문용어 아닌 "질문"**으로 프레임.

- ❌ "① 카니발 진단 — 어느 채널이 오가닉을 잠식하나 / lead-lag" 
- ✅ "① 잠식 진단 — 유료 광고가 공짜 유입을 갉아먹고 있나?"

3툴 예시(5-18):
1. **잠식 진단** — "광고가 공짜 유입을 갉아먹나?"
2. **기여 분해** — "무엇이 성과를 움직였나? 다음 예산 어디에?"
3. **미래 예측** — "이대로 가면, 예산 바꾸면 성과는?"

현재 단계는 항상 시각적으로(active 하이라이트) 표시.

### 1.1 여러 모델·방법을 비교할 때

모델 선택기는 **모델별 결과보다 먼저** 한 번만 둔다. 모델을 바꿔도 스크롤 위치와 질문 순서가 바뀌지 않아야 한다.

```text
모델 선택
→ 1. 실제를 얼마나 설명했나
→ 2. 무엇이 성과를 움직였나
→ 3. 계수·효과가 안정적인가
→ 4. 입력을 바꾸면 어떻게 달라지나
→ 5. 이 결과로 행동해도 되는가
```

- 모델마다 가능한 숫자는 달라도 **사용자 질문과 섹션 순서는 동일**하게 유지.
- 한 모델에만 있는 posterior·fold·prior 같은 전문 정보는 해당 단계의 전문가 상세로 배치.
- `자동 추천`과 `현재 보고 있는 결과`는 다른 상태다. 배지를 분리하고 정확히 하나만 선택 표시.
- 모델 선택은 `radiogroup`/`radio` 또는 올바른 tab 계약을 사용하고 Arrow·Home·End 키를 지원.
- 선택 전후에 공통 결과가 중복 렌더되거나, 이전 모델 차트가 선택기 위에 남지 않게 함.

## 2. 그룹핑 > 나열 (칸반 원칙)

여러 항목(채널 등)에 상태 붙을 때, **항목마다 배지 반복**하면 유저가 하나씩 확인해야 함. 대신 **상태별 칼럼(칸반)으로 그룹핑** — 칼럼 헤더가 곧 상태.

- ❌ 카드 그리드: 카드마다 [배지] 반복 → "이 마크 뭐지?" 계속 확인
- ✅ 칸반: `잠식 의심` / `애매함` / `문제 없음` 3칸, 채널은 칩으로 해당 칸 안에

**버킷 수 3개 권장** (조치 필요 / 애매 / 괜찮음). 엔진이 5단계·N단계 내도 마케터용으론 3개로 접음. 칩은 이름 + 한 줄 액션만; 상세 숫자는 클릭 시 드릴다운.

색: 위험=red, 애매=neutral/gray, 안전=green (semantic 토큰: `--bg-danger`/`--bg-success`, `BADGE_TONE`).

## 3. 지표·검정은 "질문 + 평어 답"으로

통계 지표 이름 그대로 쓰지 않음. **뭘 묻는지 평어 질문**으로 라벨, 결과도 평어로.

| ❌ 전문용어 | ✅ 평어 질문 |
|---|---|
| 시간 선행성 (저지출 ≤p25) | 광고를 늘리기 전에 오가닉이 이미 줄고 있었나? |
| 허위상관 (탈추세·차분) | 시즌·추세를 걷어내도 광고 늘 때 오가닉이 주나? |
| 순증분 (net 탄력성) | 광고를 늘리면 전체 성과가 순증가하나? |
| 그랜저 인과 | 광고비가 몇 주 뒤 오가닉을 끌어내리나? |

투표/판정값도 평어로: `FOR/AGAINST/ABSTAIN` → **괜찮음 / 잠식 신호 / 판단 보류**. 원 통계값(slope·p·CI·F)은 카드 하단 흐린 글씨 + `title="통계 원값(전문가용)"`.

전문용어 꼭 노출해야 하면 **평어 먼저, 괄호로 전문어**(`재현율(Recall)`), 또는 `title` 툴팁.

## 4. 결론과 근거, **모순돼 보이지 않게**

메인 배지(그룹/헤드라인)와 상세 판정이 **다른 규칙으로 계산되면** 유저 혼란 ("문제없다며 왜 의심?").
- 상세 뷰 헤드라인은 **메인 그룹핑과 동일 규칙**으로 계산.
- 종합 판정이 개별 지표와 다를 때(예: 같은 주 지표는 OK인데 시차 지표에서 걸림) → **왜 그런지 한 문장 평어 설명**:
  > "같은 주 지표(①②③)는 괜찮은데, 몇 주 시차 두고 광고비가 오가닉을 끌어내리는 신호(④) 나와서 의심으로 올렸어요."

## 5. 레이아웃 — 균등·정렬

- N개 동급 항목은 `display:grid; grid-template-columns:repeat(N, minmax(0,1fr))`로 **균등 분배**. `flex`는 왼쪽 쏠림("옹기종기") 유발 → 지양.
- ①②③는 ①왼쪽 · ②가운데 · ③오른쪽처럼 순서가 위치로 읽히게.
- Card(`border`+`radius:12px`+옅은 shadow)로 논리 단위 시각 묶음.
- **범례 많은 차트(회귀 변수 등)**: Chart.js 기본 상단 범례가 캔버스 짓눌러 레이아웃 붕괴 → `legend.position:"right"`+`maxWidth` + 컨테이너 `minHeight` 명시 + x축 `autoSkip:true, maxTicksLimit` + 툴팁 `toLocaleString()`. `maintainAspectRatio:false, responsive:true` 기본.
- **아코디언/토글 안 차트는 접힘 상태에서 폭 0으로 마운트됨**(§7 0px 함정 재발) → `<details onToggle>`에서 열릴 때 `requestAnimationFrame(()=>window.dispatchEvent(new Event("resize")))`로 재측정. 통계 상세 접어두면 거의 항상 이 문제 생김.

### 5.1 텍스트는 존재 이유를 증명해야 함

화면 문장은 아래 중 하나를 해야 한다. 어느 것에도 해당하지 않으면 제거하거나 전문가 상세로 내린다.

1. 지금 상태나 결론을 알려준다.
2. 다음 행동을 안내한다.
3. 숫자·차트의 오해를 막는다.
4. 오류 원인과 해결 방법을 알려준다.

- 제목을 본문에서 다시 풀어 쓰지 않는다.
- 같은 인과 한계·데이터 설명을 카드마다 반복하지 않고 해당 묶음 끝에서 한 번만 말한다.
- `이 화면은 … 보여줍니다`, `아래에서 … 확인할 수 있습니다`처럼 화면을 중계하는 문장은 우선 삭제.
- 라벨은 라벨만, 예시는 예시만 담당하게 하고 한 문장에 여러 역할을 얹지 않는다.
- 분석 결과 전 CSV 안내·블로그·FAQ·방법론은 현재 과업을 밀어내지 않게 접거나 뒤로 보낸다.

### 5.2 불필요한 줄바꿈을 만들지 않음

- 본문에 시각 맞춤용 `<br />`를 넣지 않는다. 의미상 문단 경계만 문단으로 나눈다.
- 짧은 설명에 습관적으로 좁은 `max-width`를 주지 않는다. 카드의 실제 가용 폭을 먼저 사용.
- 제목·토글·짧은 지표 라벨은 가능한 한 한 줄을 유지하고, 작은 화면에서만 자연스럽게 wrap.
- flex/grid 자식에는 `min-width:0`; 긴 영문·CSV 헤더에는 `overflow-wrap:anywhere`를 선택적으로 사용.
- 360·720·1100px과 200% 확대에서 **문장 끝 몇 글자만 다음 줄로 떨어지는지** 확인.
- 텍스트를 지운 뒤 빈 여백, 어긋난 세로 정렬, 고정 높이 때문에 남은 구멍도 함께 제거.

## 6. "더 알고 싶으면" 탈출구

맨 밑에 **전 과정 상세 설명 문서 다운로드 버튼** 배치("이 과정에 대한 자세한 설명이 듣고 싶으신가요? — 상세 문서 받기"). 문서 구성:
- 평어 먼저(한 줄 요약 → 왜 중요 → 각 신호 평어 설명 → 판정 종합 규칙 → 한계),
- 전문 용어는 각 항목 끝에 `(전문: …)`로 병기,
- **현재 데이터 판정 요약** 포함(자기 데이터로 재확인 가능),
- 마크다운(.md) 텍스트 다운로드(`textDownload`).

## 7. 정직성 (통계적 겸손) — 절대 훼손 금지

유저 친화적으로 단순화하되 **거짓으로 만들지 않음**.
- "연관(association)이지 인과(causation) 아님" 고지 유지. 확정은 홀드아웃 실험.
- 데이터 부족·공선이면 억지 판정 대신 **"판단 보류"**로 정직하게.
- 수학 엔진(`*Math.js`)은 절대 건드리지 않음 — **렌더층만** 재구성(골든 테스트 불변).
